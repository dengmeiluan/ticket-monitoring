# ticket-monitoring v1.5.289 · 2026-10-23

本版在已发布的 v1.5.288（探针可观察性、渠道真实明细）之上，完成关注语义、检索/明细筛选与探针布局的整合：关注航线与关注航班共享曲线样式但保持独立实体，检索台筛选成为明细筛选的超集，探针在宽屏收成单行、窄屏保持字段对齐且渠道/会话不换行。

## 关注语义、曲线与结构

- 明确「关注航线」= 配置航线（阈值/日期/渠道），「关注航班」= 独立实体：不要求落在已配置航线的日期或渠道内，两者都只对本地已存储的航线数据做过滤匹配，不存在子集或派生关系。
- 关注航班不再因日期早于配置航线而失效，也不再被配置渠道限制；日期过期只按航班日期本身判断，预览与检索保留自由航线输入。
- 关注航线、关注航班、概览走势共用 `trendSparkSvg` 迷你曲线（同一刻度、断点与可访问标签）；工作台航线摘要增加直达/中转双线曲线和「查看航线走势」入口，概览新增航线关注卡。
- 关注工作台与检索页使用同一套状态/错误/加载样式，能力差异（阈值、日期、渠道）保留在各自表单，不复制曲线实现。

## 检索与明细筛选大共集

- 实时检索新增与航班明细同级的筛选：出发/到达机场、共享/直飞/经停、风险、经停时长、总时长、价格区间、机龄、行李、餐食、儿童、少班等；检索侧对最新数据为明细筛选的超集。
- 筛选面板分为「共同筛选」「加工与历史」「检索特有」三组，命中计数分组显示；「清空共同筛选」保留只属于检索页的查询词与历史加工条件。
- 明细工具栏收拢为共同开关（共享/直飞/风险/隐藏日历/仅达标），与检索同义同名；检索结果同时合并探针最新行与明细已爬行，按航班行键去重后统一筛选。
- 实时检索的筛选状态独立于探针提交快照：改筛选不改任务请求条件，清筛选不删锁定日期与渠道。

## 探针界面收口

- 探针标题行压缩为单行：名称、数据模式、一句来源说明与操作按钮同排；≤760px 时操作按钮整行等宽换行，不再挤占标题。
- 宽屏查询区收成一行：出发/到达/日期标签内联，提交按钮与输入框底边同线，渠道片靠右且不换行；窄屏恢复字段标签在上、提交钮与日期同排。
- 会话/渠道状态条改为紧凑单行：渠道点、状态与计数同一行，完整会话文案保留在读屏文本，窄屏不再多行占高。
- 保持 v1.5.288 的任务快照、结果筛选、渠道产物与会话分栏、失败重试与取消语义不变。

## 审计修复

- 未采日期的「其他日期」计数改为遵循结果渠道筛选：渠道为途牛+同程时显示 117 行，不再拿全航线 486 行冒充可用其他日期。
- 「仅达标」等额外筛选进入生效摘要；额外筛选清空结果时先提示「筛选无结果/生效限制」，再退到日历/补位说明。
- 任务聚合保留渠道终态：login_required / blocked / challenge / partial / error / timeout 不再被折叠成 ok；本次被拒时，会话条明确写「本次需登录」，不拿历史明细可用掩盖本次登录墙。
- 退出探针会停止前端轮询并收起探针面板；已提交任务仍保留在任务存储中，可重连查看，不会在下一拍自动把探针模式拉回。
- 批量失败重试保留已提交任务快照与合并行：重试不再重置用户选中的日期/航线，也不因单腿重试把合并的成功腿行藏掉。
- 健康日志的「请登录」凭据证据纳入登录态判定；444「非法链接/会话门拒」仍按风险/会话门证据处理，不误报成登录墙。点「登录完成」后的待验证窗只被**晚于该动作**的新拒绝/新明细结束，旧证据不再把刚点的登录瞬间打回「建议重登」。
