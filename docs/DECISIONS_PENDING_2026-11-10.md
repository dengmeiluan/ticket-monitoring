## 二、要不要加一条"近端国内航线"

### 现状

你当前的监测日期距离今天：

| 航线 | 日期 | 距今 |
|---|---|---|
| SHA→NRT / BKK / SIN / LHR | 2026-11-16 | 7 天 |
| SHA→HAK | 2027-01-29 | 81 天 |
| SHA→HAK | 2027-01-30 | 82 天 |
| HAK→SHA | 2027-02-14 | 97 天 |

按你的决定「春节日期保留，但只让浏览器查」，App 视野已收窄到 **45 天** →
**国内三条日期全部在视野外**，因此**智行 App 现在几乎没活干**
（它最有价值的"整窗日历一次 50–62 天"只在国内近端航线可用）。

### 建议（需你点头）

在 `config.yaml` 的用户航线里加一条近端国内日期即可，例如：

```yaml
users:
  - name: 邓美銮
    routes:
      # …原有航线保持不变…
      - from: SHA
        to: HAK
        dates: ["2026-11-20", "2026-11-27"]   # ← 新增：近端国内
```

**预期收益**：智行 App 恢复贡献（每次抓取 50–62 天日历价 + 明细），
且这条通路的实测效率是 **20.2 行/次 @ 70.5s**（对比飞猪 PC 81 行/次 @12.9s，
浏览器仍是主力，智行是"便宜拿远期全景"的补充）。

**不改的理由**：如果你只关心春节行程，那智行确实没必要跑，保持现状（它对那三条日期已 0 秒让路给浏览器）。
