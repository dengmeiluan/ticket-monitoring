## 1. 项目事实与当前状态（开工必核验）

- **运行时下限 Python 3.10**：代码存在运行时求值的 PEP 604 注解（`core/radar_alerts.py:25`、
  `crawlers/ctrip.py:1010`、`crawlers/tongcheng.py:1051`），3.9 导入即 `TypeError`。CI/打包用 3.11。
  这条由 `test_python_floor_matches_pep604_usage` 守着——要么代码去掉这些注解，要么别把徽章写回 3.9。
- SQLite `data/prices.db`；关注清单 `data/flight_watch.json`；雷达快照 `radar_snapshots`。
- Playwright Chromium profiles 在 `user_data/`，承载各渠道登录态。
- 后台扫描轮次由 `main.py` 驱动；实时探针由任务系统执行（任务快照、逐渠道阶段、增量结果、取消、失败重试）。

## 2. 产品语义（不可动摇）

### 2.1 用户级 IA

全站以"用户"为配置与观察主体，不把关注对象做成脱离用户的全局列表。

- 配置页每个用户卡内同时承载：基础（推送/提醒偏好）、监控渠道、关注航线、关注航班、特价雷达。
- 关注航班在用户卡内**内联展开**，不弹层、不跳转。
- 特价雷达属于用户，但数据来自官方渠道特价，**不从关注航线推导**。
- 监控台页签：概览、特价雷达、航线走势、航班走势、航班明细、渠道健康。
- 检索页与配置页共享用户上下文；查询草稿、已提交任务、结果筛选三者互相隔离。

### 2.2 关注航线 / 关注航班

- 关注航线 = 出发地 + 到达地 + 日期/日期范围 + 适用筛选条件下的航班集合。
- 关注航班 = 该集合中按航班身份锁定的子集，**必须真实继承父航线条件**，不是声明上的子集。
- 采集先于关注：用户后关注时能读取已采集的真实历史；不存在的不补造。
- 航班身份需区分：日期、机场、航班号、共享/实际承运、中转结构、跨日、时区、舱位。不能只凭航班号合并。

### 2.3 特价雷达

官方渠道特价机票/低价日历/低价榜的聚合。

五个官方来源：携程（单航线低价日历 + 全国榜）、去哪儿（H5 特价深链，页面自身签名，用已保存会话读真实响应）、飞猪（`cheapestCalendar`，含税 7 天窗，软拒时回退国内榜并冷却）、同程（`queryCalendarLowestPrice`，国际 90 天/国内 180 天）、途牛（国内 H5 同源逐日日历，裸价不含税；国际无官方日历时如实为空）。

- 首屏是「特价监控」（持久化走势），不是每次打开都重查。
- 每次官方日历/榜单结果写入 `radar_snapshots`，按用户/航线/范围保留逐日价与来源。
- 启动约 90 秒首次快照，之后每 2 小时刷新（扫描持锁时跳过）。
  - 实测实现（`webui.py:_radar_auto_loop`）：`time.sleep(90 if first else 7200)`，扫描锁被占用时只记日志跳过，不排队补跑。
  - **自动雷达只遍历前 3 个用户**（`list(_State.users)[:3]`）。多用户部署时第 4 个及以后只有手动触发才出快照——这是当前实现的事实，不是设计意图；新增用户前先确认这个上限是否要放宽。
- 日历价**不能**生成航班、**不能**参与达标、**不能**标成明细成功。
- 采集记录如实显示 成功/缓存/回退/部分/空/失败；失败运行不得画成成功走势。

### 2.4 渠道与登录

优先级：携程 > 去哪儿 > 飞猪 > 同程 > 途牛（用于故障处理与资源分配，不改变最低价与达标计算）。

国内/国际能力矩阵：

| 渠道 | 国内 | 国际 |

3. 本次明细采集成功（具体查询取到真实明细）。

### 2.5 诚实边界

- 不绕过验证码、滑块、风控；只做识别、可见窗口、人工接管、诚实失败归类。
- 一次空结果不能证明渠道无能力；原站有票而程序没有 = 待解决缺陷。
- 只有排除登录要求、验证码、超时、请求异常、解析失败后，才能归类为原站真实无结果。
- 日历价、缓存补位、真实明细是三种语义，永不互相冒充。
- 页面、日志、证据导出不得泄露 Cookie/Token/密码。

#### 路径状态词表（`crawlers/base.py` `PATH_STATUS`，唯一合法取值）

每次路径尝试都落一条账（`path_note`），状态必须取自这套词表，**不在表内的一律被静默降级为 `error`**：

| 状态 | 含义 | 典型来源 |
| --- | --- | --- |
| `ok` | 真实拿到了明细/价格 | 正常采集 |
| `empty` | **站点明确表示无票**。必须有明确证据（"无符合条件的航班"等原站文案），不得由层层兜底产生 | 原站无票文案 |
| `calendar` | 只拿到日历价，没有航班级明细 | 日历接口 |
| `soft_reject` | 门拒/软拒：站点拒答但不是登录也不是无票（如去哪儿 `code:3 当前搜索无航线`、HTTP 999/1999 风控码） | 通道级拦截 |
| `login` | 明确要求登录（登录墙证据） | 需要重新登录 |
| `blocked` | 人机验证/风控拦截，需人工接管 | 滑块/验证码 |
| `timeout` | 请求超时 | 网络层 |
| `parse_error` | 拿到了响应但解析失败 | 报文结构变化 |
| `error` | 其他未归类失败（也是未知状态的兜底） | 兜底 |
| `unsupported` | 该端/该产品本身不提供（如携程单程不售），非错误 | 业务边界 |

纪律：
- **`empty` 与 `soft_reject`/`error` 不可互相冒充**：前者是业务结论，后者是没拿到结论。
- 登录墙记 `login` 而不是 `error`（"该重登"与"该重试"是两回事）；门拒不触发退避与"会话失效"判定。
- 新增状态必须先加进 `PATH_STATUS`，否则会被静默改写成 `error`，账本失真且无报错。
- 每条账同时记 `http` 状态码与 `url`：200 空、202 软拒、444 关连接、403/429 的处置完全不同，只有原始码能事后区分。

#### 渠道健康必须用「在用口径」（r406）

**问题**：退役的旧通路仍在 24h 窗口里留着历史失败。同程 r384 把国际从「日历」换成「窗历」后，
旧「日历」恒 444 但窗口内还压着 35 次失败查询，渠道成功率显示 **63.5%**，
而在用的两条路（窗历 54/54、H5 7/7）都是 **100%**——一个已经不存在的入口把健康渠道说成三分之二坏。

**判据（只用时间先后 + 是否还有产出，不做语义猜测）**：路径 P 已淘汰 ⇔

1. 窗口内**一次都没成功**（关键：只要 P 还在出数，无论 Q 多新，P 都没退役）；
2. 存在另一条路 Q，Q 的最后尝试晚于 P；
3. Q 在窗口内有过成功（确实接住了活）。

> 第一版漏了判据 ①，把**携程 PC（24h 成功 129 次）**误判成淘汰——它只是最近一次尝试比 H5 早几分钟。
> 「比谁新」永远不能单独作为退役依据。

**对外契约**（`core/storage.py`）：节点上额外挂

| 字段 | 含义 |
| --- | --- |
| `retired_paths` | 本次判定为已淘汰的路径名列表 |
| `query_rate_live` | 只统计「至少走过一条在用路径」的查询后的成功率 |
| `query_attempts_live` | 同口径的查询数 |

原 `query_rate` / `query_attempts` **保留可对照**——“在用口径”是补充视图，不是覆盖原数据。

**消费方现状（2026-10-27 逐一 grep 实证，不要照旧说法臆测）**：

| 消费方 | 用哪个口径 | 位置 |
| --- | --- | --- |
| 采集节流建议（advise） | **在用口径** `query_rate_live` | `core/pacing.py` |
| 渠道健康徽标（成功率大数字） | **在用口径优先**，无退役通路时等同查询口径；`cal_only` 轮改用航班级分母 | `webui.py` 健康卡 `shownRate` |

| 节流健康注入 | 原口径 `query_rate` | `main.py` |

> **「控制台路径行」已不存在**（2026-10-28 核对）：旧表第 3 行写「控制台路径行（近 24h 路径）
> 用原口径 `query_rate`」，但界面上已经没有独立的路径行——分通路展示并进了健康卡的 `.hpath`
> 速览，且它直接读 `paths[p].paths[k].rate`（每条通路自己的数），既不读 `query_rate`
> 也不读 `query_rate_live`。按旧表述去 `webui.py` 找「路径行」会扑空。
> 这条口径是对的：逐通路展示就该用逐通路的数，聚合口径留给渠道级判断。

> **口径统一是进行中的工作（2026-10-28 复核）**：健康徽标已从轮次口径切到查询/在用口径
> （`shownRate`：有 `query_rate_live` 用它在用值 → 否则用按域汇总的查询率 → 最后才回落轮次率），
> 目的是消除"徽标 13% / 小标国际 73%"并列的观感矛盾。**分通路速览（`.hpath`）用的是每条通路自己的
> `paths[p].paths[k].rate`**——逐通路就该看逐通路，聚合口径留给渠道级判断。
> 因此「渠道健康已全面改用在用口径」这句话：**对徽标成立，对通路速览不成立**——写文档时必须分开说。

**分域（国内/国际）必须与查询率同口径（r442）**：分域小标与节流面板的分域速览都读
`query_rate_live`（缺则 `query_rate`），不得读 `scopes[*].rate`。后者是**尝试级**口径，
与右半的查询率并列时无法互相核对——去哪儿真实数据实测渲染成「国内 95% · 国际 62% ·
查询 82%」，三个数没有一个对得上（尝试级 39/41、24/39；查询级 39/39、24/38 → 63/77）。
换查询口径后 `39/39 + 24/38 = 63/77 = 82%`，左右两半可加法核对。回落链固定为
`query_rate_live → query_rate → by_scope 轮次率`，绝不回落到尝试级 `rate`。

#### 三种"成功率"共存，文案必须自报口径（r417）

同程曾出现：健康面板 13%、建议条 100%，用户以为两个面板打架——**两个数都对，是口径不同**：

| 口径 | 分母是什么 | 出现在 | 实测数字 |
| --- | --- | --- | --- |
| **轮次口径** | 每一轮采集（一轮里多查询合算一次） | 健康面板条纹/成功率 | 同程 13% |
| **查询口径** | 每一次查询（有一条路径出数即算成功） | 建议条 `advise` | 同程 76%（原口径）/ 100%（在用口径） |
| **在用查询口径** | 同上，但剔除退役通路 | 建议条（r406 起） | 100%，并附「已排除退役通路 日历（在用 100%）」 |

**文案硬要求**：建议条必须写「近 24h 查询成功率」而非「近 24h 成功率」；
有退役通路时必须补一句「已排除退役通路 X（在用 Y%）」，否则读者看不出旧坏路已被剔除。
三者数值不一致**不是缺陷**，但没有一句口径说明就是缺陷。

#### 账本的另外两条硬规则

- **成功路径也要记 `request_url`，且必须是真正调用的那个端点**（r407）。
  不能拿“最后打开过的页面”兜底——同一轮里 H5 失败后接 httpx 时，页面早已关闭，
  会把 A 路径的地址记到 B 路径头上。
- **同一 attempt 内结论互斥，升级要撤销前一条**（r408）。
  1999 从“单次软拒”升级成“连续未放行=登录”时，必须撤掉本轮已写的 `soft_reject`，
  否则同一次查询、同一秒会出现两条互斥结论并列（账本自相矛盾）。

## 3. 设计语言：微信式扁平（全站唯一语言）

目标不是"给页面加扁平样式"，而是**同一个产品、同一套语法**。任何页面不得自带第二套皮。

### 3.1 六条语法

1. **表面只有两层**：页面画布 `--bg`；内容表面 `--card`。行 hover 用 `--hover`、隔行底色用 `--rowalt`、输入底用 `--card`/`--headbg`。禁止：卡中卡、卡上套卡、给每条信息一个边框盒。
  - 历史说明：旧版规范写 `--r-canvas` / `--r-surface*`，这四个名字在代码里**不存在**（除 `--r-surface*` 的 3 处残留），真实令牌是上面这组。以代码为准。
2. **分层靠留白与浅底，不靠线**。分隔只用 1px 发丝色（`--line` / `--r-hair`，浅灰低对比），
   且只用于「结构需要」的三类位置：表格行间、列表行的必要分隔、注脚/分组的功能性下缘。
   - **判失败的是"装饰线"，不是"所有线"**：给卡片描边、给每条信息套盒子、用深色或高对比线条
     划分层级，都属违规；同一屏出现 3 条以上**视觉可辨的装饰性**横线即判失败。
   - 实测基线（主样式块口径）：`border-top/bottom` 声明 **94 条**，其中 80 条用发丝色
     `var(--line)`（59 条 solid + 21 条 dashed），余下为 7 条 `0`、1 条 `none`、2 条 dotted，
     以及少数结构特例（`--line2` 页头下缘、`--ctlbd` 输入下划线、`--blue` 聚焦态、
     `color-mix(...--line 55%...)` 的 cfg 页头）——均属上述允许类别；
     新增代码不得引入深色分隔或描边卡。
   - 判断标准是"读者是否看见一条线在划分层级"，不是声明条数。
3. **一屏一个视觉主角**。概览页主角是"当前最低价与达标状态"；走势页主角是曲线；配置页主角是"当前分区内容"。其余元素降到 11/12px 辅助字与 `--mut`。
4. **行式信息结构**：左侧对象名（13–14px，600）、中间次要信息（12px，`--mut`）、右侧数值或动作（等宽数字或纯文本按钮）。同屏同类行：行高一致、左缘一致、右缘一致。
5. **动作写在对象身上**。行级动作放行尾或行头，卡级动作放卡头。**不得**放进展开体尾部、不得要求滚动才可见、不得出现两处同名动作。
6. **文字即界面**。按钮文案 = 动作结果（"收齐"→"已收齐 · N"，"说明"→展开说明，不换词）。不用只有图标、没有文字的入口；必要图标必须有 `aria-label` + `title`。
7. **折叠文案同构**。所有折叠类按钮一律「展开/收起 + 对象」：展开筛选 / 收起筛选、展开更多条件 / 收起更多条件、展开概览 / 收起概览、展开探针 / 收起探针、展开更多工具 / 收起更多工具、展开说明 / 收起说明。同一个动作在全站只能有一个名字（"更多筛选"与"更多条件"曾是同一件事的两个词）；状态词与 `aria-expanded` 必须同拍。三角形符号（▸/▾/▴）**只用于跳转类链接**（查看明细 ▸），不用作折叠指示。**例外**：携带计数的事实型 chip（如「组合 2/4」）保留计数为主文本，展开/收起语义放进 `title` + `aria-label`，不得把数字挤掉。
  - **已知偏差（2026-10-27 实测，未修）**：渠道健康的说明折叠用 `说明 → 收起说明`（`webui.py` `srxToggleScNote`），收起态少了「展开」二字，与本条不一致。当前没有任何门禁钉这个按钮，所以长期未被发现。修它属代码变更（要连带补门禁），不在文档维护范围内；此处如实记录，后续动该区块时一并收口。

### 3.3 密度纪律

- "紧凑"不等于"挤"。信息行 32–36px，可点击行 ≥ 36px（触屏热区地板同为 36px，见 §4.1 第 10 条），区块间距 12–16px。
- 禁止"无意义留白"：折叠体收起后不得留 `min-height`、空 `padding` 或占位骨架；区块之间不得出现超过 24px 的孤立空白带；同级区块之间不得一处 6px 一处 18px。
- 也禁止"为了紧凑而缩字"：正文级文字不低于 12px，关键数值不低于 14px。

## 4. 交互心智铁律 + 缺陷台账

### 4.1 十条铁律（新代码一律遵守）

1. **相邻律**：展开内容必须**紧贴触发器下方**。DOM 顺序是 `触发器 → 展开体`，中间不得夹任何常驻元素（说明文字、标签、按钮、另一个折叠）。
2. **不动律**：展开/收起前后，触发器自身的屏幕位置不得移动（误差 ≤ 2px，窗口尺寸变化除外）。
3. **单一触发**：一个折叠只有一个可点区域；点两次必须是"开 → 关"，不得变成"开 → 打开另一个"。
4. **真收起**：收起后高度必须真实减少 ≥ 展开体高度；不得用 `visibility`/`opacity`/`height:0 + padding` 留空壳。
5. **状态可见**：`aria-expanded`、文案、图标三者同拍；"全部收齐 / 全部展开"必须成对存在且位置固定。
6. **动作贴对象**：行级动作在行内，卡级动作在卡头；禁止把删除/登录/自检等动作放到展开体末尾。
7. **不遮挡**：吸顶元素必须实底；图表、表格、列表的任何覆盖层不得遮住数据。
8. **计数同源**：同一数字在一页只允许一种口径；跨日期总量、所选日期量、筛选后可见量必须分别标注。
9. **空态有出路**：空态必须说明原因并给一个可执行入口，不得让"加载中…"永久停驻。
10. **每个可点元素都要有悬停反馈**。2026-10-29 实测 132 个可交互元素，发现 `.pill.ok`「有人已达标」（`role=button` + onclick + `cursor:pointer`）在三个视图里**悬停零变化**——`.pill:hover{filter:none;background:…!important}` 与 `.pill.ok{background:var(--okbg)!important}` 同为 (0,2,0)、后者更靠后，把 hover 的灰底整条压掉。修法：补同特异度、更靠后的 `.pill.ok:hover`，**保持语义绿**（不改成中性灰），底色压深 12%（18% 会让 hover 态掉到 4.35:1 欠 AA，12% 为 4.75:1）。门禁 `test_clickable_status_pill_has_hover_feedback`。
    - **判 hover 反馈必须用真实鼠标**：CSSOM 里「有匹配的 `:hover` 规则」不等于「规则生效」——本例 57 类元素 100% 都有 `:hover` 规则，真实鼠标一测才发现 `.pill.ok` 被 `!important` 压死。反过来，用采样时的坐标去 `elementFromPoint` 也会因滚动失效而误判。
10. **键盘与触屏等价**：所有折叠/切换/行内动作可 Tab 到、可 Enter/Space 触发、focus 环可见。
    - 触屏热区地板 = **36px**（`pointer:coarse` 下由 `@media` 三档统一抬升；门禁钉在
      `docs/uitest.py` 的「coarse 裸 button 36px」与「nav span 36px 地板」两条）。
    - 旧版本文档写 ≥44px，与实现和门禁不符；**以 36px 为准**。主操作按钮可做到 44px
      （如抽屉 CTA），但不是全站硬门槛。
    - **热区与盒高可以不一致**：被降级为行内文字的可点元素，外观就该是文字高，但热区仍要 36px。
      实测（2026-10-29，1440）配置页 `.chband-specs .chlink` 盒高仅 **15px**、
      `elementFromPoint` 逐点探测上 8px / 下 7px（共 16px）——「PC 特价 ↗」这类入口很难点中。
      修法是伪元素补热区（`::before{top:50%;height:36px;transform:translateY(-50%)}`），
      **不改 `min-height`/`padding`**：实测补后热区 36px（上 18 / 下 17）、盒高仍 15px、观感零变化，
      7 个链接中心点全部命中自己、容器无溢出。门禁 `test_inline_channel_links_have_a_touch_sized_hit_area`。
    - 判「热区够不够」只能靠**命中测试**（`elementFromPoint` 上下扫描），不能用盒高代替：
      盒高 15px 的元素可能有 36px 热区，反之加了大 padding 的也可能被相邻元素盖住。

### 4.1b 配置生效契约：热加载 vs 启动级（新配置项必须归类）

保存配置后是"立即生效"还是"要重启"，**必须在写代码时就归类**，不能靠读者猜。
实测（2026-10-28）：README 三处都列了六项启动级，而界面的重启中心空态文案只写四项
（漏了 `host` 与 `run_on_start`）——同一承诺在不同位置说法不一。

**启动级（保存后必须重启才生效，UI 要显示旧→新差量与重启按钮）**：

| 键 | 位置 | 为何必须重启 |
| --- | --- | --- |
| 数据库路径 | `output.db_path` | SQLite 连接在进程启动时建立 |
| 日志路径 | `output.log_path` | 日志 handler 启动时绑定 |
| 登录态目录 | `crawler.user_data_dir` | 各渠道 profile 目录启动时确定 |
| 内核目录 | `crawler.browser_dir` | Playwright 内核路径启动时解析 |
| 监听地址 | `web.host` | socket 已绑定，改地址只能重开（`webui.py:455` 注释明示） |
| 启动即扫 | `schedule.run_on_start` | 只影响"进程启动那一刻是否立刻跑一轮" |

**热加载（保存即生效，不必重启）**：航线/阈值/通知通道/扫描周期与扰动/
`web.port`（原地切换监听）/**无头/超时/错峰/日报时刻/图床**。

**判据**：新增配置键时，先判断它是否参与"进程启动时的一次性初始化"——是则归启动级，
必须在重启中心可见；否则归热加载。**两类都不能悄悄落在中间状态**（改了没生效也没提示）。

> 门禁 `test_spec_startup_keys_are_actually_startup_level` 对着代码核这张表：
> `webui.py` 的 `_startup_vals()` 返回的键集合必须覆盖表里的路径四件，且 `host` /
> `run_on_start` 必须仍由同一函数产出（r345 把它们并入启动级）。

### 4.2 缺陷台账（D1–D22 已于 r374 逐条关闭；新建缺陷按同样格式追加）

> 每条给出：现象 → 根因方向 → 判定标准。判定必须在真实浏览器完成。

**D1 检索页「展开概览」中间夹常驻元素。**
现象：点「概览」后，展开的价带/五源/审计区与按钮之间还隔着探针卡等常驻块；触发器在头部，内容在下方远处。
判定：展开体第一个可见子元素的 `top` 与触发器 `bottom` 差值 ≤ 8px，中间 `elementFromPoint` 命中触发器或展开体；触发器位置前后位移 ≤ 2px。

**D2 检索页「说明」展开位置错误。**
现象：说明按钮在来源卡动作区，展开的文字却出现在另一行/别处，形成"说明展开在控制台下面"的割裂感。
判定：展开后说明块紧贴按钮所在行动作之后（或按钮正下方同宽），不得跨越其它行；触发器自身不移位。

**D3 探针「展开/收起探针」触发器位移。**
现象：展开后表单插入，开关被挤动。
判定：开关 `rect` 前后差 ≤ 2px（1440/390/320 三档）；开关锚定在探针头右侧，不参与表单换行。

**D4 折叠后仍有许多分割线、不干净。**
现象：多个折叠块之间保留了边框/分隔线/圆角卡，收起后像一堆空盒子。
判定：收起态下相邻区块之间不得出现可见 1px 线；同屏**视觉可辨的装饰性**横线 ≤ 3 条（发丝色行分隔不计，见 §3.1 第 2 条）；折叠区块自身 `border:0`。

**D5 特价雷达走势滑动卡顿。**
现象：横向滚动时整体重绘，指针拖动不跟手。
判定：滚动/拖动期间不得发生 canvas 尺寸变更（`ResizeObserver` 记录 0 次）；单帧长任务 < 50ms；拖动用 `pointerdown/move/up` + `setPointerCapture`，位移走 `transform`，不触发重排。

**D6 特价雷达走势白色遮挡，短点被盖住。**
现象：数据点少时出现白色块遮住线尾/低点。
判定：绘图区内不存在覆盖层与数据区重叠；用截图采样：数据线坐标处颜色必须是曲线色 ± 容差，不得为白色或 surface 色。

**D7 走势断档。**
现象：线跨过缺测区间；或缺口被画成连续，看起来"数据完整"。
判定：注入"中间缺失 6 小时"的 fixture，缺口区间内沿 x 采样不得出现曲线色像素；缺口两端各有一个空心断点标记，tooltip 显示"缺测"。

**D8 三处走势图各写一套实现，交互/视觉不一致。**
判定：`chart()`（航线走势）、`wsDrawChart()`（航班走势）、`spMonDraw()`（雷达走势）必须收敛到同一 `PCHART` 渲染器；三处只允许传配置；三处的 hover/tooltip/resize/空态/坐标刻度行为一致（同一套 Playwright 断言跑三次全绿）。

**D9 组件衔接留白不均，紧凑但没质感。**
判定：同页相邻区块间距集合 ⊆ {4,6,8,12,16,24}；最大/最小区块间距比 ≤ 4；无 > 24px 的孤立空白带（DOM 矩形扫描）。

**D10 渠道入口只有"扁平"，没有设计语言与对齐。**
现象：渠道×入口矩阵的列头与行内容左缘不一致（表头 160px 列 / 行 148px 列的典型错位）；"特价"占半排空格子。
判定：列头首列宽 = 行首列宽（同令牌变量）；四列入口格同排等高等宽；渠道名/会话徽标/登录要求左缘对齐；无半排空腔。

**D11 配置页「全部收齐」按钮被错误嵌套。**
现象：`#cfgFoldAll` 位于 `#cfgChromeRestart` 内部，形成 button-in-button；点「全部收齐」会冒泡打开重启中心。
判定：三个 chip 为**兄弟节点**（`parentElement` 相同）；点「全部收齐」后重启中心保持 `display:none`；各自 `aria-expanded` 与文案独立更新。
- **现行实现核对（2026-10-27）**：兄弟节点已成立，且 `tests/test_r374_unified_ui.py::test_config_status_chips_are_siblings` 钉住"不得嵌套"。但**两个 chip 都没有 `aria-expanded`**——它们是动作按钮（打开弹层 / 一次性收齐），不是折叠开关，属可接受语义；本条原文中的"各自 `aria-expanded`"**未实现也不打算实现**，勿据此提缺陷。

**D12 配置页各 tab 无法一键收齐；收齐不覆盖当前分区。**
判定：三分区（渠道登录 / 用户与航线 / 全局参数）内所有可折叠组（分组、航线行、渠道卡）一次点击后全部收起；文案短暂显示"已收齐 N"后复位；切换分区后按钮仍可用且作用域正确；理想态同时提供"全部展开"。
- **现行实现核对（2026-10-27）**：跨分区收齐已由 r412 落地——`cfgFoldAll()` 遍历全部 `.cfpanel`，把折叠态写进 `FOLD` 存档，未渲染分区由 `applyFolds()` 按存档收起；用户卡头（`.uhead2[data-u]`）一并收齐。**"全部展开"未实现**（代码里没有 `全部展开` 字样），属未落地理想态，不得写成现状。

**D13 配置页面板层级被改坏，表头与内容不对齐。**
现象：面板头（`uhead`）的图标/标题/说明与下方内容左缘错位；分组标题与卡片内容缩进不一致。
判定：同面板内 `uhead` 文本左缘、分组标题左缘、卡片内容左缘落在同一 8px 网格列，误差 ≤ 1px。

**D14 用户卡动作位置别扭（如「用户明细」）。**
判定：用户卡主操作必须位于卡头右侧动作区，不得出现在展开体中部或行尾杂项里；同名动作全站只出现一次。
- **现行实现核对（2026-10-27）**：卡头 `.uhead-end` 目前只有「删除用户」一个动作（`.uact danger`，带 `aria-label`，`stopPropagation` 防触发展开）＋ 状态箭头；**「用户明细」这个入口在代码里已不存在**，原文举的例子已失效。关注航班的新增/编辑按钮位于用户卡 D 区（`#cfgWatch` 工具栏 `data-cwact="add"`），属**分区级**动作而非卡头动作，不违反本条。

**D15 渠道健康自检按钮未对齐。**
现象：诊断卡高度不一，自检按钮各自漂浮。
判定：同排诊断卡等高（误差 ≤ 1px）；动作行贴底（`margin-top:auto`）；按钮基线一致；长证据文本换行不推挤按钮。

**D16 航班明细吸顶表头透明，滚动时数据从表头下穿过。**
判定：滚动 200px 后截图，表头区域像素必须是表头底色（不得出现行文字）；表头 `z-index` 高于表体；`background` 为不透明实色（按主题变量解析后的实际颜色判定）。

**D17 走势图未统一框架（D8 的页面侧体现）。**
判定：航线走势 / 航班走势 / 雷达走势的容器高度、坐标轴内边距、网格样式、tooltip 样式、图例位置、空态文案结构必须一致；差异只允许出现在业务标注（达标线、目标线、低点标签）。

**D18 补位数据真实性存疑。**
现象：列表出现"补位 57 / 补位 32.7h"等行，与真实明细混排。
判定：补位行必须有"来源 + 采集时刻 + 年龄"；视觉上与真实行分区（不得同色同权）；不参与达标/最低价/同班比价；排序不得压过真实行冒充最低；"仅看真实/隐藏补位"开关可一键隔离且计数同步。

**D19 解析正确性未复核。**
判定：抽 5 条真实 raw，逐字段核对价/税/舱位/时长/跨天/机场/共享承运/退改；缺键显示"未供"，不得猜测；与 raw 不一致即为缺陷。

**D20 测试存在跳过、重复、过时用例。**
判定：新增 `skip/xfail` 数量 = 0；同义断言只保留一处；已废弃行为对应的用例删除，并在提交信息写明原因。

**D21 首屏与深链加载依赖额外点击。**
判定：深链进入特价雷达/关注走势，首帧数据自动到位（`/api/radar/history`、`/api/state` 已发出），不需刷新或切页。

**D22 陈旧标签页造成"改坏了"的误判。**
判定：页面版本与 `/api/state.version` 失配时显示刷新横幅；门禁记录 `window.__PAGEVER__` 与进程版本一致。

## 5. 页面级要求

### 5.1 概览

- 首屏顺序：当前对象与状态 → 关键数字（最低价/达标/下一轮）→ 走势主图 → 异常入口。
- 折叠摘要常驻可见，展开体紧贴其下（D1）。
- "去配置 / 去登录"入口在对应异常出现时就地给出，不让用户自己找页签。

### 5.2 实时检索

- 结构：检索台（用户/航线/日期/渠道）→ 当前任务反馈 → 结果筛选 → 列表/矩阵 → 镜像/详情。
- 折叠区（概览/价带/五源/说明）全部遵守 D1/D2/D4。
- 价带全未采时收敛为"日期范围 + 未采说明 + 查询入口"，不留 14 个空格子。
- 说明类文字默认收起，展开在触发器正下方；展开体里不再塞动作按钮。

### 5.3 航班明细

- 吸顶表头实底（D16）；表头与表体列宽单一真源（同一 `colgroup`/grid 模板），缩放后仍对齐。
- 行内动作（定位/比价/关注）放行尾；批量动作放表头工具条；不得散落。
- 窄屏横向滚动要有可发现性（右侧渐隐 + "左右滑动"提示），滚到底自动撤提示。

### 5.4 航线走势 / 航班走势

> 页签名以 `#montabs` 为准：「航线走势」「航班走势」——旧称「关注航线走势 / 关注航班走势」已废；本节讲的是这两张走势图，"关注"只是数据范围而非标题用词。

- 与雷达走势共用 `PCHART`（D8/D17）。
- 图注必须说明：对象（航线/航班）、横轴（采集时间/出发日期）、价格口径（含税/裸价/未标）、是否存在缺口/失败/过期。
- KPI 行、标题、图表、图注、明细卡自上而下对齐同一左缘。

### 5.5 渠道健康

- 诊断卡等高、动作贴底（D15）；状态不能只靠颜色，必须配文案。
- 自检/重登/预热的批量动作放区块头；执行中显示真实进度，结果不被自动刷新冲掉。
- 时间线图例、格子、计数三项对齐；长文案换行不得挤压指标。
- **健康度是四维的，不能只报厂商一个数**（r415/r406/r421 实测口径）：
  1. **厂商级**：徽标上的单个成功率。口径按优先级取——有 `query_rate_live` 用它（**在用口径**）→
     否则用按域汇总的查询率 → 最后才回落轮次率；`cal_only>0` 的轮改用航班级分母（`明细 50/87`）。
     **不要写成"近 24h 成功率"了事**：三个候选口径会给出不同数字（见 §2.5 三种口径表）。
  2. **分域**（`by_scope`，r415）：`国内 X% · 国际 Y%`，两端都有样本才显示。
     实测：同程厂商 12% 其实是国内 100%(5/5) + 国际 13%(5/39)——国际日历通路的门拒污染了厂商总分。
  3. **分通路**（`paths`，r406）：同厂商内 PC/H5/日历/窗历 各自成功率，退役通路标灰注明。
  4. **分会话**（`slots`，r421）：同一厂商有多个**独立 cookie** 的会话时逐端列出
     （当前只有飞猪 PC / H5 双槽），`PC 入口可达` / `H5 需重登` 并排；「去登录」落到具体槽位。
     单会话厂商不显示这一行，避免噪声。此前只有厂商一个维度，飞猪 H5 掉了照样只写「飞猪需登录」，
     看不出该核哪一端。**演示载荷（`demo:true`）只写「PC 演示 / H5 演示」且不染色**——
     合成会话不是真实登出，红点会被局部截图当成故障。
     节流面板的「需登录」同理：多会话厂商必须点名失效端（`H5 会话已失效`），
     单会话仍写「会话已失效」；会话态比节流面板晚到时按 `_paccSlotSig` 自动重画。
     动作必须跟随证据：多会话时按钮改「去登录 H5」直达该端槽位
     （`srxGoLogin('fliggy_h5')`），不再给会打开厂商级验证窗的「去验证」。
  5. **诊断卡同维**（r430）：`diag` 卡片也按会话给证据——`dead_surfaces` +
     `slot_action`，前端写「H5 登录态失效 · 打开登录 H5」。
     **不能为此把演示 `/api/health` 接进 `_health_decorate`**：那会打开 PriceStorage，
     接口从 0.03s 挂到 25s+，页面 `networkidle` 永不达成、整批 UI 用例连锁超时
     （实测 34 error）。演示与真实都只调 `_attach_diag_slots`（只读 `/api/login-state`）。
     该函数会回到 `_login_state_view`，后者默认仍走 `_health_state`（保留测试注入点），
     仅在 `_IN_HEALTH_DECORATE` 置位时改走「直接解析日志」，避免无限递归。
     演示的分域/分通路由 `_attach_demo_paths` 从**轮次已有字段**聚合补上（否则演示里
     健康只有厂商一个数）；**失败轮必须计入该渠道的通路分母**（否则通路只剩成功轮恒为
     100%，与徽标 93% 打架），**维护轮既不算成功也不算失败**（否则查询率被拉低到 15%
     而通路仍 100%）；但绝不能臆造一条叫「无出数」的通路。
     **健康卡与节流面板必须读同一份聚合**（r441）：演示 `/api/paths` 曾恒返回
     `platforms={}`，于是同页健康卡写「明细 97%」、节流面板写「按轮判定 · 明细 0 /
     日历 0」，两个面板对同一渠道给出互相否定的结论。现两条接口共用
     `_demo_paths_from_rounds`；演示聚合还须给出查询级 `query_detail_ok` /
     `query_calendar_only`（与生产 `path_stats` 同名同义），否则节流行右半会写成
     「查询 93% · 明细 0 / 日历 0」。通路名本身含「日历」时台数用 `×N` 承接，
     不得拼成「日历 日历14」。
  口径边界：分域只解决"哪一端坏了"，**"健康度该按哪条通路算"仍以 §2.5 的在用口径为准**；
  节流罚速（`set_health`）读的是**原口径** `query_rate`（`main.py`），不随徽标切换。
- **两张通道表同序**（r421）：健康行与「节流与干预」的渠道行都必须走 `SRX_PLAT_ORDER`
  （携程→去哪儿→飞猪→同程→途牛）。曾分别用字母序与 API key 序各排一套，上下相邻却对不上。
- **多槽位动作必须落到失效端**（r449）：飞猪 PC/H5 双槽时 `needs_login` 是厂商级的，
  但按钮不能写「去验证」——`/api/channel/verify` 只收 platform，点开的是 PC 窗，
  与「H5 会话已失效」对不上。按钮文案写「去登录 H5」，`onclick` 实参必须是**失效槽位**
  （实测 `srxGoLogin('fliggy_h5')`）。只断言文案不够，契约要钉到实参。
- **退役通路不得静默消失**（r449）：`retired` 里的通路要 push 成「<名> 退役」留在行内，
  且不得被当成在用通路再算一次成功率（否则同一通路出现两遍、把在用率拖低）。
  真实库平时 `retired` 为空，这两个分支只能靠注入载荷才验得到，别以为跑 demo 覆盖了。
- **演示态不显示可被引用的合成百分比**（r449）：`_demoAll` 为真时 `pathTxt` 与 `_qbit`
  都置空，节流行右半只写「合成样本 · 不参与成功率」。理由：`--demo` 的百分比是按合成
  轮次迭代算的，与真实实测读起来一模一样。**但这个屏蔽只许作用于演示态**——顺手写宽
  会把真实实例的分域/分通路一起抹掉，等于退回「渠道健康只有厂商一个数」。
  验收时两侧都要看：演示态应无百分比，非演示路径应仍出
  「国内 … · 国际 … · H5 … · 查询 … · 明细 n / 日历 n · m 次」。
- **不可用也是一种状态，不许静默消失**（r450）：预热只对声明了 `warmup_url` 的渠道生效
  （当前 qunar/fliggy/tuniu；ctrip/tongcheng 没有）。旧实现直接 `.map(WARM)`，把这两家
  从按钮行里删掉，用户看到「预热 3 个 / 自检 5 个」会以为面板漏渲染。现在五家全列，
  无入口的给 `disabled` + `aria-disabled` + 原因 `title`（「该渠道未配置预热入口，打首页
  不会下发可用会话」），且**不绑 onclick**（避免点了没反应）。不可用态对比度实测
  亮 5.03:1 / 暗 6.03:1，仍达 AA。
- **「全部」必须与逐个按钮同源**（r450）：`warmAll()` 曾写死 `['qunar','fliggy','tuniu']`，
  配置一改就与按钮行不一致。现从 `PACE_CFG.warmup_platforms` 读（`loadPacing` 写入）。
- **复发备注窄屏最多两行**（r454）：两次踩坑的折中。放开成 `normal` 时一条 200 字备注
  撑 3 行、5 条吃 680px（360 档行高 136px）；改成一律 `nowrap` 后**真实**备注被切——
  「国际列表 1999/8 连续 7 次未放行（疑会话失效）」在 420 档只露 226/323px（丢 97px）、
  360 档丢 157px，而这句正是「要不要人工介入」的依据。现 `-webkit-line-clamp:2`：
  宽屏单行 50px、窄屏两行 68px，5 条超长备注在 360 档实测 345px（旧实现 680px）。
- **CSS 少一个选择器会吞掉其后整张样式表**（r456，最贵的一课）：`:is(.btn2,{…}` 少了
  第二个选择器，浏览器从此处起**静默丢弃后续全部规则**——`.pace*` 125 条规则一条没生效，
  节流面板从「台账」退化成裸文字 + 蓝色实心按钮，而 pytest 全绿、UI 用例也全绿
  （用例查 DOM 结构与文本，查不出 CSS 没生效）。判据：`document.styleSheets[1]` 里
  `.pace` 命中数应为上百，突然变 0 就是被前面的语法错误吞了。
  门禁：`test_css_rules_are_syntactically_valid`（括号配平 + 禁 `,{` 空选择器）已加负控。
- **干预成效必须出现在决定行上**（r456）：最高准则是「让用户做得成能提高成功率的操作」，
  而唯一能回答「按哪个钮有用」的是「上次同类干预带来了什么」——同程实测 44%→100%
  （121 次样本）、去哪儿 44%→71%。这段原先只在点开「溯源」后可见，等于把决策依据

## 6. 走势图统一框架（强制）

### 6.1 单一渲染器

`PAGE` 内的唯一渲染内核 `PCHART`（2026-10-27 按 `webui.py` 实测校正）。

**形态**：不是一个持有 canvas 的实例对象，而是**共享函数库**——各调用点自己持有
canvas/ctx/DPR/指针事件，只把坐标系、刻度、断档、命中、浮窗定位交给 `PCHART`。
（旧版文档写的 `mount/draw/hover/destroy` 四方法从未实现，调用处为 0，已废弃该描述。）

真实成员（改动前先读实现，不要照旧文档臆造）：

```
PCHART.prep(c)                       // 预处理：点集排序/去重、时间轴准备
PCHART.niceTicks(mn, mx, n)          // 1/2/5/10 阶梯取整
PCHART.domain(vals, padRatio)        // Y 域；单值/同价给最小高度，避免 ±Infinity
PCHART.frame(W, H, {xKind, n, x0,x1, y0,y1, axisRows})
                                     // 内边距单源（PCHART_PAD）+ X/Y 映射，返回 {L,R,T,B,X,Y,...}
PCHART.axes(ctx, frame, {ticks, xTicks, ...})   // 网格与刻度
PCHART.line(ctx, frame, pts, {color, width, gapMin})
PCHART.area(ctx, frame, pts, {color, gapMin})   // 主角线面积填充（三处都有）
PCHART.markMin(ctx, ...)             // 最低点标记
PCHART.gaps(pts, gapMin)             // 断档分段（中位间隔 × 1.8，不低于 gapMin）
PCHART.pick(...)                     // 最近点命中（先比 |Δx|，同刻容差内再比 |Δy|）
PCHART.placeAxis(boxW, boxH, tw, th, localX, topY)  // 浮窗落位算术（唯一一份）
PCHART.placeTipAxis(host, tip, cx, topY)            // DOM 浮窗：取 placeAxis 结果落位
                                                    // 航线画布浮窗直接取 placeAxis 绘制
                                                    // 规则：横向跟十字线并翻边，纵向恒在顶部带
```

内边距常量：`PCHART_PAD = {L:48, R:16, T:12, B:26, B2:40}`（`B2` 用于两行轴刻度）。

**调用契约**：`chart()` / `wsDrawChart()` / `spMonDraw()` 只允许调用上述函数，
不得各自实现坐标、刻度、断档、命中、浮窗定位（D8/D17）。
与旧文档的差异：三处各自保留自己的 cfg 组织与 canvas 绑定，**共享的是内核函数而非某个
`draw(cfg)` 入口**；统一性靠"同一个 `frame`/`gaps`/`pick`/`placeTip`"保证。

`chart()` / `wsDrawChart()` / `spMonDraw()` **只允许**构造 cfg 并调用 `PCHART`；不得各自实现坐标、刻度、tooltip、resize、空态（D8/D17）。迁移期可以保留旧函数名作薄封装，但内部必须只剩配置构造。

### 6.2 断档规则（D6/D7）

- 相邻点时间差 > `gapMs` → 断线，两端画空心断点。
- 缺口中间**不画任何填充/遮罩**；不得用白色矩形盖住缺口（当前白色遮挡的根因方向）。
- tooltip 在缺口处显示"缺测 · 前次 HH:MM · 后次 HH:MM"。
- 单点系列只画点，不画线，不显示"线尾"装饰。
- 价格口径混合时（裸价/含税）：只画可信度最高的一种，并在图注写"仅画含税口径"；单口径数据原样保留，不得过滤成空。

### 6.3 X 轴与密度（D5）

- 画布宽度 = **取大(可视宽, min(点数 × 最小间距, 可视宽 × 2.4))**（2026-10-27 实测 `webui.py` 中 `const W=Math.max(baseW,Math.min(units*MINPX,baseW*2.4))` 这一行；**不写行号**——并行改写后行号会漂）
  - 最小间距：K 线 46px / 时间轴 30px；少于该密度会把密集点挤成糊线，悬停也分不开相邻点。
  - 宽于可视宽时**必须真的能滚**：`scrollWidth > clientWidth` 且拖动生效。
    r373 曾把宽度锁成可视宽——拖动指令还在、光标仍是 grab，但拖了不动，即用户实报的「滑动卡顿」；
    因此"锁成容器宽"是**已被实证否决**的做法，不得回退。
  - 绘完自动滚到最新（数据在右端）；用户手动拖动过就不再抢回。
  - 上限 2.4× 可视宽：防止点数极多时画布无限拉长。
- 点数密集时可压缩 x 域；若做缩放，缩放只改域，不改画布宽度的取大公式。
- 横向平移：先绘制一次静态位图，平移期间不重绘、不重排（三处走势统一走 `_CHBASE` 位图底座）。
- 悬停：`pointermove` 合帧到 `requestAnimationFrame`；最近点以 `|Δx|` 为主键、`|Δy|` 为次键。
- 十字线与 tooltip 不得超出宿主容器；`position:fixed` 的 tooltip 按视口钳制。

### 6.4 视觉一致（D17）

- 绘图内边距：基准左 48 / 右 16 / 上 12 / 下 26（`PCHART_PAD`），另有 `B2:40` 供两行轴刻度。
  - 实情是**同源而非同值**：`PCHART.frame` 在基准上按 `band`（顶部价签带）与 `axisRows`（1/2 行轴）扩展；
    航线走势调用点再按自身需要偏移（`L+16, R-2, T+2, B2+12`，见 `webui.py` 航线走势段）。
  - 约束是"不得绕开 `PCHART_PAD` 另造一套内边距"，不是"三处像素值必须完全相等"。
- 网格：1px 虚线，色 `--grid`，不透明度 ≤ 0.5；Y 轴走 `nice-step` 取整（1/2/5/10 阶梯）。
- 线宽 1.5px；低点/目标标签带 halo，按已放置盒互避重叠。
- 选中日高亮带在最底层，不覆盖曲线。
- 入场动画遵循 `prefers-reduced-motion`。

### 6.5 数据诚实

- 不补零、不插值、不用历史最低价替代真实观察。
- 目标线/达标线与明细/推送同口径，或在图注明确标注差异。
- 空态写清"为什么空 + 怎么办"，不写"加载中"占位。
- 图表下方的 `sr-only` 表格必须与图上的点同源，便于读屏与证据核对。

### 6.6 有意保留的差异（不得以"统一"为由改掉）

## 7. 数据真实性与解析正确性（D18/D19）

- 三种来源必须可区分：**真实明细 / 日历参考价 / 补位缓存**。UI、计数、导出、推送都要能分。
  - 代码里的表达方式（2026-10-27 实测，不要臆造一个 `real/calendar/cache` 枚举字段）：
    - 行来源由 `path_status` 区分——`ok`＝真实明细，`calendar`＝日历价（`core/storage.py` 多处按
      `path_status IN ('ok','calendar')` 聚合）；`unsupported` 表示该端本就不供。
    - 补位行来自历史缓存，带采集时刻与年龄，UI 用「去日历/补位」筛选隔离——真实开关是
      `SRX.f.hideCal`（`webui.py`，勾选后 `FLT.hideCal=true`）；**没有**叫 `real` 的筛选项（2026-10-27 核），也不是靠一个 `cache` 状态值。
    - `prov` 字段保存入口/路径级证据 JSON（空＝未记录），用于溯源到具体请求。
- 补位行规则：显示来源渠道 + 采集时刻 + 年龄（如 `32.7h`）；与真实行视觉分区；不参与达标、最低价、同班比价；默认排序不得让补位压过真实行；提供"隐藏补位 / 仅看真实"一键隔离并同步计数。
- 同一查询内"来源 X 行"与"列表 Y 行"必须能对上；对不上就解释口径，不允许两个数字并存而无说明。
- 解析核对：每渠道抽 5 条 raw，逐项核对价格、税费、类别、日期、航班号、起降时刻、机场/航站楼、跨天、时长、中转、舱位、共享/实际承运、退改。缺键一律"未供"，不猜。
- 补位数据不得写入 `history` 冒充真实采集点；雷达走势只用 `radar_snapshots` 的真实快照。
- 任何"看起来像真实"的合成数据（演示模式）必须全程可辨识（DEMO 徽标 + 合成说明）。

## 8. 测试与门禁纪律（D20）

### 8.1 命令

- `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 python -m pytest -q`

    一行测试都跑不到。`-p no:langsmith` 也救不了——插件在 entrypoint 加载期就已报错。
  - 只关这项自动加载不影响项目自身用例；CI 与 `CONTRIBUTING.md` 用的是同一条命令。
- `python docs/uitest.py`
- 发布阶段：`python docs/release_align_check.py`（本地用 `--local`，不访问 GitHub）

### 8.2 规则

- **全绿**：pytest 0 failed；UI 门禁 0 失败、0 `pageerror`、0 `console.error`。
- **不跳过**：新增 `skip`/`xfail` 一律禁止。确实无法自动化的（如需真人过验证码）写成独立手工核对项并在汇报中标注"手工"，而不是 skip。
- **该废弃就废弃**：行为已删除/已改名的用例必须删除，不得改成恒真断言；删除原因写进提交信息。
- **该统一就统一**：同一约束只允许一处断言；字符串 grep 与浏览器断言重复时保留浏览器断言。
- **禁止字符串冒充交互**：`assert "function cfgFoldAll" in src` 只能证明代码存在，不能证明按钮可用。交互类缺陷必须有 Playwright 行为断言（真实 `mouse.click`/`keyboard.press` + 几何/状态断言）。
- **必须有负控**：每个新门禁都要证明它能抓到旧缺陷（临时还原旧行为 → 断言必须失败 → 再恢复）。
- 测试不得污染真实 `config.yaml`、`data/prices.db`、`user_data/`；用临时目录 + monkeypatch。

**写这类门禁的三条纪律**（都是踩过才写的）：
1. **必须做负控**：故意改错文档 → 断言必须红 → 还原。没有负控的绿是空转。

3. **允许「已标注未实现」的例外**：设计文档里的接口提案可以保留，但必须写明「未按此名实现」，门禁据此放行。

## 9. 验收矩阵与证据

### 9.1 视口与主题

- 宽度：320 / 390 / 768 / 1024 / 1280 / 1360 / 1512 / 1920。
- 主题：亮 / 暗 / 自动（跟随系统）。
- 缩放：100% / 125% / 200%（真实浏览器缩放，不用 `device_scale_factor` 冒充）。
  - **现状**：`docs/uitest.py` 目前只做多档 `set_viewport_size`，**没有缩放档的自动化用例**。
    这一项属于"发布前手工核对 / 待补自动化"，不得在汇报里写成"已由门禁覆盖"。
  - 手工核对的判据仍是硬性的：缩放后不得出现文字裁切、按钮重叠、横向溢出、表格与表头错列。
- 每组合至少覆盖：概览、检索（收/展）、特价雷达、航线走势、航班走势、明细（滚动）、渠道健康、配置（三分区 + 展开/收起）。

### 9.2 交互流程

展开/收起三轮 → 切页返回 → 筛选变化 → 刷新 → 缩放，状态仍正确；`aria-expanded` 与视觉一致。

### 9.3 渠道 × 国内/国际矩阵

| 项 | 必须写明 |
| --- | --- |
| 原站查询条件 | 航线、日期、渠道、舱位、行程类型 |
| **域** | **国内 / 国际**（同一渠道两端入口与登录墙不同，必须分行记录——r415 的分域统计就来自这里，合记会掩盖"哪一端坏了"） |
| 原站结果 | 有票 / 无票 / 需登录 / 风控 |
| 会话验证 | 已保存 / 验证有效 / 明细成功（三态分开） |
| 程序请求 | 状态码、路径（PC/H5/API）、耗时 |
| 明细数量 | 真实明细行数 |
| 日历价数量 | 单独统计，不算明细 |
| 证据位置 | 文件路径 / 截图名 |
| 结论 | 通过 / 边界 / 缺陷 |

合计 ≥ 30 组合（国内 ≥ 20，国际 ≥ 8，途牛国际 ≥ 2 允许真实无结果）。
统计口径：**组合按「渠道 × 域 × 航线」计**，同一个渠道的国内与国际是两条记录。

### 9.4 证据规范

- 截图命名：`页面_视口_主题_状态_日期.png`；关键缺陷附"修复前 / 修复后"两张。
- 几何证据贴数值（rect、差值），不要只说"已对齐"。
- 像素证据贴采样坐标与颜色。
- 性能证据：同机、同视口、同数据规模的前后对比（P50/P95、长任务、请求次数）。

### 9.5 禁止

- 用空集合断言（`for ...: pass`）当通过。
- 直接调用内部函数替代真实点击。
- 只看接口 200 判定交互通过。
- 把"代码里有这行"当作"用户可以看到"。
