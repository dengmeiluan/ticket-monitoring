# 第一部分：最新状态解释版

## 1. 产品与架构

产品是自托管的多渠道机票价格监控台：采集携程、去哪儿、飞猪、同程、途牛的航班与价格，支持国内和国际航线，提供用户级关注、特价雷达、走势、航班历史、钉钉推送和达标提醒。数据留在本机，配置在网页完成。

技术形态：

- 单文件 Python SPA `webui.py`，通过 `http.server` 在 8765 提供服务。
- SQLite `data/prices.db` 保存价格与航班历史；`data/flight_watch.json` 保存用户关注航班。
- Playwright Chromium profiles 位于 `user_data/`，承载各渠道登录态。
- 后台扫描轮次由 `main.py` 驱动；实时探针由任务系统执行，支持任务快照、逐渠道阶段、增量结果、取消和失败重试。
- `core/special_radar.py` 聚合五大官方特价来源；`crawlers/*.py` 负责各渠道采集与解析。
- 公开面包括 GitHub Repository、Release、Pages 站点、README/EN 和四平台发行包。

## 2. 用户级 IA 与页面职责

全站以“用户”为配置和观察主体，不把关注对象做成脱离用户的全局列表。

- 配置页中，每个用户卡片内同时承载关注航线、关注航班、特价雷达和监控参数。
- 关注航班在用户卡内联展开，不弹层、不跳转；修改后直接保存回读。
- 特价雷达属于用户，但它的数据来自官方渠道特价，不从用户关注航线推导。
- 监控台的 tab：概览、特价雷达、关注航线走势、关注航班走势、关注航班明细、渠道健康。
- 单用户也常显“用户视图”chip；多用户提供用户切换，切换后列表、计数、走势和关注筛选必须属于当前用户。
- 检索页和配置页共享用户上下文，但查询草稿、已提交任务和结果筛选保持隔离。

页面职责：

- 概览：整体状态、监控对象摘要、关键走势和异常入口。
- 实时检索：临时查询、组合探针、结果筛选、同班比价、详情和溯源。
- 明细列表：已采集/已返回记录的筛选、对比、详情和关注操作。
- 关注航线：航线级集合、日期范围、走势和历史。
- 关注航班：航线明细集合中的航班子集、价格观察和渠道差异。
- 监控配置：用户、航线、关注航班、雷达、渠道、目标价、提醒和启停。
- 渠道登录：六槽位登录与状态验证。
- 渠道健康：采集轮次、渠道状态、登录/验证/失败证据和处理入口。

## 3. 关注航线与关注航班语义

关注航线是“出发地 + 到达地 + 日期或日期范围 + 适用筛选条件”的航班集合。

关注航班是上述航线及日期对应明细集合中的子集，按航班身份和适用条件筛选得到。它不是独立重复实体，也不为每个渠道各自维护一套不一致的数据。

已确立的口径：

- 航线采集保存实际取得的航班维度历史，不依赖用户先关注某个航班。
- 用户后关注时，可以读取此前已经采集到的真实历史；不存在的历史不得补造。
- 航班身份需要区分日期、机场、航班号、共享/实际承运、中转结构、跨日、时区和舱位等维度；不能只凭航班号或页面文本合并。
- 详情页提供“只看关注”，按当前用户关注清单过滤本轮真实明细；切换用户自动复位。
- 关注航线和关注航班的数据关系必须可解释、可追溯，不能出现同一对象在配置、监控、检索和走势中身份不一致。

## 4. 特价雷达语义

特价雷达是“官方渠道特价机票/低价日历/低价榜”的聚合，不是用户关注航线的衍生视图。

当前五个官方来源：

- 携程：单航线低价日历 + 全国榜。
- 去哪儿：官方 H5 特价深链；页面自身生成请求签名；使用已保存会话读取真实响应；风控失败有冷却。
- 飞猪：单航线 `cheapestCalendar`（含税，7 天窗口）；软拒时回退国内出发榜并冷却。
- 同程：`queryCalendarLowestPrice`（免登录/免签名，国际 90 天、国内 180 天）。
- 途牛：国内官方 H5 同源逐日日历（`type=1`，裸价不含税）；国际没有官方日历时如实为空。

行为口径：

- 用户选择出发地、目的地、日期范围，可指定渠道；携程支持全国选项。
- 特价雷达页首屏是「特价监控」，不是每次打开都重查：每次官方日历/榜单结果写入 `radar_snapshots`，按用户/航线/范围保留逐日价与来源；控制台启动后约 90 秒做首次快照，之后每 2 小时刷新（扫描持锁时跳过）。
- 监控面展示逐日低价日历、监控时间轴、低价日相对上次的价差，以及该日已采集的真实航班；没有明细时明确说明日历价不能生成航班，并给该日探针入口。
- 查询条件收进可折叠区；同条件成功结果有短期缓存；失败和冷却原因必须如实显示。
- 日历价不能标成航班明细成功；国际某次无结果不能定义成渠道永久无能力。
- 演示模式与静态站使用明确标注的合成快照，保证监控面可浏览且不冒充真实报价。

## 5. 渠道、登录与数据真实性

渠道优先级：携程 > 去哪儿 > 飞猪 > 同程 > 途牛。该顺序用于故障处理、取数保障和资源分配；同班比价、最低价和达标判定仍按真实数据计算。

国内/国际能力矩阵：

| 渠道 | 国内 | 国际 |
| --- | --- | --- |
| 携程 | 必须取得真实明细 | 必须取得真实明细 |
| 去哪儿 | 必须取得真实明细 | 必须取得真实明细 |
| 飞猪 | 必须取得真实明细 | 必须取得真实明细 |
| 同程 | 必须取得真实明细 | 必须取得真实明细 |
| 途牛 | 必须取得真实明细 | 允许有证据的原站真实无结果；有明细时必须取得 |

口径：

- 日历最低价、缓存补位、真实航班明细是三种不同语义；日历价不能冒充可售航班，不能用其他渠道数据填补失败渠道，不能让过期或不可比数据参与达标和同班比价。
- 必须取得明细的渠道，如果只有日历价，应标记“仅日历参考价，明细未取得”，不能计入明细成功。
- 原站与程序对照要使用相同航线、日期、行程类型、乘客、舱位和登录身份；动态价格比较核对时间、币种、税费和舱位。
- 一次空结果不能证明整个渠道无能力；原站有票而程序没有属于待解决缺陷。
- 途牛国际只有在排除登录墙、验证码、超时、请求异常和解析失败后，才能归类为原站真实无结果。

登录槽位共六个：携程、去哪儿、同程、途牛各一个；飞猪 PC 与淘宝 H5 为独立 profile、独立会话和独立窗口，飞猪卡用「双端登录」弹层管理。

登录状态必须区分三件事：

1. 登录态已保存：持久化操作成功。
2. 会话验证有效：实际验证确认当前入口可用。
3. 本次明细采集成功：具体查询取得真实明细。

保存后显示“已保存，验证中”，验证完成自动更新；不能用超时、空结果或日历价反推登录失效。新登录态必须被下一次真实请求使用。

## 6. 实时探针与任务可观察性

实时探针支持多航线、多日期、多渠道组合，结果由真实后端任务驱动。

已确立的目标口径：

- 启动后立即出现任务摘要并自动展开执行详情；收起不停止任务，重新打开不重复提交。
- 按“任务 → 航线/日期 → 渠道”展示真实阶段、状态、耗时、结果类型/数量、重试次数和阻塞原因。
- 阶段来自真实事件：排队、检查会话、打开页面/发起请求、等待响应、接收数据、解析明细、标准化/去重、更新结果、完成。不同渠道可以有不同阶段，未发生或无法观察的步骤不能伪造。
- 禁止定时器生成的假日志、假进度、固定增长百分比和没有依据的预计完成时间；心跳只表示任务存活，不代表采集进展。
- 增量结果先到先展示；支持筛选、定位、详情、取消、断线重连和失败项单独重试。
- 取消必须传到后端；晚到响应不得污染新任务；成功结果保留。
- 事件支持按渠道、阶段、异常筛选，以及跟随最新/暂停跟随；用户上翻阅读时不强制拉回底部。
- 页面、日志和证据导出不得泄露 Cookie、Token、密码等凭据。
- 正常本机连接下，后端已产生的关键阶段、增量结果和状态变化以 2 秒内页面可见为目标；上游响应耗时单独记录。
- 每条探针结果行标注本次真实采集入口（PC / H5 / API），详情页给「采集入口」；历史轮次没有入口记录时明确标「未记录」，不从渠道名猜测。

## 6A 渠道健康诊断

- 渠道健康按最近一轮证据给每渠道一张诊断卡：正常、登录态失效、Cookie 已过期、需要人工验证、IP/频率风控、上游超时、抓取失败待核对。
- 诊断必须同时给证据摘要和可执行动作（重新登录/打开可见验证/停止重试等待冷却/查看该轮日志），不能只染色。
- 登录三态与轮次状态分开显示；1999 等响应必须先检查原站消息，明确“没有符合条件的航班”按空结果处理，不误报登录失效。
- 风控、验证码、登录和超时是不同分型；没有证据时标“待核对”，不武断归因。

## 7. 筛选、计数与空态

当前系统同时存在检索页筛选和明细列表筛选，目标语义如下：

- 查询上下文：用户、监控/探针模式、航线定义、草稿输入。
- 已提交任务快照：提交时的出发日期、请求渠道和实际发送给上游的条件；不能被展示筛选改写。
- 结果筛选：关键词、舱位、直飞/中转、只看达标、隐藏补位、只看关注等，只过滤已有结果。

必须遵守：

- 无明确深链或用户主动恢复快照时，首次进入使用中性条件：全部渠道、关键词空、“只看达标/隐藏补位”等限制开关关闭。
- 如果自动定位到有数据的航线或日期，必须明确告诉用户，不能同时宣称“当前展示全部日期与渠道”。
- 恢复旧条件时提示“已恢复上次筛选”并展示完整生效条件，提供一键重置。
- 生效条件始终可见；编辑器可收起，摘要不可隐藏；支持单项移除、按组清除和重置。
- 清除结果筛选不得改变已提交任务的日期或请求渠道；监控模式的日期筛选按自身规则处理。
- 计数区分：跨日期总量、所选日期量、筛选后可见量、唯一航班数、渠道报价数、本轮/历史记录。范围不同导致数量不等时明确标注。
- 空态分别表达：尚未采集、原站无票、请求失败、所选日期无数据、筛选无结果。筛选为空时列出生效限制和放宽动作。
- 切换用户、航线、日期、页面或模式时，清除不适用条件，关闭或重定位不匹配详情；旧响应不得覆盖新上下文。

## 8. 走势与历史

走势分三层：

- 航线走势：展示集合层面的统计，例如符合条件的最低价、价格区间或渠道比较。
- 航班走势：展示指定航班实例的价格观察和渠道差异。
- 概览走势：简化操作，但指标含义、配色、价格口径和详细页一致。

共同要求：

- 共享基础图表组件、时间轴、价格轴、图例、渠道配色、tooltip、时间范围、缩放/重置、渠道开关、原始明细入口和来源跳转。
- 每条曲线必须能说明对象是航线还是航班、横轴是采集时间还是出发日期、价格是票面价/含税总价/未确认口径、是否受渠道/舱位/直飞/中转影响、是否存在缺口/失败/过期。
- 不得补零、无依据插值或用历史最低价替代真实观察。
- 从概览进入完整走势时，保留关注对象、时间范围和必要筛选条件。
- 告警、UI 达标标记和走势目标线使用同一价格口径，或在界面明确标注差异。

## 9. 官方图标与资源

- 渠道和航空公司优先使用可核验的官方品牌资源；全站映射一致。
- 区分渠道/航司 Logo、制造商 Logo、具体机型图/官方示意图/剪影；制造商 Logo 不能冒充具体机型图。
- 找不到可核验官方素材时使用明确标注的示意或通用图标，不生成近似官方图，不宣称无法证明的精度。
- 资源记录来源、用途、核验日期和本地标识；随项目/发行包交付，运行时离线可用。
- 统一尺寸、比例、留白、清晰度、缓存和加载失败回退；图标与文字基线协调，不拉伸、不裁切、不遮字。
- 图标加载不得造成首屏卡顿或布局跳动。

## 10. 当前边界（必须如实表达）

- 途牛国际没有官方低价日历时，雷达返回空是真实边界；这不等于途牛国际航班明细永久不可用。
- 携程 H5 官方列表在部分航线返回 30212“当前查询无结果”时，明细主路径仍以 PC 列表为准。
- 去哪儿特价深链的签名由页面自身生成；不逆向签名，只用已保存会话读取真实响应。
- 飞猪可能出现 65B 软拒或限流；回退国内榜和冷却必须如实标注。
- 同程列表接口存在签名/环境要求；日历接口与列表接口能力不同，不能互相冒充。
- 登录态存在不等于会话有效，会话有效不等于本次明细成功。
- 不绕过验证码、滑块或风控；只做识别、可见窗口、人工接管和诚实失败归类。

# 第二部分：最终目标要求版

## 12. 全项目 UI、布局与交互质量

覆盖概览、实时检索、明细列表、关注航线、关注航班、关注航线走势、关注航班走势、关注航班明细、监控配置、渠道登录、健康状态，以及所有弹窗、抽屉、浮层、下拉、日期面板、提示、折叠区域和图表 tooltip。

必须覆盖：

- 首次进入、刷新、切页、返回、深链进入、从其他页面跳入。
- 加载中、无数据、有数据、错误、部分成功、历史数据、过期数据。
- 长文案、多标签、大数字、多渠道、多日期、大数据量。
- 展开、收起、再次展开、窗口缩放、移动端重排。
- 亮色、暗色、自动主题；100%、125%、200% 缩放。

要求：

- 任何元素之间不得出现非预期遮挡、文字挤压、按钮错位、图标压字、内容越界、弹层定位错误。
- 短字段、短选项、日期、开关、普通按钮使用合理紧凑宽度；城市、路径、搜索和长表达式保留必要空间；禁止所有输入机械等宽或铺满整行。
- 同组按钮统一高度、间距、基线；文案变化、错误提示、保存中/验证中状态不得导致整组操作错位。
- 出发/到达、起飞/降落、价格/税费等成对信息使用稳定列结构和阅读顺序；时间、数字、单位、标签对齐规则一致。
- 弹窗、浮层、下拉贴合触发元素，具备边界避让、合理滚动、正确层级和焦点返回；滚动、缩放和窗口变化后不脱离锚点。
- 吸顶栏、固定底栏不得遮住标题、表单、按钮、当前焦点或列表最后一项。
- 检索页按“查询与任务入口 → 当前执行反馈 → 结果筛选与列表/详情”组织；折叠后必须真正减少高度，不能保留空壳、min-height 或大留白。
- 日历价带全部未采时，收敛为日期范围 + 未采说明 + 查询入口；有数据时保留可比较价值。
- 采用克制、清晰的扁平化设计，减少厚重边框、重复阴影、过多圆角和层层套卡片；用间距、对齐、字号、字重、背景层次和必要分隔建立层级。
- 同一语义使用统一组件和样式；不同语义明确区分。统一按钮、输入、选择器、标签、图标、表格、列表、图表、弹窗的尺寸与状态。
- 正文和常用控件以清晰可读为起点，辅助信息不得过小；不靠缩小字体、降低对比度、隐藏关键内容或裁切文字解决拥挤。
- 状态不能只靠颜色区分，必须有文案或图形辅助。
- 动态文案不能破坏同组动作区对齐；短/长说明、错误、保存中、验证中切换后，同一行按钮仍保持基线/底边对齐。
- 复合输入（城市、机场、日期等）的输入区与尾部触发区共享外层轮廓、底色和状态视觉；触发区可点击、可聚焦，输入文字不被遮挡。
- 健康页的渠道行使用稳定的名称区、时间轨道区和指标区；长计数、百分比、未知状态和处理入口不得互相覆盖；不同口径指标分别标注。
- 不得用 `overflow:hidden` 掩盖溢出；确需省略时提供桌面和触屏都可访问的完整信息。

## 13. 页面进入、状态恢复与折叠能力

- 首次进入、刷新、返回、深链、从关注航班进入配置时，必须自动加载正确对象的数据，不能依赖额外点击或刷新。
- 检查路由参数、选中对象、初始化依赖、请求触发、缓存键、状态恢复和异步竞态；旧响应不得覆盖新页面、新用户或新筛选。
- 加载中、真实空结果、筛选后为空、无配置对象、请求失败、过期缓存必须分别表达；请求失败要结束等待并给出恢复方式。
- 折叠区域连续展开/收起至少三轮；切页返回、筛选变化、刷新、缩放后仍可操作；多个同类组件互不干扰；文案、图标、内容、aria 状态同步。
- 收起不停止任务；重新打开进度不重复提交；刷新/断线后能按任务标识恢复观察。
- 不能用“第一次展开成功”证明组件能力恢复。

## 14. 关注航线 / 关注航班与走势

- 关注航线：出发地、到达地、出行日期或日期范围，以及相关筛选条件下的航班集合。
- 关注航班：上述航线及日期对应明细集合中的指定航班子集，必须真实继承父航线适用条件，不能只是声明上的子集。
- 关注航班数据来自航线检索和采集得到的明细；不得为每个渠道重复构造互不一致的数据逻辑；不得要求用户先配置具体航班才开始保存该航班历史。
- 必须正确处理同一航班号不同日期、城市与机场、共享/实际承运、多航段、跨日、时区和渠道表达差异；不能只凭航班号或页面文本合并。
- 只看关注的匹配必须覆盖与关注定义相关的身份维度；切换用户、刷新、重新采集后，集合必须与当前用户有效关注一致；过期、停用、越界关注不得继续命中。
- 航线、航班和概览走势共享基础组件、视觉规范和通用交互；保留集合统计与具体航班观察的业务差异。
- 概览走势可简化操作，但指标含义、配色、价格口径与详细页一致；从概览进入完整走势时保留对象、时间范围和必要筛选。
- 每条曲线必须说明对象、横轴、价格口径、受哪些条件影响、是否存在缺口/失败/过期；不得补零、无依据插值或用历史最低价替代真实观察。
- 告警、UI 达标标记和走势目标线必须同口径，或在界面明确标注差异及原因。

## 15. 检索与明细筛选统一

先建立筛选能力矩阵，明确：公共筛选、页面专属筛选、有数据但未开放、缺少可靠数据暂不支持、名称相同但语义不同的筛选。

至少评估：航线/机场、日期/日期范围、渠道、航空公司、航班号、起飞/到达时间段、直飞/中转/经停/时长、舱位、价格/价格口径、数据新鲜度/真实明细类型、关注状态/监控状态。

要求：

- 公共筛选统一名称、选项、默认值、组合规则、空值处理、执行结果和计数；专属筛选保留明确业务意义。
- 实时检索和明细列表面对同一份数据、同一组公共条件时结果一致；图表/概览继承条件时明确展示作用范围。
- 首次进入默认值合理，不继承不兼容的历史筛选、旧日期、旧渠道或旧草稿；自动定位到有数据航线/日期时必须明确说明，不能同时宣称“全部日期与渠道”。
- 恢复历史条件时提示“已恢复上次筛选”并展示完整生效条件，提供一键重置。
- 已选条件始终可见，支持单项移除、按组清除、重置；编辑器可收起，生效摘要不可隐藏。
- 展示筛选前后数量；零结果区分筛选无匹配、尚未取得数据、原站无票、采集异常。
- 切换航线、日期、页面、用户时正确处理失效条件，关闭或重定位不匹配详情。
- 查询上下文、已提交任务快照、结果筛选隔离：修改探针草稿不改变当前结果/日期带/镜像/结果筛选；清除结果筛选不改任务日期/请求渠道。
- 每个筛选必须用真实数据验证结果集合变化；组合、重置、跨页公共条件一致性都要验证。
- 持久化必须覆盖所有影响结果的开关；刷新/返回后不能出现界面状态与实际筛选不一致。
- 计数区分跨日期总量、所选日期量、筛选后可见量、唯一航班、渠道报价、本轮/历史；不得把跨日期总量说成所选日期量。

## 16. 官方图标与性能

图标：

- 建立渠道、航空公司、制造商、机型资源清单；有可核验官方资源时优先使用，记录来源、用途、核验日期和本地标识。
- 区分品牌 Logo、制造商 Logo、具体机型图/官方示意/剪影；制造商 Logo 不能冒充机型图，不能生成近似官方图。
- 全站统一映射、身份解析、资源选择、渲染和缺失回退；核对销售航司与实际承运航司，避免代码共享串用。
- 统一尺寸、比例、留白、清晰度、缓存和加载失败回退；图标与文字基线协调，不拉伸、不裁切、不遮字、不挤压。
- 资源随项目/发行包交付，运行时离线可用；避免每行请求第三方图片、重复 Base64 拼接和重复解码；加载不得造成首屏卡顿或布局跳动。

性能：

- 先记录基线，再定位，再优化，再用同一条件复测；固定机器、浏览器、视口、数据规模和网络条件，区分冷启动与再次进入。
- 分层测量后端、传输、归一化/筛选/排序、DOM、样式/布局/绘制、图表、图标、轮询。
- 覆盖首次进入、再次进入、输入联想、连续搜索、切换用户/航线/日期/渠道、筛选、排序、详情、加载更多、滚动、图表、后台轮询和探针全流程。
- 目标：页面切换、查询提交、取消等反馈不超过 100ms；本地常规筛选/排序/切换/详情到下一次有效绘制 P95 不超过 200ms；持续输入和滚动无明显停顿；无监听器/定时器/DOM/图表/资源泄漏。
- 记录首屏可用时间、P50/P95、长任务、请求次数和流量；不能只报单次最快值。
- 优化必须保留正确性与完整性；不能靠丢结果、隐藏字段、减少渠道、停止必要刷新或缩小字体变快。
- 分页常量、304、缓存函数或移除阴影本身不能作为性能通过证据；必须提供同场景前后对比。
- 已知性能债（需重新确认是否仍影响目标路径）：health/pulse/config 的 ETag 不完整、长列表无虚拟化、4× CPU 下恢复较慢。没有证据不要引入复杂架构。

## 17. 渠道、探针与登录闭环

渠道：

- 国内五渠道、国际前四渠道必须取得经原站对照的真实明细；途牛国际按有证据的原站真实无结果单独归类。
- 日历价、缓存补位和真实明细严格区分；飞猪、同程国内/国际不得用日历价充当明细通过。
- 原站与程序使用相同条件，记录核验时间；动态价格比较核对时间、币种、税费、舱位。
- 代码共享、实际承运、往返/联程、机场、时区和跨日必须正确处理。

探针：

- 多航线、多日期、多渠道组合；提交前展示组合总量；执行中逐组合显示状态和结果量。
- 单项失败不覆盖其他结果；保留合理并发、冷却、取消和请求去重。
- 任务摘要、阶段、增量、取消、重连、失败重试和事件筛选按第 6 节执行。
- 收起/展开不重复提交；刷新/断线不丢失任务；服务重启导致中断时如实标记。

登录：

- 六槽位状态统一来源；保存、验证、明细成功三态分开并跨页同步。
- 新登录态被下一次真实请求使用；旧任务需要重试时提供入口。
- 登录卡在长说明、错误、二维码/验证码、保存中、验证中、失效和窄屏下按钮对齐、可见、可操作。
- 飞猪 PC/H5、同程、途牛国内/国际分别验证；不能用一次空结果反推登录失效。
- 不绕过验证码；只做识别、可见窗口、人工接管和诚实失败归类。

## 18. 多 Agent 协作与实施纪律

主控统一目标、依赖、验收、写入归属和最终集成。至少安排以下专项职责，目标同时开展不少于 8 路审计；槽位不足时按上限分批覆盖并如实说明：

1. 产品心智、页面职责、用户级 IA 与跨页闭环。
2. 首屏初始化、登录态同步、共享状态、缓存与异步竞态。
3. 全站视觉、扁平化、字体、控件尺寸与主题。
4. 遮挡、弹层、对齐、响应式、可访问性与缩放。
5. 携程真实取数、字段校验与原站对照。
6. 去哪儿 H5、登录态与溯源。
7. 飞猪/同程真实明细、途牛国内/国际边界及原站对照。
8. 关注航线/关注航班、航班历史、走势口径与提醒。
9. 实时探针阶段事件、增量结果、恢复/取消、性能与浏览器回归。
10. 筛选矩阵、查询/结果隔离、计数与空态。
11. 官方图标资源、映射、回退与包体完整性。
12. GitHub、文档、截图、发行与部署一致性。

审计可并发；共享文件、8765 服务、浏览器会话、数据库和发行操作必须明确所有权。`webui.py` 指定唯一集成人，禁止多个 agent 无协调修改同一核心文件。

每条发现包含：问题、用户影响、复现条件、页面/视口、证据、修复方案、验收方式、复验结果。对真实缺陷补充行为/数据/布局回归，不能主要靠源码字符串、CSS token、DOM 数量或测试计数宣称完成。

执行顺序：基线复现 → 核心正确性与性能阻塞 → 数据与监控闭环 → 全站设计和资源统一 → 浏览器全流程复验 → 文档截图 → 冻结交付 → 发布及远端复验（仅在授权后）。

## 19. 真实验收

确认 8765 运行的是本轮最终代码，记录版本、进程、启动目录和源码来源。其他端口、静态 mock 或演示站不能替代。

### 19.1 渠道与数据矩阵

- 国内：至少两条热门航线 × 两个有效未来日期 × 五渠道，合计至少 20 个组合；五渠道都必须有经原站对照的真实明细成功证据。
- 国际：至少一条代表性国际航线 × 两个有效未来日期 × 携程/去哪儿/飞猪/同程，合计至少 8 个组合；四渠道都必须有经原站对照的真实明细成功证据。
- 途牛国际：同条件核验两个有效未来日期，允许有证据的原站真实无结果；若原站有明细，程序也必须取得。
- 合计至少 30 个组合；九个“渠道 × 国内/国际”能力单元各至少一组成功证据；失败样本和无票样本必须保留分析。
- 仅日历价不能作为必须有明细渠道的成功证据；一次空结果不能证明渠道无能力；原站有票而程序没有属于待解决缺陷。

### 19.2 完整用户路径

城市联想 → 多组合查询 → 自动展开真实阶段进度 → 首个渠道增量结果出现 → 筛选排序 → 同班比价 → 详情/原始证据/原页 → 最终一致汇总 → 历史 → 加入监控 → 编辑配置 → 保存回读 → 查看监控状态与走势。

额外验证：

- 从配置页空白创建监控，无需经过检索。
- 首次进入配置，关注数据无需点击自动显示。
- 慢响应、失败恢复、乱序请求、用户切换不串数据。
- 未关注航班先采集，后关注仍能读取既有历史。
- 修改配置后跨页同步；快速切换、反复进入、后台刷新不丢输入、不抢焦点。
- 提醒启停、目标判定与重复提醒抑制。
- 单渠道文案/阶段/计数正确；多渠道快慢不同仍及时显示部分结果。
- 展开、收起、返回任务不重新采集；刷新、断线重连能恢复观察。
- 排队、超时、需要用户操作、取消中、已取消、部分失败状态真实。
- 取消传到后端；晚到响应不污染新任务；成功结果保留；失败组合可单独重试。
- 飞猪/同程新登录态被下一次真实请求使用；已保存、验证有效、明细成功分开显示并跨页同步。
- 飞猪国内/国际、同程国内/国际不得用日历价充当明细通过。
- 途牛国内有明细正例；途牛国际原站无结果与程序失败分开归类。
- 长文案和错误状态下的登录弹窗按钮对齐、可见、可操作。
- 多轮探针和实时面板不造成监听器、定时器、DOM 或资源泄漏。
- 关注航班真实继承父航线适用筛选；只看关注不会把不同舱位/时间/中转/跨日的对象混为一谈。
- 检索与明细在相同公共筛选下结果一致；计数和空态可解释。

### 19.3 浏览器与视觉

- 覆盖亮/暗/自动主题，至少 1920、1512、1360、1280、1024、768、390、320 宽度，补测实际出问题的断点。
- 覆盖 100%、125%、200% 缩放；检查文字、图标、图表清晰度、重排和主要动作可达。不能用 device_scale_factor 冒充浏览器缩放。
- 真实打开所有重要弹层、下拉、日期选择、详情和图表 tooltip，滚到页面和弹层底部，确认最后一项与操作按钮可见、可点、可达。
- 自动几何检查与肉眼截图结合，验证最终生效样式，不只检查某段 CSS。
- 截图注明页面、视口、主题、缩放、状态和数据条件；区分真实遮挡与整页截图滚动位置造成的伪影。
- 禁止用空集合断言、直接调用内部函数代替真实点击、只看接口成功判定交互通过。

### 19.4 回归命令

## 20. 最终公开形态：单一初始化提交、单一首发

公开交付采用“单一初始化提交 + 单一首发形态”，这是本项目的最终要求。开发过程中的工作提交只属于过程历史，交付前必须收敛，不得把开发流水账暴露为公开历史。

最终公开形态必须同时满足：

- 一个包含当前完整交付内容的初始化提交。
- 一个正式 Release。
- 一个有效的当前公开部署。
- 一套唯一的当前发行资产（四平台 zip + `SHA256SUMS.txt`）。
- 一套统一、完整、符合首次项目介绍定位的中英文文案与截图。

发布流程：

1. **冻结**并发写入，确认 `webui.py`、后端、测试、文档为同一一致状态；不在移动的工作区构建。
2. **验收**：全量 pytest、UI 门禁、真实 8765 验收、渠道矩阵和必要性能测量全部通过。
3. **备份**：在仓库外保存可恢复的完整 Git 历史、未提交工作和必要审计证据，并验证恢复能力；备份不得进入公开仓库和发行包。

5. **版本与材料**：版本号在全部门禁通过后提升；更新 `main.py`、版本门禁、`docs/release-notes-v<version>.md`、README/EN 计数、截图和站点。中英文 README、Release 与站点保留完整首次介绍，统一章节、截图、功能事实、安装入口和能力边界；公开材料不堆叠内部轮次、重复 release 说明和开发流水账。

8. **更新唯一 Release**：使用规范中文介绍 + 当前版本/验证统计/源码 SHA/SHA256；保持 `v1.0` 为常量 tag，最后把它移到已验证的初始化提交 SHA，并确认 tag 上的 `main.py` 携带当前版本。
