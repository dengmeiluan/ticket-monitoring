## 渠道矩阵口径更正（2026-11-02）

能力矩阵的三态改成**采集端事实**，而不是「渠道有没有这个产品」：

- `✓` 已验证出数；`×` 渠道无此能力或已停服；`?` 产品支持但采集端未实现，或当前风控未出数。图例、卡头说明和每格悬停统一按这套口径，悬停会写清「下一步做什么」。
- **去哪儿 App 的「低价机票 / 日历」从 `×` 更正为 `✓`**：登录后点「搜索低价机票」落的是原生 RN 页（`QReactNativeActivity1`），不是 H5 WebView；真机北京→上海 14 天逐日价 ¥408/359/…（41.2s，`low-fare ok`）。点「日历」后整月（2026-11 → 2027-01，约 60 天）每天都有 ¥ 价，采集端按 `q_flight_calendarDayItem#YYYY-MM-DD` 日格子树解析，并单独写 `日历/calendar` 账本证据；H5 WebView 只保留为异常转场兜底。特价雷达的该渠道发现源随之恢复。
- **同程国内往返接通**：同程自己的 `book1/roundtrips` 接口直接给出组合总价 `atp`（2026-11-02 真报文 210/210 条满足 `atp = lp + atpd`），裸 httpx 可取，不需要页面签名；采集端只搬运接口的 `atp`，绝不把两段单程相加。矩阵同程往返由 `?` 升 `y`（国内已验证；国际往返仍需页面两步流，卡点写在悬停里）。
- **去哪儿 App 低价雷达日期带对齐**：低价页日期带从今天起 14 天。此前雷达把请求区间长度当 `days`，11-10..11-12 实际只抓今天起 3 天，过滤后成了无理由空结果（线上 176s / empty / 0 天）。现在按今天到区间末日请求，超出日期带或返回带未覆盖都写明原因；线上同一请求 111.6s / ok / 3 行（11-10 ¥260、11-11 ¥269…）。
- **携程往返接通**：PC `online/list/round-…&containstax=1` 直接给产品往返总价（国际写「往返含税价」、国内写「往返总价」；2026-11-02 真跑 上海→东京 6 条 ¥2404…¥2682、上海→北京 6 条 ¥1002…¥1049）。采集端只采渠道自己的组合总价，未做两段单程相加；H5 结果页仍只有去程，不走那条。矩阵携程往返升 `y`。
- **去哪儿（浏览器）往返接通（仅国内）**：touch 往返页的去程卡直接给产品「往返总价 ¥N 起」（2026-11-02 真跑 北京→上海 ¥808…¥2546，71 条）；返程卡的「补 ¥N」是加价，不落库；国际往返页未验证。矩阵去哪儿往返升 `y`，范围记「仅国内」。
- **全部渠道的多程**：渠道产品都有入口，采集端未实现，仍记 `?` 并逐格写明原因，不用 `×` 把「我们没做」画成「渠道没有」。
- **途牛日历仍为 `×`**：没有独立日历端点，按单日 `listFlight` 取数；不拿榜单或单日接口冒充日历。
- **同程 H5 国际入口改为已验证查询页**：`m.ly.com/ft/touch/index`，进入后在页内点「国际」页签；手拼 `tiflight/book1` 深链不再提供给用户，只保留为采集端数据通路。
- **跨线程登录态修复**：健康装饰层的重入标志改为按线程记账。此前后台线程把它置真时，请求线程会绕开可注入证据去读旧日志，「新拒绝结束待验证窗」会被误判。

## 交互：点了要有反应

- **无 body 的按钮全部打哑（已修）**：浏览器 `fetch(path,{method:'POST'})`
  不带 body 时会自动补 `Content-Type: text/plain`。13 个写端点（登录桥接
  5 个、人机验证 3 个、`/api/login*` 3 个、渠道自检/验证/预热、节流解封、
  特价雷达、关注增删）各自抄了一段「不是 application/json 就 415」，于是
  「立即扫描 / 打开文件夹 / 测试弹窗 / 重启 / 立即核验」这些无参按钮全部
  点不动。现在判据收成一处：**只有带 body 才要求 JSON**；跨站请求照旧由
  同源闸门拦下，安全边界不变。
- **「全部收齐」在渠道登录页只改了按钮字**：点下去按钮翻成「全部展开」、
  `aria-expanded` 写成 false，但面板高 1151→1151、可见元素 308→308 ——
  一个像素都没收。该页两张卡的卡头是 `.uhead`，不在收齐逻辑认识的任何
  一类里，循环压根没枚举到。修后 1151→146、可见元素 308→17，卡头仍在，
  再点一次完全恢复，切走标签页再回来保持收齐。

## App 渠道：两个 App 的往返都成为真实能力

- **智行 App「往返」跑通（真机 2026-10-31）**：北京⇄上海点「往返」→「机票查询」，
  页面是去程/返程双列，**往返总价只在左列**；右列的 `¥0 / ¥26` 是返程加价，
  当票价会产出 0 元假数据。解析器按「时刻与价格同一张卡片」的 y 窗口对齐，
  并把「临近推荐」（火车接驳 `¥704 起`）整段排除。门禁
  `tests/test_r700_zhixing_round_trip.py`（5 条）。
- **去哪儿 App「往返」也跑通（真机 2026-10-31）**：单程/往返/多程三档，
  选「往返」后出现返程日期位，结果页左右两列 + 页脚「往返价格」总额。
  页脚只报当前选中对的总价，所以逐张去程点过去、每张读一次真实总额，
  不靠两段相加编价格。门禁 `tests/test_r701_qunar_round_trip.py`（7 条）。
- **对齐基准改为「浏览器端整体能力」**：此前按「同源友商」判缺口会自证——
  携程自己 `round_trip=n`，于是「智行 ↔ 携程」永远算不出往返缺口，而网页端
  飞猪/途牛明明支持。用户的要求是「PC/H5 拥有的能力 App 都要有」，基准因此
  改成任一浏览器渠道具备该维度。当前缺口：两个 App 的往返都已补齐；两家 App
  的低价机票也都已接入（智行「特价」逐天最低价，r732）。

## 稳定性与测试可移植

- **登录会话保活（回答「配置完过一会又要登录」）**：正常保存配置/重启不会主动清 Cookie；线上 `qunar` 每轮 `need_login`、`tuniu` 偶发，是渠道侧登录墙/短命 Cookie，不是配置动作。本轮修了两处自身缺口：①恢复快照时按 `expires` 替换「已过期 / 更旧」的同名 Cookie，避免 profile 里的旧 Cookie 永远遮住新快照；②采集成功关闭时回写快照（沿用原 `saved_at`，不冒充重新登录），且只认真正的登录凭证 `AUTH_COOKIES`（携程 `cticket`、飞猪 `cookie2`、去哪儿 `QN1`），不拿 `_bfa`/`cna` 之类统计 Cookie 当判据。真实 qunar profile 验证：快照 mtime 刷新、`saved_at` 不变、`QN1` 仍在；新增 5 条测试。同程/途牛的 `AUTH_COOKIES` 仍待补，当前继续依赖 Chromium profile 持久 Cookie。
- **无航线自检不再 NameError（Linux 社区反馈）**：点「核验」时若配置里没有可用航线，`probe_channel` 的兜底分支用了只在别处导入的 `_dtm`，接口返回「核验失败：name '_dtm' is not defined」。导入已移进函数，并新增「无航线 → 用今天 SHA→NRT 兜底」的回归用例。
- **「测试红」曾是一种假象**：端点普查测试会真打 `/api/restart`，而该接口
  会拉起新实例并在 1 秒后 `os._exit(0)` —— 把 in-process 起的服务连同**整个
  pytest 进程**在 61% 处静默杀死，日志只剩一个 `F`、没有 traceback。现已
  排除该端点的同源真打，并断言「它仍在清单里」，不让守卫因此缩小范围。
- **两个夹具的模块级替身不再泄漏**：`test_r671` / `test_r672` 起服务前把
  `webui._bind_host` 换成回环替身却不还原，导致后面的容器监听地址用例
  全红（单跑全绿）。现在夹具退出（含异常路径）都会还原。
- **测试不再依赖跑测机器**：CI 安装中文字体后再跑渲染度量；`has_cjk_font()`
  改为真的检查字体有没有汉字（此前 DejaVu 回退被当成「有中文字体」，
  在 CI 上跑出与真实中文排版不同的像素断言）。
- **登录窗口类用例与「有没有桌面」解耦**：无图形环境下的短路保护仍在，
  但默认按有桌面跑，窗口逻辑本身由替身校验——这类红此前只在 CI 出现。
