## [v1.7.2] - 2026-11-15

**安全：升级包解压只走一个安全入口（社区 PR #17）**

> 感谢 [@Shengcun-Scanner](https://github.com/Shengcun-Scanner)（Roni Saguey）报告并提交
> 修复：升级包解压可能写到缓存目录之外。

## 报告说的和实测的

报告指出 `core/update.py::apply()` 用 `z.extractall(tmp)` 解开**从 release 下载的升级包**，
成员名由发布方决定，于是 `../x` 或 `/x` 能写到缓存目录外。按"先量再改"的规矩，我们先实测
（Python 3.11 / Windows）：

| 成员名 | 落盘位置 | 结论 |
|---|---|---|
| `../escaped.txt` | `cache/escaped.txt` | **没逃逸**：CPython 的 `_extract_member` 会去掉 `..` |
| `/abs.txt` | `cache/abs.txt` | 没逃逸：前导分隔符被去掉 |
| `C:/evil.txt` | `cache/evil.txt` | 没逃逸：盘符被去掉 |
| `link -> /outside` + `link/pwned.txt` | 平台相关 | **真向量**：`extractall` 不管软链 |

也就是说方向是对的，但**现代 CPython 已把 `..`/绝对路径关进来**；真正能逃出去的是
**符号链接穿透**——而本项目正好发行 Linux/macOS 包（`os.symlink` 无需特权），必须堵死。

## 我们做了什么（在报告基础上加固）

- 新增 `core/safezip.py`：**唯一**解压入口 `safe_extract()`，先全量校验再落盘
  （任一成员不安全 → 一个字节都不写）；拒绝空名 / 绝对路径 / 盘符 / UNC /
  任何 `..` 分量 / 解析后越界 / **符号链接** / fifo / 设备节点；目标处已有软链也不顺着写；
  成员数上限 20 万，解压后体积上限可选（默认不限，避免误伤正常大包）。
- `core/update.py::apply()` 接入它；保留薄别名 `_safe_extract()`，**贡献者自带的 5 条测试
  原样继续跑通**（署名保留在提交里）。
- 新增门禁 `tests/test_r1903_safezip_matrix.py`（19 条）：7 类越界名、软链成员、
  fifo、软链穿透（POSIX）、目标已有软链（POSIX）、正常包仍可解、成员/体积上限、
  **全仓不许再出现裸 `extractall(`**（AST 扫描）、安全文档单源。
- 安全文档收口：并入根 `SECURITY.md` 的「不可信输入」一节，**安全文档只保留这一份**。

## 升级

升级包完整性仍以 SHA256 + 备份回滚为准；解压防护是"包本身恶意"的兜底。
现有配置与数据无需改动。

## [v1.7.1] - 2026-11-14

**修 #16：App 渠道开通脚本的必崩 bug + 开通引导**

> 这一版只做一件事：把用户报的「app通道无法开启」修到底，并把「怎么开」写成能照着做的三步。

## 修了什么（issue #16）

`python scripts/setup_device.py` 在「adb 连不上、需要自动拉起模拟器」时**必崩**，
而且崩了两层：

1. `AttributeError: 'Namespace' object has no attribute 'mumu'`
   argparse 从未定义 `--mumu`，代码却用了它；
2. 修掉第 1 层后立刻露出第 2 层：`UnboundLocalError: ... 'time'`
   同一函数末尾有 `import time`，Python 因此把 `time` 当整个函数的局部名，
   而前面的 `time.sleep(5)` 先执行。

两处都在 `scripts/setup_device.py`，已修。

## 新增

- `--mumu`（MuMu 安装目录**或** `MuMuManager.exe` 均可，自动解析到 `nx_main\MuMuManager.exe`）
  与 `--vm`（多开实例序号）——装在非常规目录、多开实例不再是 0 号时不用改代码；
- adb 连不上时打印**四步核对**（实例在跑 / ADB 调试开 / adb 路径 / 端口），不再只说「重启试试」；
- `docs/APP_CHANNELS.md` 新增 **「开启 App 渠道（三步）」**：环境自检 →
  `setup_device.py --apply --reboot --enable-app-channels` → 配置页勾选，附 adb 四卡点与症状对照；
- `core.setup_check` 的提示从「想采就在 users[].platforms 里加上」换成**能直接粘的三条命令**；
- 门禁 `tests/test_local_import_shadowing.py`：AST 全仓扫描「函数内裸 import 遮蔽同名用法」
  （这类写法必然 `UnboundLocalError`）。全仓 1445 个 py 文件扫出 2 处，均已修；
- 门禁 `tests/test_r1886_app_channel_onboarding.py`：钉住引导里的可执行命令、手册小节与 `--mumu/--vm`。

## [v1.7.0] - 2026-11-12

**采集自愈、口径诚实与 App 渠道改造**

> 这一版的共同主题：**让"监控"这件事对自己也诚实**——进程死了有人拉起来、
> 界面不再承诺做不到的事、成功率不再把"我们主动不发"算成失败。

## 新增

- **看门狗 + 心跳**：`main.py` 每 30 秒原子写 `data/.heartbeat`；
  `tools/watchdog.py` 判定三态（心跳新鲜=ok / 陈旧但在=卡死先杀再起 / 不在=已退出直接起），
  事件写 `logs/watchdog.log`。实测：轮次进行中杀进程，看门狗 1 分钟内拉起。
- **App 日期视野预过滤**：日期超出某 App 渠道视野（默认 62 天，可按渠道配置）时，
  **规划阶段**就不派它——实测一天省掉 27 次"起来了才发现超窗"的白跑，
  浏览器通路照常接住（同一天入库 5 条价）。
- **采到即落库**：每个渠道完成即写库，不再等整条查询收齐。
  实测：轮次中途杀进程，已采的 12 行仍在库里（此前会整条查询丢失）。

## 修正（口径与诚实性）

- **三率分母**不再把「能力边界（unsupported）」与「我方主动跳过（paced/skipped）」
  算成失败：智行 App 34% → **81%**；页脚同时报出「另 N 条为能力边界/主动跳过，未计入分母」。
- **`paced` 不再记成 `error`**：节流/TTL 跳过曾经抬高错误率、拖低成功率。
- **App 闸门跳过记 `paced`**（不再是 `blocked`）：那是我们在等自己，不是站点在拦。
- **停手文案四处统一**：`停手 7d` / `剩 7 天` / `人工停手 7 天` 一个口径，
  后端日志也从「剩 10079 分钟」改成「剩 7 天」。
- **登录墙建议按渠道类型分口径**：App 说「在手机上打开「去哪儿 App」用手机号登录一次」，
  浏览器才说「去验证」；并且**上次成功之后没再撞墙就不再催重登**。
- **特价雷达不再假承诺**「每 2 小时自动」：没配置就写「自动刷新未启用」。
- **静默窗页头**写真实开跑时刻（如「07:00 开跑」），不再给假承诺。
- **超窗日期预过滤**的规划日志、停手/停服/未在清单等六个状态的口径统一
  落档在 `docs/HEALTH_STATES.md` 与 `docs/CHANNEL_PARKED.md`。

## 渠道现状（发布时）

- 浏览器 5 家（携程 / 飞猪 / 同程 / 途牛 / 去哪儿网页）：正常，携程与飞猪近 24h 100% 成功率。

## 2026-11-10 滚动修复（同版本号重建）

### 登录与核验（对应 issue #15）

- **核验一直不通过**（飞猪 PC 已登录仍提示需登录、携程登录不了）：核验时打开的
  本来就是登录页 `passport.*` / `/login`，而判定把 **URL 命中** 当成"需要登录"的证据，
  与是否已登录无关。现在槽位核验只按页面正文判断；未登录仍能正确识别。
- **核验成功却仍提示核验**：核验结果此前只在 H5 槽位生效，PC 槽位没有读取。
  现在卡片显示「核验于 HH:MM」；"页面可达但未出数"的按钮改为「再核验」并说明原因。
- 登录窗口不再重复弹/闪：同槽位的打开请求会排队，超时会把僵尸窗口关掉。

### 升级（新增能力）

- **不再需要卸载重装**：`python -m core.update --check / --download / --apply`
  或面板「检查更新 / 立即升级」一键完成（下载 → 备份 → 覆盖 → 失败回滚），
  完成后重启即可。**不会覆盖** `config.yaml`、`user_data`、`data`、`logs`。
- 面板常显当前版本，可随时手动检查更新（结果缓存 6 小时）。

- **智行 App**：整窗日历收割（一次 50–62 天有价）；日历限频 1 小时避免烧设备配额；

  国际航线拿不到价不再拖累其它航线（此前会触发 30 分钟熔断把国内也挡掉）。
- **携程 / 飞猪**：周历收割跨日期低价条（飞猪周历页无价已默认关闭）。

## 诚实性（本版主线）

- **「没票」必须有明确证据**：以往层层兜底的最后落点会写成「无票」，把请求失败、解析失败包装成业务空结论。现在 `empty` 只能由站点的明确无票证据支撑，其余一律记 `error` 并保留现场。
- **门拒不等于会话失效**：去哪儿「当前搜索无航线」等通道级门拒不再被当成真无票，也不再触发退避重试或提示重新登录；「该重登」和「该重试」分开。
- **携程国际、去哪儿 HTTP 回退**：请求无响应、未解析出内容时不再记成真无票。
- **有行无价**：解析出航班行但取不到价格时，不再因空序列抛异常留下「无证据的空」。
- **登录墙不冒充错误**：登录墙记 `login` 而不是 `error`，面板据此提示重新登录而不是重试。
- **证据不跨域**：一个日期/一条路径的判定不再污染另一个日期或另一条路径。
- **路径溯源**：路径账补上 `request_url`，出问题能直接点开复现，不靠截图猜。
- **历史行按证据改判**：早先记成「登录失败」的 1999/444 行，按实际证据改判为软拒，面板不再催重登完好的会话。
