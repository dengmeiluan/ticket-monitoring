# ticket-monitoring 初版 · 持续更新

> 自托管的多渠道机票价格监控：五平台明细采集 → 钉钉图文推送 → 达标四层强提醒。
> 国内航线与国际航线（五洲目的地）同一套采集-判定-推送链路。
> 数据留在本机，配置全在网页，开源免费。

**当前版本：v1.5.306 · 2026-10-30**（初版首发 2026-10-23）

本版主线是**把「装、登、验、发」四件事各自闭环**：镜像能直接拉、容器里配置
不会把服务锁回环、登录后能当场验证会话到底能不能用、邮件在无图形容器里也
能正常出图。App 渠道补齐统一基类契约，多日期采集不再把价格记到错日期名下。

## 部署：预构建镜像 + 容器内监听地址

- **预构建镜像已发布**：`ghcr.io/dengmeiluan/ticket-monitoring:latest`（另有
  `sha-<短哈希>` 溯源标签），公开可匿名拉取。`docker-compose.yml` 拉取优先，
  保留 `build: .` 本地构建兜底；工作流新增 `push_image` 开关，日常手动跑只
  构建+冒烟不推送。镜像 `linux/amd64`，内置 chromium 与中文字体。
- **容器内监听地址不再被写坏**：配置页此前按文件缺省回显 127.0.0.1，而容器
  实际绑 0.0.0.0；保存任意配置会把 127.0.0.1 写回 yaml，下次重启端口映射
  直接不可达（表现为「容器在跑但网页打不开」）。现在配置页与重启中心都报
  **实际生效值**，保存不再钉死回环。
- **邮件快照在 root 容器内可渲染**：Chromium 在 root 下必须带 `--no-sandbox`，
  此前邮件每次都降级成无图轻壳并刷失败。

## 登录：入口实测可用 + 当场可验证

- **登录入口按实测重选**：`www.tuniu.com` 在采集同款移动指纹下是 WAF 拦截页、
  `www.ctrip.com` 是 App 式首页（都没有登录控件）。两者改到实测可直接出
  登录表单的 passport 页，爬虫与登录卡读同一个常量，不再一处改一处漏。
- **所有槽位都能「立即核验」**：此前只有飞猪 H5 有核验。现在核验跑一条
  **真实查询**——出数记「明细可用」，被登录墙/人机验证拦记拒绝证据，
  0 条但无拦截证据只说「本次无数据」，不判会话失效。点击期间按钮显示
  「核验中…」并禁用，防重复点。

## App 渠道：统一基类契约

- 城市名映射、航线判定、逐日期记账收进 `AppCrawler` 基类单源，两个 App
  渠道不再各写一份。
- 多日期稳定性：航线未变时不再重复设城市；**选日失败不搜索**——列表页
  无法校验属于哪天，继续搜会把上一个日期的价格记到目标日期名下。

## 图表与配置

- 折线缺口判据按样本量分流：样本不足时不再用中位数外推，48h 的空缺不会
  被画成一条连续线；3 点等间隔序列也不会被逐点断开。
- 配置项可达性保持不变：所有配置键都能在页面配置并热更新，启动级项
  （监听地址、数据库/日志/资料目录）保存后走重启生效，界面显式提示。

## 验证

- 新增门禁覆盖：容器监听地址回写（含真保存后读 yaml）、登录卡真查询核验
  三态证据、邮件快照 root 启动参数、登录入口真网络可用性、测试不得写死
  本机路径。
- 负控均按预期变红（只改一处实现、保留结构）。
