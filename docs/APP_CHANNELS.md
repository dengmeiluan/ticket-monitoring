## 这是什么

框架默认只跑 5 个浏览器渠道。App 渠道（智行 / 去哪儿 / 飞猪 / 同程 / 携程 App）是**额外可选**能力：
它们没有可用 Web 面，只能通过 Android App 取数，因此需要本机跑一个
Android 模拟器（MuMu），由框架通过 adb 驱动。

**不启用时，框架行为与以前完全一致**——不 import、不检测设备、不显示 UI。

## 前置条件

| 项 | 要求 |
| --- | --- |
| 系统 | Windows（MuMu 仅 Windows；Linux/macOS 上 App 渠道自动不可用） |
| 模拟器 | MuMu 12（本机实测 `D:\Program Files\Netease\MuMu`，装 5 个 App 后约 14.8 GB；每多装一个 App 镜像继续涨） |
| 虚拟化 | 需开启 VT；MuMu 与 Hyper-V/VBS 可共存（实测 `hyperv_enabled: true`） |
| 磁盘 | 引擎 + 实例约 5 GB 起 |

## 配置

```yaml
android:
  enabled: true                    # 总开关，默认 false
  provider: mumu
  install_dir: ""                  # 空=自动探测常见安装位置
  vm_index: 0                      # 多开时选第几个实例
  boot_timeout_s: 180              # 冷启动实测 24–36s，留足余量
  action_timeout_s: 60
  snapshot: true                   # 登录态快照：网页登录一次后自动保存/恢复

users:
  - platforms: [qunar, fliggy, app_zhixing, app_qunar, app_fliggy, app_tongcheng]  # 显式加入才启用
```

渠道 id：`app_zhixing`（智行 App）、`app_qunar`（去哪儿 App）、
`app_tongcheng`（同程 App）、`app_fliggy`（飞猪 App）、
`app_ctrip`（携程 App，修复城市页判据后连续两次 32/33 行）——
**都要显式写进 `users[].platforms` 才会被调度**。不写就完全不采集，渠道健康卡上
只会在「未扫描」一行点名它们（见下）。

## 已知限制

1. **登录一次，之后不用再登**：在网页「渠道登录」分区点「App 登录」，
   画面就是真机实时屏幕，点几下完成登录并点「我已登录完成」，程序会把
   `shared_prefs + databases + files` 打包到
   `user_data/android_snapshots/<渠道>.tar.gz`。下次采集前自动恢复，
   换机/重装/清数据后仍是登录态。
   内嵌画面是**近全屏工作台**：默认按视口放大、可切专注（隐藏控制轨）、
   可缩成可拖动浮窗继续操作；画面支持点按/拖动/长按/滚轮，控制轨有内联
   文字输入与返回/桌面/最近/退格；`GET /api/app-login/info?plat=` 只读返回
   分辨率、前台 App 与本次会话统计，供状态栏显示。App 渠道图标使用独立
   squircle 质感层（`.bic-app`，顶高光/底收影）；智行字标已去原图底部
   促销横幅，详见 `docs/ASSET_LEDGER.md`。
   三条保护：设备上的登录态比快照**新**时跳过恢复（不覆盖用户刚登的账号）；
   恢复失败会记 `snap-restore`；**恢复了快照但仍停在登录墙**时会写明
   「快照已失效（需重新登录）」——这是「该重登」而非「该查文件」，两种情况
   必须能分开读。
   **设备上已经登录着，就完全不恢复**：快照是某一刻的副本，用完即旧。
   去哪儿实测：刚登录完导出快照 → 立刻恢复 → App 回到登录墙；不恢复、
   直接重启 → 登录态正常。用旧副本盖掉设备上更新的会话，等于每次采集都把
   用户踢下线（`_looks_blank` 保证白屏中间态不算「已登录」）。
   **导出快照前会先 force-stop**：登录态写在 SQLite（去哪儿是
   `databases/RKStorage`），运行中大部分内容还压在 `-wal`/内存里，边跑边
   打包只会打出一份"看起来有库、其实没有新会话"的旧快照。
   **恢复以 tar 退出码为准**：曾经以输出里有 `DONE` 当成功，而 `echo DONE`
   无条件执行——tar 明明报 `No such file`，恢复却返回「已恢复快照」，设备
   上什么都没变。
   **快照不含动态 so**：`files/plt_dynamic_so` 是 App 自下载的**可执行代码**，
   与设备 ABI 绑定（去哪儿那个是 arm64，模拟器是 x86_64）。带进快照就会在
   恢复时写回设备，App 启动加载即死锁（见下条）。排除后快照从 2.8 MB 降到
   564 KB——登录态本来就只该是凭据。
2. **明细优先，日历兜底**：远期日期（首页 8 天条之外）走「长窗口选日
   → 点查询 → 列表页」拿真实明细（航班号/时刻/价格）。明细解析失败时
   回落到日历价（每天一条最低价、无航班号），并在账本里分开记
   `航班明细` 与 `日历` 两条通路。实测未登录也能拿到明细，遮罩价
   （`￥3??`）才需要登录。
3. **长窗口靠「选择日期」弹层**：首页日期条只有 7–8 天，点开弹层后
   是跨两个月的完整日历、每天有价。入口在首页，**一旦点了「机票查询」
   进列表页就没有日历图标了**——所以流程必须是「设航线 → 停在首页
   → 开弹层选日 → 再点查询」。
4. **弹层价格是异步渲染的**：打开瞬间格子已在但价格为空（实测 2s 后
   才有价），必须轮询到「有价格出现」再读，否则会当成「有日期无价」。
5. **列表页价格被拆成两个节点**：`￥` 与数字是两个独立 TextView，
   不是整串 `¥256`；按整串解析会把整页判成「有航班无价格」。
6. **系统权限框会被自动点掉**：换机/重装后首次启动会弹通知权限，
   它盖在首页上；程序按 activity 判据识别并代点「允许」，不误点正文按钮。
7. **App 卡死（系统「没有响应」）可自愈**：先是「动态 so 与设备 ABI
   不匹配」——App 启动时加载它，主线程 Blocked 在 `Runtime.load0` 等锁，
   **点「等待」186 s 也不恢复**（死锁不会自解）。处置顺序：先点「等待」
   等 30–60 s；仍卡就自己 force-stop 再冷启动（不点「关闭应用」由系统
   乱杀）。根治是让快照别带动态 so（见上一条）。
8. 单设备串行：多个 App 渠道共用一台模拟器，采集是排队执行的。
9. App 改版会导致元素定位失效；届时账本会记具体状态，不会伪装成无票。

### 档位复位：往返 → 单程（去哪儿）

去哪儿首页的「单程/往返/多程」是**持久档位**，跨轮不自动复位。跑过往返
之后接着跑单程，首页仍是往返档：

* 往返日期弹层是**两段式**（先点去程、再点返程、最后「确定」），单程流程
  拿它当单程日历 → 判据永不成立 → `pick-date-failed`，整轮 0 行；
* 更糟的是不报错那条路：结果页是往返页，往返总价被记成单程价。

所以 `_fetch_locked` 一开始就调 `_switch_to_single`，判据是**返程日期位在
不在**（`atom_flight_ll_back_date`）——不用 RadioButton 的 `checked`，实测
同一渲染帧里 checked 会滞后。真机对照：往返跑完后立刻跑 11-06 单程，
复位后拿到 4 条航班、行头 ¥520；不复位时同一条命令直接
`pick-date-failed`。

`multi_city`（多程）**App 全渠道未接，矩阵标 `""`（产品有入口、
采集未接）；浏览器端仅携程 PC 2 段已生产验证（y，scope 仅 2 段）**，
采集端未实现 = 未验证），不标 `n`——`n` 只留给渠道真没有的能力/停服；
也不写一个不会工作的 `y`。数据模型仍是单 O-D，改造设计见
`docs/HANDOFF_CAPABILITY_MATRIX.md` §1.6。

### 智行 App 的国际档（2026-10-30 真机跑通）

国际与国内是首页上**两个不同的表单**：国际档多出「返程日期」与
「经济/超级经济舱」舱位行，城市选择页的 tab 也不同。`set_flight_route`
按 `is_intl_route(from, to)` 先切档（`select_mode`，判据是该舱位行在不在），
再设城市。不切档就设国际城市时，首页城市位与结果页仍是国内那套。

国际列表页还有一个版式差异：**卡片没有航班号**，只有航司名 + 起降时刻
（国内页有 `CZ8890` 之类）。明细解析因此改成**以「同一排的起飞→到达时刻」
为锚**，航班号退化成可选字段（取不到就留空，绝不编）。

同一改动还收紧了三件事，都是真机踩出来的：

* **经停城市**：中转卡片的「青岛 20h35m」必须落到 `transCity`，否则
  中转会被当成直飞进直飞最优池；
* **行头价取最低直飞**：中转低价不再顶掉行头价（真机：青岛中转 ￥450
  曾把直飞 ￥552 压成行头）；
* **航司名**：机场行（「浦东T2 / 羽田T3」）、排序栏（「比价」）、区头
  （「优选航班」「宠物友好」）都落在同一纵向窗口里，按"第一个中文名"
  取会取到它们；改为优先走"航班号同排左侧"，国际卡再退回"机场行以下"。

实测（MuMu，2026-10-30）：浦东→成田 11-20 / 11-24 各 7 条真实航班
（￥988 起，含起飞与到达时刻），两日期共 60 s；北京→上海 11-05 / 11-06
各 9 条（含 1 条青岛中转，￥450），共 139 s。

### 明细通路的四个坑（r725–r727，全部真机踩出）

这四条都不是"页面变了"，而是**判据把"没看见"当成了"不存在"**：

| 现象 | 真因 | 修法 |
| --- | --- | --- |
| 明细整轮等超时，最后回退日历价 | 点查询后前台换成独立 RN 全屏 Activity（`CRNBaseActivityV2` 的「全网招募：智行机票体验官」），14 行文案 > 旧阈值 12，既判不成广告也不含登录标记 | 营销词 + **无数据**即算广告，文案条数不再设上限 |
| 上一条的 ✕ 点不中 | 关闭钮是私用区字形（`\ue706`），且 y=1092 在页高一半以下（「一键报名」在 1527） | 认图标字形，**只按横向判右侧 2/3**，不限纵向 |
| 设航线记「找不到城市行」 | 冷启动头 4 帧 `dump()` 全是空串（uiautomator 未就绪），`is_intl_form("")` 为 False → 判成「已是国内档」→ 在没渲染的首页上找城市行 | `_await_home`：先拿到首页再谈页面长什么样；空帧只能报「没取到页面」 |
| 某班记成 `984839 ¥2094` | 图标写成 XML 数字实体 `text="&#984839;"`，不还原时 `[A-Z0-9]{2}\d{3,4}` 在字面量里匹配出 6 位数字，还抢在真航班号前被取走 | 解码实体 + 航班号**必须含字母** |

最后一条的判据值得记：纯数字不可能是航班号（`CA8573` / `3U8888` /
`9C8888` 都至少含一位字母），所以"数字正好落在卡片窗口里"不该被当成航班号。

**去哪儿 App 有没有同样的问题**：它的解析器也不还原 XML 实体、正则同样
允许纯数字（`([A-Z0-9]{2}\d{3,4})(?![0-9])`）。但用真机 dump
（`dom_1106_list.xml`，含 `&#986266;` 等实体）实测**没有**串味：它的航班号
候选按「本卡片纵向窗口内」筛选，工具栏图标落在窗口外，取到的是真实航班号。
所以本轮不改它——没有证据就不动；哪天版式让图标落进卡片窗口，先照着
`tests/test_r727_glyph_is_not_flight_no.py` 的思路补行为断言。

真机复验（2026-10-31，SHA→HAK 2027-01-29）：产出 1 条 FlightPrice
（一渠道一日期一行的池约定），`extra` 里 **8 班全部带航班号与时刻**：
CA8573 ¥1734 / MU6355 ¥2085 / FM9253 ¥2085 / MU6381 ¥2085 /
FM9269 ¥2085 / FM9251 ¥2085 / CZ6686 ¥2094 / CZ3516 ¥2094。

## 弹窗状态（三类，互不冒充）

| 状态 | 含义 | 处置 |
| --- | --- | --- |
| `ad` | 营销弹层 | 自动点关闭（≤2 次）后继续采；关不掉则上报 |
| `captcha` | 验证码/滑块/点选 | 停下等人工接管 |
| `face` | 人脸/活体核验 | 生物特征，只能本人操作；优先级最高 |

判据说明：真实航班页顶部本来就有「登录解锁更低价」横幅，但数据能采，
所以**登录只在页面没有可采数据时才算拦路**，否则会把好数据误判成登录墙。

## 首次使用（引导）

装好框架后，App 渠道是**可选项**，不会自动启用。推荐顺序：

```bash
# 1) 体检：看运行时状态与下一步（只读，不安装任何东西）
python main.py --app-status

# 2) 按提示装 MuMu（约 7 GB，需一次管理员确认），装完再体检
python main.py --app-status

# 3) 配置页打开「Android 真机通道」总开关，并在用户里勾选「智行 App」
```

`--app-status` 输出五个阶段（检测 / 安装 / 启动 / 装 App / 验证），
已完成的打勾。它**先于实例锁返回**——已有实例在跑时也能查，那正是
用户想确认状态的时刻。

## 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 状态 `not_installed` | 找不到 MuMu | 按 `--app-status` 的提示装，或配 `install_dir` |
| 状态 `stopped` | 实例未启动 | 首轮采集会自动拉起；也可在 MuMu 里手动启动 |
| 状态 `error` + `adb 未连接` | adb 会话断了 | 重开实例；`adb kill-server` 后重试 |
| 账本 `login` | 需要登录 | 页面是登录墙时记此状态；遮罩价（`￥3??`）需登录才显示 |
| 账本 `captcha` | 验证码触发 | 人工接管 |
| 账本 `face` | 人脸/活体核验 | 只能本人操作；本条渠道在该账号下不可自动化 |
| 账本 `timeout` + 「无法识别的页面状态」 | App 可能改版 | 需更新解析器，不是"没票" |
| 账本「N 个目标日期在日历窗口外」 | 目标日期超出两个月 | 缩短监控日期，或等窗口推进 |

## 实现结构

```
core/android/config.py    配置归一化（缺省关闭、数值钳制）
core/android/mumu.py      MuMuManager 封装（发现/查询/控制，失败不抛）
core/android/device.py    ADB 原语（screencap/tap/input/dump/app_start/deep_link）
core/android/ocr.py       Windows 自带 OCR（截图→词块；Flutter 画布页兜底）
core/android/runtime.py   单例 + 设备锁 + ensure_ready 编排
core/android/snapshot.py  登录态快照（**排除动态 so**）
core/channels.py          渠道清单 + 维度矩阵（零依赖单一事实源）
crawlers/app_base.py      AppCrawler 基类：账本契约、城市名、航线判定、
                          逐日期记账、设备前置（登录恢复→清权限框→清 ANR）
crawlers/app_zhixing*.py  智行渠道（明细优先 → 日历兜底）
crawlers/app_qunar.py     去哪儿渠道（深链进首页 → 整月网格选日 → 列表）
crawlers/app_qunar_parse.py  去哪儿列表解析（纯函数，离线可测）
crawlers/app_qunar_lowfare.py 去哪儿「低价机票」日期带解析（每天一条最低价）
crawlers/app_blockers.py  拦路物识别（广告/验证码/人脸/登录/ANR）
crawlers/app_fliggy.py     飞猪 App 采集器（固定竖屏 + OCR）
crawlers/app_fliggy_parse.py  飞猪结果页/表单 OCR 词块解析（纯函数）
```

**统一设计**：城市名映射、航线判定（`read_route` 钩子）、逐日期记账、
设备前置都只在基类实现一次；新增 App 渠道只需实现导航与解析两个钩子，
口径自动与既有渠道一致。
