# 经验沉淀：反爬、工程与 UI 的坑与解法

本项目两天高强度迭代中踩过并解决的坑，按主题沉淀，供后续维护与同类项目参考。

## 一、反爬与数据采集

### 1. 响应"看不懂"先分层：限流 / 风控 / 接口废弃
| 响应特征 | 本质 | 正确动作 |
|---|---|---|
| `{"errcode":-1}` 反复、短时恢复 | 网关抖动 | 退避重试（但见下"幽灵送达"） |
| `FAIL_SYS_TOKEN_EMPTY` | 首次无 token | 重签一次即过 |
| `NOT_SUPPORT / 老版本不支持` | **官方下线接口** | **绝不重试**，立即降级渠道 |
| `RGV587 / 滑块` | 行为风控 | 停手换路径，重试只会加深 |
| 响应体极小（几百字节） | 错误包 | 先打印响应体再决定策略 |

> 教训：把"接口废弃"当"限流"处理 = 每轮多分钟空转。错误语义先分类，再谈重试。

### 2. 阶梯式优于预防式
为规避"可能的全局限流"而固定等待 310s，实测 99% 时间在白等。正确姿势：**礼貌间隔（20s）+ 失败才阶梯退避（90/180/300s）+ 冷却期共享 + 成功即重置**。一轮扫描从 11 分钟降到 2.5 分钟。

### 3. 浏览器 DOM 是反爬的终极兜底
当 XHR 响应是分片混淆体（服务端把数据切片+混淆 JS 由前端拼装）时，别逆向拼接算法——**直接读渲染后的 DOM 文本**（`innerText` 按行结构化解析），稳定得多。

### 4. 渠道健康要可见
每轮推送列出"本轮无数据渠道"，渠道故障 30 分钟内可感知（否则用户以为程序死了）。

### 5. 渠道降级要"即检即断"
废弃特征检测到后置进程级标志，后续查询 0s 跳过；重启重新探测（接口恢复自动自愈）。

## 二、钉钉推送

### 1. -1 "系统繁忙"存在幽灵送达
报错但消息实际入群——**任何重试都可能造成用户收到两条一样的消息**。且 markdown 消息**聊天窗口不显示标题**，重试标记放标题用户看不见。
**终局原则：防重复优先于防丢失。单发不重试，丢失由下轮心跳自然补，关键警报走独立通道（电话）兜底。**

### 2. 手机窄屏排版：每行 ≤26 全角当量
写脚本渲染真实 desp 逐行量宽度（`全角=2 半角=1`），超宽行必折行错位。KPI 用三行制（价格/参数/仪表各一行）；比价链超 3 渠道只列最低/最高两端（中间价在明细总表图里有完整链）。

### 3. 表格进图片
钉钉 markdown 不支持表格——用 Pillow 渲染表格图直推（分组+达标红色+价格列大号彩色）。高度公式必须与实际绘制逐组一致（漏算一个表头高度=底部内容被裁出画布）。

### 4. 电话/短信通道（免费）
钉钉电话 DING 需专业版（9800元/年）。替代：**阿里云云监控事件通知**（CRITICAL 事件→联系人组电话+短信），Basic Auth+一行 JSON。中文用 `ensure_ascii=True` 纯 ASCII 传输防网关解错编码。达标才拨、去抖（2h 内不重拨、再降≥50 才再响）。

## 三、工程

### 1. Shell 传代码必踩反斜杠折叠
Bash 内联 python/heredoc 中 `\\n` 会被折叠成真实换行断字符串——**同一坑可以连踩三次**。铁律：改代码一律用编辑器工具（Edit/Write），shell 只跑已落盘的脚本。
第 N 变体（09-09 再踩）：**PAGE/HTML 等非 raw Python 字符串里写 JS 转义**——`'\r\n'`/`'\ufeff'` 被 Python 解释成真实控制字符，JS 字符串源码被拦腰截断、整页脚本失效（症状=所有函数 undefined）。铁律：嵌入 JS 需要控制字符时用 `String.fromCharCode(13,10)`，绝不在模板字符串里写反斜杠转义。

### 2. `;` 链会吞失败
`a && b; c; d` 中 b 失败后 c/d 照跑——曾把语法损坏的代码 commit+push。关键链路用 `&&` 串接，或显式 `set -e` 语义。

### 3. 重写代码文件后必须 import 级验证
`py_compile` 只查语法，**误删函数要 `from x import 具体名` 才能暴露**（曾误删 `build_notifier` 导致进程启动即崩两次）。

### 4. BlockingScheduler 的实例引用要用模块级
`start()` 永久阻塞，任何 `return sched` 都不可达——模块级 `SCHED` 变量在 start 前赋值，热重载时才能 reschedule。

### 5. 热重载不重新 import 模块
新增/修改类后必须重启进程；热重载只重建配置对象。

### 6. 推送类改动验证：等自然轮，不手动触发
调试期连环重启+手动触发=1 小时 5 轮推送轰炸用户。启动加节流（上轮<5min 跳过首轮）。

### 7. Windows 换行/编码
PS1 中文脚本必须 **UTF-8 BOM + CRLF**（PS5.1 无 BOM 按 GBK 解析全乱码）；`$ErrorActionPreference=Stop` 下 git 的 stderr 正常输出会触发终止——git 调用段临时降 Continue。

### 8. GitHub 资产名 ASCII、上传要 Content-Type 与大超时
中文资产名会丢参变 default.zip；上传 API 必须 `Content-Type: application/zip` + `httpx.Timeout(write=300)`。

### 9. push 后必须远端终验
管道截断的 push 输出不可信；仓库重置后第一推必须 `-u`（无 upstream 时裸 push 静默失败、提交全部积压本地）。

### 10. 代理环境trust_env=False
图床/钉钉/ntfy 等直连域名走系统代理会被随机掐断（EOF in violation of protocol）——`httpx.post(..., trust_env=False)` 一律直连。

## 四、UI 与可读性

### 1. 对比度用公式不用目测
弱化灰 #8a99a8 在白底仅 2.8:1（WCAG AA 要 4.5:1）。定色跑对比度计算：正文≥7、次级≥4.5、白字彩底≥3。

### 2. 底色中性化，彩色只留语义
带蓝调的灰底（#f0f3f7）与白卡片、蓝主色三层蓝叠=割裂感。背景用无色相灰阶（B-R 偏移≤4），蓝只出现在按钮/选中/数据。

### 3. 暗色模式三雷
- 媒体查询改 data-theme 时 `:root{}` 嵌套进选择器会失效——变量要提升到选择器本体；
- 逐元素排残留硬编码（table background:#fff 这类）要用脚本扫 computed style 清零，不靠眼睛；
- 内嵌浏览器可能不传系统偏好——加手动三态切换（自动/亮/暗，localStorage 持久）。

### 4. 多租户配置界面必须显式呈现实体边界
平铺长表单看不出"用户"——折叠用户卡（名字+航线数+推送状态头部）是底线。

### 5. 全配置热加载
"部分项需重启"是架构不完整。调度周期用 `reschedule_job` 热更，用户/阈值/通道走对象重建。

## 五、产品

- **丢失可补，重复扰民**（不可靠通道重试设计的唯一正确取向）
- **渠道覆盖看供给重合度**：美团/智行无 H5 攻击面且供给与携程系重合，放弃；性价比是判断标准
- 每次发版前跑回归测试（含"未达标零触达电话"这类守卫场景）——守卫类逻辑没有测试固化，迟早被重构吞掉

## 六、09-09 增补：渠道废弃与复活实战

### 1. 接口被封时先找 SSR 页面
移动端 MTOP 接口被官方下线+新版强制登录看似死路，但 **PC 搜索结果页可能是服务端直出**（数据在初始 HTML 里，无接口无登录）——用 Playwright 滚屏收集 innerText + 行状态机解析即可复活。数据在初始 HTML 里比想象中常见。

### 2. 用户随手给的真实 URL 是最高价值情报
自己猜入口 URL 探测十次（flight.fliggy.com 空壳/www 超时/m 端登录墙），不如用户贴一次日常使用的真实链接。**渠道故障时直接问用户'你平时在哪个网页查'**。

### 3. 跨天时刻行是解析器杀手
到达行带后缀（"01:25 第2天"）不匹配纯 HHMM 正则 → 卡片错位连锁（吞首卡+把下一卡时刻接到上一卡）。时刻类字段一律允许行尾后缀，解析完做"dep<arr 或跨天"自洽断言。

### 4. 渠道废弃的完整决策树
废弃确认（官方 NOT_SUPPORT 实锤）→ 三路探测（新版本号/移动端新页/PC 端）→ 全断则即检即断降级（0s 跳过省时间）→ UI/推送标注"维护中"管理预期 → **留复活探测钩子**（重启重探，恢复自动自愈）。

### 5. 多查询架构下的平台唯一性假设要全面升级
"每平台取一条明细"的去重在多航线（一轮多查询）下吞数据——所有 平台级 唯一键（去重/最低价/chart 缓存）都要升级为 平台+航线+日期。同类 bug 一次重构全部排查，别修一个漏两个。

### 6. 价格口径要在渠道接入时标注
飞猪 PC 是不含税展示价（与含税渠道差 50-130）——渠道接入第一天就确认计价口径并写进 docstring，否则比价长期偏优误导决策。

## 七、TDD 纪律（自查纠偏）

> 用户指出后自查：近 20 轮迭代全部"改完→真机验证"，零个先写失败测试——违反 Iron Law（没有失败测试就没有生产代码）。本节为纠偏记录。

### 1. 真机验证 ≠ 复现测试
真机只能证明"这次好了"，不能证明"再坏时会被抓住"。回归防线必须是一跑就红的自动化用例。

### 2. 补欠账的诚实做法：变异验证
理想 TDD 是看着测试失败再修；已上线的代码补测试时，用**变异验证**等效：注入原 bug 形态 → 确认测试变红 → 还原复绿。证明测试具备抓该 bug 的能力（本轮 3/3 变异被抓）。

### 3. 补测试当场抓到两个真 bug
- `arrDate` 带时间尾巴（`2026-09-26 00:00:00`）——下游 strptime 前 10 位侥幸没炸，schema 暗病
- fliggy `_RE_FNO` 不认数字开头二字码（9C 春秋/8L 西藏/3U 川航）——qunar 版修过的坑重写时忘了，**生产正在丢春秋全部航班**
这就是"tests-after 有偏"的反证：不写测试，你以为修完了。

### 4. 难测 = 设计问题（听测试的）
轮聚类逻辑埋在 `_user_state` 大函数里无法单测——提取为纯函数 `_cluster_round_rows(rows, gap_s)` 后 3 个用例立即可写。每次"不好测"都是重构信号。

### 5. 今后纪律
- bug 修复：先写复现测试看它红，再修
- 新功能（可测部分）：测试先行
- 每次提交前：`tests/` 全绿

## 八、钉钉渲染三禁（09-09 实锤）

1. **尖括号家族全禁**（含全角 ＜＞）：markdown 层按 HTML 标签解析吞掉后续文字——比价链用 `→`。已有测试 `test_cross_compare_no_angle_brackets` 守卫。
2. 聊天窗口不显示标题：任何"重发标记"必须放正文首行。
3. 表格不存在：Pillow 渲染 PNG。

## 九、登录态体系（游客限流通病解法）

- 未登录 = 游客态，各渠道风控阈值严苛（途牛 179991、携程 IP 灰名单、qunar 限流窗口更长）。
- 解法：`--setup-login` 五窗齐弹（**桌面视口**——手机模拟下鼠标拖滑块失灵，页面监听 touch；cookie 同域通用）。
- 用户本地 Chrome cookie 不可迁移：新版独占锁 + App-Bound Encryption（Google 2024 加固，实测复制都拒）。
- 登录引导页用**用户熟悉的官网首页**而非 passport 页（用户点右上角登录更顺）。
- 渠道被风控 → 推送"无数据"提示 + 建议跑 `--login <plat>`。

## 十、09-09 下午增补：钉钉双端渲染与单实例纪律

### 1. 钉钉换行双端不一致：PC 不认单 `\n`，手机认
同一条 markdown：手机端 `\n` 正常换行，PC 端把相邻行**粘成一行**随文本折行——进度条因此和参数行粘连、被腰斩。终局解法：**所有需要换行的位置一律段落级 `\n\n`**（价格/参数/仪表三段、⚠️ 行、页脚），列表项交给 `- ` bullet（两端都安全）。写推送时别再用裸 `\n` 假设两端行为一致。

### 2. U+2026「…」在钉钉渲染成。。。。
比价链里省略中间渠道的「…」实锤显示成"。。。。"（用户截图确认）。禁用：超过 3 家只展示最低/最高两端。同族结论：**钉钉正文只用确定安全的字符集**（→、｜、￥、emoji 常规款）；生僻 Unicode（▓░、…）都出过事。

### 3. emoji 进度条格数上限：5 格
🟦⬜ 是宽字符，10 格在窄屏必折行破坏完整性（截图实锤 7+3 腰斩），5 格稳定单行。设计仪表条类元素先量宽度：宽字符 emoji 按每格 2 全角当量算，5 格=10 当量是安全上限。

### 4. `--login` 残留进程 = 旧代码僵尸监控（本日最大坑）
`main.py --login <plat>` 在终端里跑完登录后，终端不关进程就不退（input 等待/落调度循环），**带着旧代码内存镜像并行跑完整监控**：旧格式推送混进群里、与正式实例双监听 8765、DB/日志互踩。症状：**改完代码部署后推送"忽新忽旧"**。
排查三板斧：
1. `Get-CimInstance Win32_Process`（注意 CommandLine 为空的高级进程会被 `like '*main.py*'` 过滤漏掉，按创建时间兜底对账）；
2. `netstat -ano | findstr 8765` 出现**两个 LISTENING PID** 即双实例实锤；
3. 日志里 `[启动]` 行出现次数 ≠ 已知重启次数，按时间戳对账。
纪律：**只允许一个监控实例**；改版后验证要看"最新一条推送"由哪个进程发出（debug/last_push.md 的 mtime 对日志时间戳）。磁盘代码是对的但推送还是旧格式 ⇒ 必有旧进程活着，先查进程再查代码。

### 5. qunar 间隔终值：8s + 去末尾空等
登录态连续零失败后 MIN_GAP 12→8 安全落地；更大的隐藏浪费是 `_fetch_inner` 每个日期后的 `_sleep()`（配置 5-15s）——末条日期后的等待是纯空转（fetch() 的 MIN_GAP 已兜住礼貌间隔），只保留日期间的 _sleep。单轮 qunar 净省约 1 分钟。

### 6. 钉钉 -1 高发日的表现
同日多次 `{"errcode":-1,"errmsg":"系统繁忙"}`，消息实际入群（幽灵送达）——单发不重试策略正确，勿因高频 -1 加回重试。

### 7. 页面级 JS ReferenceError 被 fetch 的 catch 吞成「服务未启动」
控制台曾长期半瘫：渠道角标之后全部不渲染（表格空、走势图空白），页头却显示「服务未启动」——真相是 buildChips 引用了未定义的 `MAINT` 常量，render() 抛异常被 load() 的 catch 吃掉，错误语义完全误导（服务明明正常，数据都在）。
教训：
1. **fetch 链路与 render 链路分开 try/catch**，渲染异常要显式暴露（console.error + 页面提示「渲染异常: …」），别让两类故障共用一个含混文案；
2. 前端无构建链（纯 HTML 字符串）没有语法兜底——改完必做两步验证：`new Function(脚本全文)` 查语法 + 页面内手动调 `render()` 捕获运行时错误；
3. 「功能消失但页面还活着」优先怀疑 JS 半途抛错，其次才是服务问题。

## 十一、09-10 增补：控制台"虚报达标"与交互卡顿

### 1. 聚合 KPI 的阈值必须随最优航班所属航线（两层坑）
用户截图反馈"虚报"：控制台显示"直飞 ￥1760（线 ￥1900）✅ 可出手"，但 1760 是乌→上 10/04 的价，那条线是 1600——**全局最低价配 routes[0] 的线**判达标。修完第一层又暴露第二层：`route_by_pair` 按城市对索引，**同城市对不同日期互相覆盖**（10/04 的 1600 被 10/05 的 1900 盖掉），逐行 qual 判定同样中招。
终局修法：① best 简报带 `th`（该航班所属航线的阈值），前端标签/进度条/文案全用它；② 航线索引键 = `(from, to, date)` 精确匹配、城市对兜底；③ pill/标题用逐行 `any(f.qual)`（与推送同语义）。这是六.5"唯一键带日期维度"家族的第三起——**每次引入聚合展示都要全链路排查索引维度**。

### 2. 行交互禁止全量重建表格
600+ 行表格每次点击行都 `innerHTML` 全量重建（100-500ms 卡顿感）：展开/收起改**外科手术式 DOM**——只 `insertAdjacentHTML`/`remove` 一个 `<tr>`（实测 4.2ms/0ms）。通用律：交互反馈路径只动增量节点；全量重建只留给排序/筛选这类结果集真变的操作。

## 十二、09-10 晚增补：热加载的最后一环与缓存签名

### 1. 热重载换的是"对象"，闭包捕获的是"快照"
`reload_config` 里 `cfg = load_config(...)` 让 main 作用域看到新 dict，但 `make_sweep_job(cfg, ...)` 的形参是**另一个绑定**，仍指启动快照——爬虫超时/错峰/UA、日报时刻、图床配置热保存后静默不生效（headless 清了缓存，重建实例读的还是旧 dict）。铁律：**跨热重载的可变配置必须走单一事实源容器**（本项目的 `rt["cfg"]`），闭包/长生命周期函数一律从容器现读，不持有 cfg 形参直引。

### 2. 缓存签名禁用 `id(对象)`
给 `/api/state` 加签名缓存时若用 `id(st.users)`：热重载释放旧 list 后新 list **很可能分配到同一地址**（CPython id 复用），新配置撞上旧签名 → 改了阈值页面纹丝不动。用内容摘要（users 的 JSON 哈希，dataclass 经 `default=str` 进 repr）或显式代数递增，不用对象身份。

### 3. "外科手术式 DOM"仍会被扩展击穿：点击路径要零 childList 变更
用户实测"每点一行卡数秒"但干净 Chromium 探针全绿（JS 0ms/零长任务）——真凶是**翻译/比价类 Chrome 扩展监听 MutationObserver，任何 childList 插入都触发全页重扫**，652 行表格上每次"插/删一个展开行"都被放大成秒级卡顿。终局修法：展开行改为**渲染期预置隐藏行（display:none），点击只切 display**——childList 零变更（attribute 变更不在默认 Observer 过滤内），预置成本仅每行一个空 tr。通用律：面向用户浏览器的页面，交互路径避免任何节点插拔；"只插一个节点"的优化在扩展面前不算数。

## 十三、v5.0 渠道 PC 化：方法论与证据

### 1. "token 刷新成功但接口 1999" = 接口级风控升级，别在 token 上打转
qunar H5 的 Bella token 每轮都成功刷新（长度 911）却 121 连拒 1999——**风控升级发生在接口校验层，与 token 新鲜度无关**。判据：拦截到的请求带合法 token + 响应仍是风控码 ⇒ 换路径（换端/换接口），不重试、不逆向新校验。

### 2. 同族接口的 PC 版结构差异清单（qunar wbdflightlist 实测）
H5 touchInnerList 与 PC wbdflightlist 同族但有三处不同，照搬 H5 解析器必错：
① `data.flights` 是普通数组（H5 是字符串化 JSON）；
② **中转整体到达时刻在 `binfo2.arrTime`**（binfo1.arr 是中转段到达——H5 的 binfoX 语义不同）；
③ 无 `mixFlightName`，显示名用 `binfo.shortName+airCode` 拼；直飞时长在 `binfo.flightTime`（"5h30m" 需转 "5时30分"）。
另：Python `str.format` 里 `{from}` 是非法占位符（关键字参数），模板命名避开关键字。

### 3. 渠道 PC 化要"逐渠道定证"，不是一刀切
- **qunar**：H5 死 ⇒ PC 必换（救活，72 条明细实测）；
- **ctrip**：PC 版 302→432 风拒 ⇒ 保留 H5（登录态路径），改动即打破现状；
- **tongcheng**：PC 接口 getflightlist 带易盾 openDun、无头下列表卡片不渲染、价格口径未证实（日历价 2600 与 H5 存量一致 ⇒ H5 口径正确）⇒ 保留 H5，路由/接口/响应证据存 debug/tc_pc_list.json 备查；
- **tuniu**：无独立 PC 机票页，纯 httpx API 性能最优 ⇒ 保留；
- **fliggy**：PC SSR 直读，本就是 PC。
通用律：**"以 PC 为准"的正确姿势是给每个渠道拿证据做决策**——能救活的救活（qunar），已优的保留（tuniu/fliggy），有疑点的存证不动（tongcheng/ctrip）。SPA 404 页返回完整壳 ≠ 路由不存在（前端路由接管）；同程 PC 路由从 JS bundle 里 grep `itinerary` 得来（/flights/itinerary/oneway/:code，少个斜杠就是 404）。

### 4. CLI 交互搬进 Web 的关键：把"按回车"换成"事件置位"
--login 的本质是"有头持久化上下文 + 阻塞等用户信号"。搬进网页登录时无需重写浏览器逻辑——`_login_window(done_evt)` 本就吃 Event：Web 层只要 `POST /api/login` 起线程弹窗、`POST /api/login-finish` 置 Event 即可，会话保存/窗口关闭全部复用既有链路。注意两点：① user_data 是 Chrome profile 独占锁——采集进行中弹登录窗（或反之）会 Profile 冲突，靠 safe_fetch 自吞 + 健康条纹可见，UI 文案提示"采集进行中稍后再试"；② 会话落盘后**下轮采集自动生效**，本就热加载，无需任何刷新机制。

### 5. 发版流程的两个隐形坑
① **版本号 bump 必须与功能改动同批**：tag 写 v10.1.1 而 main.py 还是 10.1.0 → 页脚/测试推送显示旧版，"tag 与运行版本不一致"。bump 放进发版批次的第一个动作。
② **目检前先杀旧演示服**：8799 被旧进程占用时新演示服启动即失败（_Srv 禁复用会抛错但后台 `&` 吞掉），浏览器连到的是**旧代码页面**——"改了没生效"的假象。目检脚本开头先按端口清进程（同 uitest 的 free_port）。

## 十四、V50 骨架级重塑：长页→工作台/面板（09-11）

### 1. "换汤不换药"的根因：只做 cosmetics 不动信息架构
配置页三轮质感迭代（V20 分区骨架→登录卡/参数格/通道卡）后用户仍一句"一直都是大长页"点破——**表单再精致，堆成一条长滚动就是工具页，不是产品页**。设置类页面的产品级形态是"左导航=视图切换器，同屏只显一个分区"；监控类页面是"常驻英雄区+子视图 tab"。改骨架一次胜过改样式十次。

### 2. display 切换的三个连带坑（一次全踩，一次修完）
① **canvas 在隐藏容器里 offsetWidth=0**：chart() 开头加 `if(!c.offsetWidth)return` 跳绘，tab 切回时显式重绘——否则画出 0 尺寸废图或切回后空白；
② **徽标随面板隐藏**：cfgDirty 在用户面板工具行里，切到全局面板后 is_visible=False——"守卫失效"其实是断言看错了地方，守卫状态以常驻 savebar 为准；
③ **锚点断言假绿**：`cnav[data-t=sec-globals]` 指向不存在的 id（实际叫 sec-globals-card），getElementById 返回 null 被 if(t) 静默吞掉，而 scrollY>80 因此前内容残留恰好为真——**跳转类断言必须先回零位再断言目标入视口**（或直接改断言切换后的可见性）。

### 3. 可观察性数据要在采集现场取，别从日志倒推
健康时间线解析 monitor.log（文本、轮窗口猜、维护态锁存），脉冲则直接在 sweep 的 futures 包装处计时——`_timed_fetch` 一行拿到每渠道行数/耗时，Pulse 环形缓冲进程内即弃。**结构化数据在产生点捕获，日志解析只留给历史**（没有脉冲前的轮次）。

### 4. 搜索过滤与视图切换要互相成全而不是互相打架
面板化后搜索面临"命中的字段在隐藏面板里"的矛盾——解法：**搜索态临时展开全部分区（只留命中字段+命中计数），清空即还原单面板**。二者共享 display 切换原语，互不打架。凡"过滤/导航/切换"类功能叠加，先画清楚各自控制哪一层 display。

### 5. 推文详情链接复用同一份存档
Windows 弹窗 launch 与钉钉"完整详情"共用 `_archive_notify` 返回的 /notify/{nid}——**存档先行，链接后拼**（desp 在进 _send_urgent 前追加链接，随后钉钉主推/风暴同一 desp 自然携带）。一处存档，三端（弹窗/群消息/详情页）同源。

### 6. netstat 输出被 PYTHONUTF8 强解崩掉读线程
`subprocess.run(text=True)` 在 PYTHONUTF8=1 环境用 utf-8 解 GBK 的 netstat 输出 → UnicodeDecodeError 在 reader 线程里炸。**外部命令输出一律字节捕获 + errors="ignore" 解码**（只要匹配 ASCII 关键字就安全）。

### 6. 渠道 PC 化是"半程迁移"重灾区：爬虫换了，用户链接没换
v5.0.0 把 qunar 爬虫迁到 PC wbdflightlist 主路径，但 `_build_view_url`（推送价格链接/控制台 ↗）仍指 touch H5——接口风控死页，用户点开"挂羊头卖狗肉"（2026-09-11 用户报告）。**任何渠道路径迁移，必须全仓 grep 该渠道 URL 并清点"给人点的链接"**；正确姿势是链接与爬虫同源（爬虫在哪拿到数据，人就跳到哪页）。webui `_view_url` 助手统一出口，并按航班数据来源渠道出链而非一律 qunar。

### 7. "一切可配置"的诚实边界：热载与启动级要如实标注，别假装
V100 把 config 全量键暴露进控制台（/api/config globals 从 4 键扩到 13 键）。关键纪律：**每一项都标真实生效方式**——热载的标 🔥（保存即生效），启动级的标 ♻ 只读展示（db/log/user_data_dir，改 config.yaml 后重启），半热的写清生效时机（run_on_start="下次启动生效"）。产品话术统一说"全部热生效"而不标注例外，就是在制造下一轮"我改了为什么不生效"的信任透支。配套：每个通道一个真实测试按钮（钉钉/ntfy 用表单值实测、Windows 弹窗真发一条），让"配置对了"变成可自证的事实，而非信仰。
