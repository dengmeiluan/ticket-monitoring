# 经验沉淀：反爬、工程与 UI 的坑与解法

本项目高强度迭代中踩过并解决的坑，按主题沉淀，供后续维护与同类项目参考。

## 一、反爬与数据采集

### 1. 响应"看不懂"先分层：限流 / 风控 / 接口废弃
| 响应特征 | 本质 | 正确动作 |
|---|---|---|
| `{"errcode":-1}` 反复、短时恢复 | 网关抖动 | 退避重试（但见下"幽灵送达"） |
| `FAIL_SYS_TOKEN_EMPTY` | 首次无 token | 重签一次即过 |
| `NOT_SUPPORT / 老版本不支持` | **官方下线接口** | **绝不重试**，立即降级渠道 |
| `RGV587 / 滑块` | 行为风控 | 停手换路径，重试只会加深 |
| 响应体极小（几百字节） | 错误包 | 先打印响应体再决定策略 |

> 教训：把"接口废弃"当"限流"处理 = 每轮多分钟空转。错误语义先分类，再谈重试。

### 2. 阶梯式优于预防式
为规避"可能的全局限流"而固定等待 310s，实测 99% 时间在白等。正确姿势：**礼貌间隔（20s）+ 失败才阶梯退避（90/180/300s）+ 冷却期共享 + 成功即重置**。一轮扫描从 11 分钟降到 2.5 分钟。

### 3. 浏览器 DOM 是反爬的终极兜底
当 XHR 响应是分片混淆体（服务端把数据切片+混淆 JS 由前端拼装）时，别逆向拼接算法——**直接读渲染后的 DOM 文本**（`innerText` 按行结构化解析），稳定得多。

### 4. 渠道健康要可见
每轮推送列出"本轮无数据渠道"，渠道故障 30 分钟内可感知（否则用户以为程序死了）。

### 5. 渠道降级要"即检即断"
废弃特征检测到后置进程级标志，后续查询 0s 跳过；重启重新探测（接口恢复自动自愈）。

### 6. 结构化真值自相矛盾时：双独立信号一致才降信
渠道报文偶发自我矛盾（到达日期字段说是当日，跨天描述与「出发时刻+时长」重算却一致指向次日）。**单个信号矛盾不降信结构化日期字段**——描述写法各渠道不一、时长字段可能只给首段口径，单信号降信会把正确数据改错；**两个互相独立的信号同时指向同一另一取值才降信**。守卫规则要按「最坏输入」预演误杀面，不只按典型输入验证命中。

### 7. 同族接口的同名键跨端语义可不同：带量纲的键逐端实证
同族 H5/PC 接口都带顶层 transTime，H5 口径记「全程时长」，PC 解析器照抄落库——dump 逐行对账后实证 PC 端该键实为**中转停留时长**（45/45 行=两段起降差精确相等，「1天55分钟」即跨天停留），停留词面冒充全程落库多代之久，还连带让「全程−两段飞行」的停留推导公式在停留>两段飞行和时产出低估错值，直通衔接筛选与展示。三步修复缺一不可：读层换真值源（起降差权威）；真值挂来源标并对基于统计特征的启发守卫豁免（真值恰会落进击杀区——真停 9h+全程 14h55=1435 距 1440 仅差 5）；旧用例预期跟着真值层走（绿测试护住的可能是误解口径）。**键名相同≠语义相同：跨端移植解析器，每个带量纲的键都在目标端 dump 逐行核一次真值锚；报告里「X 无恙」的断言同样要可重跑复核。**

### 8. 响应结构合法≠样本完整：聚合指标要按「样本数」设早收门槛
渠道偶发返回结构合法但样本截断的响应（fareList 3/43 条、逐轮交替出勤）：每条价格都是真价，坏在轮最低价与明细随截断面失真（实录轮最低价较健康轮虚高 50%——「值域对不对」守卫抓不住「样本全不全」）。守卫形态：样本数 ≥ 门槛才允许首响即收（健康轮零额外请求）；薄样本不早收，记 best-so-far 续询（有界，礼貌预算不失控）；穷尽兜底返回 best-so-far——真稀疏日期零数据丢失，**不丢数据也不早收坏样本**；兜底路径打日志供观测记责任周期。凡「最低/最高/计数」类聚合指标都对采样率敏感，逐轮比对样本数是第二层观测。
门槛值要取「薄带与健康带的分离带」：门槛只挡首响即收，恰卡门槛的截断轮会以「过闸」新形态流入（实录 n 恰等于门槛的轮 8 班全缺真最低班、虚高 +6.8%）——低门槛只是把失真面从首收挪到过闸。以实测薄样本带与健康带之间的空档作门槛值，让整个过闸带落入续询面；渠道侧分布漂移时按「逐轮样本数分布」复检门槛仍在空档内。
「空档」是样本推断不是定理：少量 dump 判出的「16-38 恒空」被自然轮出勤推翻（DB 全量分布里该带按日出勤，抽检 min/max 在场=真稀疏与良性截断并存）——门槛落在空档「中段」仍留半条过闸带（中段即收不续询），地板档必须取健康带下缘，两带之间才无死角。「恒空」类断言的复检口径是 DB 全量逐轮分布，不是几份抽样 dump；判「空档无样本」与判「样本落在空档」所需证据量不同，后者一条即翻案。

### 9. 过期监控查询的滚动返回：按请求日期落桶=把别的日期的价挂进过期桶
监控日期过期后渠道不会报错，而是把查询**滚动为其他日期的航班照常返回**（滚次日、甚至滚两日）——行内自带真实起飞日期，与请求日期错位。照常落库的后果是决策级错位：曲线在过期日期上继续画活点（实为其他日期的价）、推送按过期日期呈现航班、「数据截至恒新鲜」让陈旧防线全部失效，最坏情形是向已起飞的日期发「可出手」电话。**过期航班无购买意义，跳采是唯一治本**（采集层跳过过期日期查询，日志留痕供「为何没数据」对账），配套三层防线：行内真实日期与查询日期的错位判定收口为单源函数（normalize 打标），推送池/曲线/列表各收集点凭标过滤（存量行与未来形态双覆盖，任何一端漏滤都是「图有列无」或毒价复活的入口），概览对过期日期渲染「停采」徽标让静默自解释。守卫落地前先做全库错位分布预演：错位只应出现在滚动期组合，正常期零错位才允许上线；测试样本的元素日期必须跟随行日期走——老样本「元素日期不随行」的构造疏漏会被该守卫当场抓获，那不是误杀是样本病。

### 10. 钟面差模回绕在「真值可跨过模周期」时系统性失真：量纲重建要带日期维度
两段航段的钟面差 `(二段起飞−首段到达)%1440` 处理衔接停留时，对「隔夜衔接」（真值 <24h）与「跨日长停」（真值 ≥24h）共用一条公式——后者钟面差本就落在 [0,1440) 内，模运算不产生任何异常信号，真停 24:05 被落成 0:05，衔接筛选把它当「不足下限」保守误剔、展示词面直接读错；而「跨度 ≥2 天且差值 <5h 弃算」类窄守卫只挡走极端带，恰好 1 天跨度的 24h± 停留从缝里漏网。**根治形态是量纲重建带日期维度**：渠道分段级 date 键是结构化真值（先做在场率实证），真实量纲=起飞日相对到达日的天数差×模周期+钟面差；键的语义用「首段到达日 ≤ 二段起飞日 ≤ 整体到达日」逐行验证，验证不过/键缺/解析败一律退回旧钟面形态（真值 <模周期 时两法数学等价，存量行为零变化）；钉值再与渠道自带的时长词面逐分互证（第三方信号）。判别「哪些计算存在此盲区」的口径：凡模运算参与真实量纲重建（`%1440` 分钟、`%24` 小时、`%100` 分位），都要先证明值域上界 < 模周期——证不出来就补日期/高位维度，靠窄区间守卫补丁只是把失真面从首收挪到过闸（样本门槛案同构）。

## 二、钉钉推送

### 1. -1 "系统繁忙"存在幽灵送达
报错但消息实际入群——**任何重试都可能造成用户收到两条一样的消息**。且 markdown 消息**聊天窗口不显示标题**，重试标记放标题用户看不见。
**终局原则：防重复优先于防丢失。单发不重试，丢失由下轮心跳自然补，关键警报走独立通道（电话）兜底。**

### 2. 手机窄屏排版：每行 ≤20 全角（40 半角）当量
写脚本渲染真实 desp 逐行量宽度（`全角=2 半角=1`；行宽守卫 `_fit_line` limit=40 含线判定，ASCII 真实 advance 高于 1 半角基准的校准口径见十九§13），超宽行必折行错位。KPI 用三行制（价格/参数/仪表各一行）；比价链超 3 渠道只列最低/最高两端（中间价在明细总表图里有完整链）。

### 3. 表格进图片
钉钉 markdown 不支持表格——用 Pillow 渲染表格图直推（分组色带+类别胶囊+达标价格标绿——曾用红与达标行浅绿底语义打架）。高度公式必须与实际绘制逐组一致（漏算一个表头高度=底部内容被裁出画布）。

### 4. 电话/短信通道（免费）
钉钉电话 DING 需专业版（9800元/年）。替代：**阿里云云监控事件通知**（CRITICAL 事件→联系人组电话+短信），Basic Auth+一行 JSON。中文用 `ensure_ascii=True` 纯 ASCII 传输防网关解错编码。达标才拨、去抖（2h 内不重拨、再降≥50 才再响）。

## 三、工程

### 1. Shell 传代码必踩反斜杠折叠
Bash 内联 python/heredoc 中 `\\n` 会被折叠成真实换行断字符串——**同一坑可以连踩三次**。铁律：改代码一律用编辑器工具（Edit/Write），shell 只跑已落盘的脚本。
第 N 变体（再踩实录）：**PAGE/HTML 等非 raw Python 字符串里写 JS 转义**——`'\r\n'`/`'\ufeff'` 被 Python 解释成真实控制字符，JS 字符串源码被拦腰截断、整页脚本失效（症状=所有函数 undefined）。铁律：嵌入 JS 需要控制字符时用 `String.fromCharCode(13,10)`，绝不在模板字符串里写反斜杠转义。

### 2. `;` 链会吞失败
`a && b; c; d` 中 b 失败后 c/d 照跑——曾把语法损坏的代码 commit+push。关键链路用 `&&` 串接，或显式 `set -e` 语义。

### 3. 重写代码文件后必须 import 级验证
`py_compile` 只查语法，**误删函数要 `from x import 具体名` 才能暴露**（曾误删 `build_notifier` 导致进程启动即崩两次）。

### 4. BlockingScheduler 的实例引用要用模块级
`start()` 永久阻塞，任何 `return sched` 都不可达——模块级 `SCHED` 变量在 start 前赋值，热重载时才能 reschedule。

### 5. 热重载不重新 import 模块
新增/修改类后必须重启进程；热重载只重建配置对象。

### 6. 推送类改动验证：等自然轮，不手动触发
调试期连环重启+手动触发=1 小时 5 轮推送轰炸用户。启动加节流（上轮<5min 跳过首轮）。

### 7. Windows 换行/编码
PS1 中文脚本必须 **UTF-8 BOM + CRLF**（PS5.1 无 BOM 按 GBK 解析全乱码）；`$ErrorActionPreference=Stop` 下 git 的 stderr 正常输出会触发终止——git 调用段临时降 Continue。

### 8. GitHub 资产名 ASCII、上传要 Content-Type 与大超时
中文资产名会丢参变 default.zip；上传 API 必须 `Content-Type: application/zip` + `httpx.Timeout(write=300)`。

### 9. push 后必须远端终验
管道截断的 push 输出不可信；仓库重置后第一推必须 `-u`（无 upstream 时裸 push 静默失败、提交全部积压本地）。

### 10. 代理环境trust_env=False
图床/钉钉/ntfy 等直连域名走系统代理会被随机掐断（EOF in violation of protocol）——`httpx.post(..., trust_env=False)` 一律直连。

### 11. 批量替换同名单调用点，先枚举每处作用域
同一 API 在多通道文件里同名同签名（如 `_append_push_history(title, desp, ...)` 在 ServerChan/钉钉/邮件三通道各有一处），无脑全局替换会把「变量名恰好同串、作用域里却不存在该变量」的调用点一起打炸——某通道 send 作用域里根本没有 `text` 变量，替换后 `NameError` 只在该通道真实发送时才引爆（编译期 py_compile 查不出局部名错误）。修法：替换前先 grep 全部命中点、逐处核对新变量在该作用域真实存在；或用带上下文锚的精确替换。**发送链的局部 NameError = 该通道整轮静默断推，聚合层只看到单通道 False。**

### 12. 改方法绑定（staticmethod ↔ 实例方法）前，先枚举「类名直调」形态
测试里大量存在 `Crawler._parse(Crawler, text)` 的类名直调形态（借类名省实例化）。方法从 staticmethod 改为实例方法后，类方法体内 `self._helper(x)` 在 self=类的直调语境下退化为 unbound 单参调用——报「missing 1 required positional argument」，炸面遍及全部直调测试（数十用例齐红），而实例化调用的新测试全绿，两态分裂极具迷惑性（手动 python 正常、pytest 齐红，还会被误判成 pyc 陈旧）。**改任何方法绑定前 `grep "Cls\\._method("` 枚举直调面；绑定敏感的 helper 需要日志时用模块级 logger 而非 self.logger。**

### 13. 带行首缩进的行做批量替换，匹配的是「行尾子串」：多缩进层级的同构块先逐处核对层级
同文件两个函数各有一份镜像逻辑（直飞路径与中转路径）时，批量替换按「带缩进的行文本」匹配，实际命中的是更深缩进行的**尾部子串**——12 空格锚能命中 20/24 空格行的尾部，插入行按锚的缩进落下，深缩进位被插进浅缩进行：轻则 IndentationError 当场暴露，重则层级悄悄漂移（如复位语句落到循环体外，守卫静默失效）。**镜像同构块做批量替换前先 `grep -n` 列出全部命中点并核对各自真实缩进层级；层级不唯一时逐处带上下文锚精确替换，不用全量替换。**

### 14. if/else 两分支共享的「汇合行」最怕被编辑吞进末分支
分支汇合后的单点赋值（如 `l1 = _fit_line(forms[0], fallbacks=...)` 同时服务两个尾注分支）在编辑替换时被按「末分支体内的缩进」抄写，共享行就被吞进末分支——另一分支从此不绑定该名字，`UnboundLocalError` 只在失绑分支的运行路径引爆（恰有该分支的行为测试当场抓获；无分支覆盖的钉面会静默漏到生产）。**编辑跨分支共享行后，diff 对账「该行缩进层级是否变化」是 30 秒可做的防线；全量测试套（分支覆盖齐全的行为钉）是这类回归的唯一兜底——改共享控制流先跑全量再继续。**

### 15. 测试脚本的「中断」必须参与退出码：except 分支只写报告 = CI 假绿
UI 自检脚本中途抛异常（元素脱附/超时/浏览器崩溃）走 except 分支时只把「中断于异常」写进结果文件、不置任何标志，退出码判定只看「失败断言数/JS 错误数」——中断发生时这两者常常为空，脚本以 0 退出，CI 按全绿放行：**中断（部分断言未执行）被吞成全绿，漏测面完全不可见**（实录：单跑中断退出码仍 0，与历史全绿结果文件混在一起无从分辨）。**失败路径与成功路径在退出码上必须可区分：except 分支置中断标志并参与退出码判定；中断、断言红、JS 错是三种独立失败源，任一非零即非零退出。**附带信号：结果文件尾部出现「中断于异常」字样但退出码为 0，即为本案实锤。

### 16. 动态词面进带参 logger 调用前先问格式化语义：裸 % 被二次格式化=消息静默消失
带参日志调用 `logger.info("[连续%d日] " + msg, cnt)` 会对拼接后的 msg 再做一次 percent 格式化——词面含裸 `%`（如「<10%」）时该分支抛格式化异常，logging 把它当 handler 错误静默吞掉（stderr 打 "--- Logging error ---" 噪音、消息不落盘），且只在「带参分支」（如连续命中计数）显形：首日报警分支不带参常年绿，缺陷潜伏到第 3 日连续命中才现身。**动态拼出的词面一律经 `%s` 参数传入（`logger.info("[连续%d日] %s", cnt, msg)`），不让它参与格式化模板；冒烟钉要同时验「新形态落盘 + 旧形态（变异）不落盘」双证，只验新形态绿证不了缺陷存在。**

### 17. 「启动/首轮」语义的守卫必须绑定进程生命周期，不绑数据状态
把「进程启动后的首轮跳过（连环重启不轰炸推送）」实现成调度 job 入口的每次检查（查「上轮落库距今 <5 分钟则跳过」）——长周期下触发时刻距上轮完成恒大于窗口，守卫从不拦截，缺陷潜伏；扫描周期缩短到与扫描时长同量级后，每个对齐点都落进窗口，守卫逐轮拦截，实际轮距被拉长一倍以上，用户配置名存实亡。**凡带「启动/首轮/一次性」语义的守卫，用进程生命周期标志（首触发后耗臂）实现，不用「每次触发重查数据状态」模拟——数据状态是周期的函数，周期参数一变，守卫的命中面就整体漂移。参数变更评审的隐性面：所有「按数据年龄判断」的守卫都要按新周期重演一遍命中分布。**

### 18. 显式接力驱动的调度器，接力分支不得带参数条件：档位 0 值是参数域的一部分
调度 job 以 paused（next_run_time=None）创建、「下次触发」靠每轮回调末尾显式排定时，若排定动作包在 `if 扰动>0` 之类的参数分支里，参数取 0 的合法配置档即无人排定——调度器永久静默且零报错（进程活着、端口在听、就是永不扫描）。历史配置恒带扰动所以从不显形，扰动归零（用户要精确间隔）当轮即死。**「驱动源必须无条件执行」：档位退化值（0/空/关）是参数域内的合法输入，不是可以跳过驱动的空档；档位分支只允许改变驱动的参数，不允许跳过驱动本身。这类缺陷的复现测试造真调度器不 start、直接调排定函数断言 next_run_time 非 None。**

### 19. 守卫消费自身上一轮的写入产物=自指污染：先复位再判
过滤函数的「跳过不可见行」守卫若按 computed display 判定，无法区分「样式表 !important 藏住（inline 复位压不过）」与「上一轮本函数自己写入的普通 inline none」——命中判定在前、inline 复位在后时，前轮被藏的行本轮即使命中也在复位前被 return，顺序查询第二轮起假零，直到清空路径全量复位才复活。**交互函数写入的临时态，下一轮进入时先无条件复位再判定（复位普通 inline 后仍 hidden=真 !important 档）；守卫的判定对象必须是「复位后的状态」，不是「上一轮结束时留在 DOM 上的状态」。**

## 四、UI 与可读性

### 1. 对比度用公式不用目测
弱化灰 #8a99a8 在白底仅 2.8:1（WCAG AA 要 4.5:1）。定色跑对比度计算：正文≥7、次级≥4.5、白字彩底≥3。

### 2. 底色中性化，彩色只留语义
带蓝调的灰底（#f0f3f7）与白卡片、蓝主色三层蓝叠=割裂感。背景用无色相灰阶（B-R 偏移≤4），蓝只出现在按钮/选中/数据。

### 3. 暗色模式三雷
- 媒体查询改 data-theme 时 `:root{}` 嵌套进选择器会失效——变量要提升到选择器本体；
- 逐元素排残留硬编码（table background:#fff 这类）要用脚本扫 computed style 清零，不靠眼睛；
- 内嵌浏览器可能不传系统偏好——加手动三态切换（自动/亮/暗，localStorage 持久）。

### 4. 多租户配置界面必须显式呈现实体边界
平铺长表单看不出"用户"——折叠用户卡（名字+航线数+推送状态头部）是底线。

### 5. 全配置热加载
"部分项需重启"是架构不完整。调度周期用 `reschedule_job` 热更，用户/阈值/通道走对象重建。

### 6. canvas 像素层文字是 DOM 对比度扫描的结构性盲区
全元素对比度扫描（TreeWalker 遍历可见文本节点）天然看不到 canvas 里 `fillText` 画的字——图表最低价标注这类「画布上的正文」沿用图形档色令牌时，欠 AA 缺陷躲过全部 DOM 层扫描长期在册。审计口径补第二通道：对绘制代码的 `fillStyle` 消费点逐个走读、按 WCAG 公式算术复算。复算时底色取「文字实际衬的那一块」（标注常有白 halo 衬底，不是画布本身）——图形档令牌对卡片底过线不等于对 halo 块过线。「同一语义两档令牌（图形档/文字档）」体系里，canvas 文字消费点一律挂文字档；计数钉锁消费点数量，防后续新增绘制点回退图形档。

## 五、产品

- **丢失可补，重复扰民**（不可靠通道重试设计的唯一正确取向）
- **渠道覆盖看供给重合度**：美团/智行无 H5 攻击面且供给与携程系重合，放弃；性价比是判断标准
- 每次发版前跑回归测试（含"未达标零触达电话"这类守卫场景）——守卫类逻辑没有测试固化，迟早被重构吞掉
- **键名推断不构成口径变更依据**：无文字实证的语义假设（某标记是否会员专享价）直接改计价口径是拿数据准确性赌博——先落透明标记让受众自判，证据到手再动口径。改向代价要预演双侧：把不可购价当真值产生幻影达标（误报电话），比把促销价排除错失优惠伤害更大

## 六、渠道废弃与复活实战

### 1. 接口被封时先找 SSR 页面
移动端 MTOP 接口被官方下线+新版强制登录看似死路，但 **PC 搜索结果页可能是服务端直出**（数据在初始 HTML 里，无接口无登录）——用 Playwright 滚屏收集 innerText + 行状态机解析即可复活。数据在初始 HTML 里比想象中常见。

### 2. 用户随手给的真实 URL 是最高价值情报
自己猜入口 URL 探测十次（flight.fliggy.com 空壳/www 超时/m 端登录墙），不如用户贴一次日常使用的真实链接。**渠道故障时直接问用户'你平时在哪个网页查'**。

### 3. 跨天时刻行是解析器杀手
到达行带后缀（"01:25 第2天"）不匹配纯 HHMM 正则 → 卡片错位连锁（吞首卡+把下一卡时刻接到上一卡）。时刻类字段一律允许行尾后缀，解析完做"dep<arr 或跨天"自洽断言。

### 4. 渠道废弃的完整决策树
废弃确认（官方 NOT_SUPPORT 实锤）→ 三路探测（新版本号/移动端新页/PC 端）→ 全断则即检即断降级（0s 跳过省时间）→ UI/推送标注"维护中"管理预期 → **留复活探测钩子**（重启重探，恢复自动自愈）。

### 5. 多查询架构下的平台唯一性假设要全面升级
"每平台取一条明细"的去重在多航线（一轮多查询）下吞数据——所有 平台级 唯一键（去重/最低价/chart 缓存）都要升级为 平台+航线+日期。同类 bug 一次重构全部排查，别修一个漏两个。

### 6. 价格口径要在渠道接入时标注
飞猪 PC 是不含税展示价（与含税渠道差 50-130）——渠道接入第一天就确认计价口径并写进 docstring，否则比价长期偏优误导决策。

## 七、TDD 纪律（自查纠偏）

> 用户指出后自查：近 20 轮迭代全部"改完→真机验证"，零个先写失败测试——违反 Iron Law（没有失败测试就没有生产代码）。本节为纠偏记录。

### 1. 真机验证 ≠ 复现测试
真机只能证明"这次好了"，不能证明"再坏时会被抓住"。回归防线必须是一跑就红的自动化用例。

### 2. 补欠账的诚实做法：变异验证
理想 TDD 是看着测试失败再修；已上线的代码补测试时，用**变异验证**等效：注入原 bug 形态 → 确认测试变红 → 还原复绿。证明测试具备抓该 bug 的能力（本轮 3/3 变异被抓）。

### 3. 补测试当场抓到两个真 bug
- `arrDate` 带时间尾巴（`YYYY-MM-DD 00:00:00` 形态）——下游 strptime 前 10 位侥幸没炸，schema 暗病
- fliggy `_RE_FNO` 不认数字开头二字码（9C 春秋/8L 西藏/3U 川航）——qunar 版修过的坑重写时忘了，**生产正在丢春秋全部航班**
这就是"tests-after 有偏"的反证：不写测试，你以为修完了。

### 4. 难测 = 设计问题（听测试的）
轮聚类逻辑埋在 `_user_state` 大函数里无法单测——提取为纯函数 `_cluster_round_rows(rows, gap_s)` 后 3 个用例立即可写。每次"不好测"都是重构信号。

### 5. 今后纪律
- bug 修复：先写复现测试看它红，再修
- 新功能（可测部分）：测试先行
- 每次提交前：`tests/` 全绿

### 6. 测试隔离在「根治层」收口：autouse 夹具防下一颗漏网，个案补钉防不住
测试触达真实写盘路径（如推送落账 JSONL 按环境变量重定向）时，逐用例补隔离钉注定漏——新用例照抄邻近无隔离的样板就复发，合成数据静默混入生产账本（现象：控制台推送记录里出现测试航班号/假价，生产 DB 却无对应行）。**根治层是 conftest 的 autouse 夹具：整个会话级重定向，显式 setenv/delenv 的用例按 monkeypatch LIFO 照常自覆零冲突**；历史用例里「写读同锚」的读路径断言要随重定向改读环境变量路径（只补写侧不补读侧=FileNotFoundError 假红）。判别哪类用例需要隔离的口径：凡走到真实 send/落账链路的用例（含"空转也落账"的记账分支），无论主断言是什么都在隔离面上。

autouse 的防护边界止于 pytest 入口：**python 直跑的重放/调试脚本、`-c` 内联调用绕过 conftest，隔离形同虚设**——渲染定律重放与 bug 复现脚本的落账曾两段成批混入生产账本（合成记录形态、bug 期密集落账形态各一段），且「monitor.log 同窗口无对应轮次」是甄别污染的铁证（真实轮必有三通道齐发）。根治层的完整形态是**写入端生产资格门**：未显式设重定向变量时，只有生产形态进程（frozen exe / main.py、webui.py 入口）可写默认账本，其余进程静默拒写——「显式重定向永远放行」的原契约保留，压测/探针脚本设变量落独立账本不受影响。「默认路径行为不变」类钉随门改写 argv 模拟生产形态，语义担保（生产进程写默认路径）不丢。

第二落点（状态文件家族）：落盘型全局状态是「双通道污染」——不只是「漏补丁用例直接落盘」，还有**模块级内存态跨测试残留**：前序用例写入的合成告警态留在全局 dict 里，后续任一漏补丁用例的「全量落盘」会把前序合成态一并带进生产文件（键集逐一吻合是归因铁证）。根治层夹具必须同时重定向路径+清空内存态；钉面三件套=「路径已重定向出仓库」「内存态新鲜」「端到端写盘防护（生产文件字节不变）」。构造端到端事故形态时先清内存态——否则存量「当日已报」记录让告警链首行短路，测试假绿还以为防护在位。

诊断动作自身的污染面：**复现实验与它诊断的对象用同一个生产面时，复现即二次污染**——诊断「测试残留写脏生产状态文件」的复现脚本若漏打重定向补丁，会以全新内存态再写一遍生产文件（mtime 与内容日期双证：文件里的日期串晚于被诊断的污染事件=诊断者所为）。声称「全程未动生产文件」必须以动作前后的 mtime/字节复核收口，不能凭意图；诊断报告的红项定性前先排除「自己的探针就是写入者」。

## 九、登录态体系（游客限流通病解法）

- 未登录 = 游客态，各渠道风控阈值严苛（途牛 179991、携程 IP 灰名单、qunar 限流窗口更长）。
- 解法：`--setup-login` 五窗齐弹（**桌面视口**——手机模拟下鼠标拖滑块失灵，页面监听 touch；cookie 同域通用）。
- 用户本地 Chrome cookie 不可迁移：新版独占锁 + App-Bound Encryption（Google 2024 加固，实测复制都拒）。
- 登录引导页用**用户熟悉的官网首页**而非 passport 页（用户点右上角登录更顺）。
- 渠道被风控 → 推送"无数据"提示 + 建议跑 `--login <plat>`。

## 十、钉钉双端渲染与单实例纪律

### 1. 钉钉换行双端不一致：PC 不认单 `\n`，手机认
同一条 markdown：手机端 `\n` 正常换行，PC 端把相邻行**粘成一行**随文本折行——进度条因此和参数行粘连、被腰斩。终局解法：**所有需要换行的位置一律段落级 `\n\n`**（价格/参数/仪表三段、⚠️ 行、页脚），列表项交给 `- ` bullet（两端都安全）。写推送时别再用裸 `\n` 假设两端行为一致。

### 2. U+2026「…」在钉钉渲染成。。。。
比价链里省略中间渠道的「…」实锤显示成"。。。。"（用户截图确认）。禁用：超过 3 家只展示最低/最高两端。同族结论：**钉钉正文只用确定安全的字符集**（→、｜、￥、emoji 常规款、连接号 en dash「–」）；生僻 Unicode（▓░、…）都出过事。**派生文本同受本律**——降级链/兜底档是逐档新写出来的正文，新增 fallback 时每一档单独过一遍字符集再上线（图挂兜底头行降级第二档「- …航班号」的省略号同样实锤成。。。。，且随 desp 同源进短信与 TTS）。安全集成员以真实渲染实证在册（长期实发零事故即成立），与「现行文案是否仍产出该字符」无关——在册是给未来新词面的选字依据。

### 3. emoji 进度条格数上限：5 格
🟦⬜ 是宽字符，10 格在窄屏必折行破坏完整性（截图实锤 7+3 腰斩），5 格稳定单行。设计仪表条类元素先量宽度：宽字符 emoji 按每格 2 全角当量算，5 格=10 当量是安全上限。

### 4. `--login` 残留进程 = 旧代码僵尸监控（头号大坑）
`main.py --login <plat>` 在终端里跑完登录后，终端不关进程就不退（input 等待/落调度循环），**带着旧代码内存镜像并行跑完整监控**：旧格式推送混进群里、与正式实例双监听 8765、DB/日志互踩。症状：**改完代码部署后推送"忽新忽旧"**。
排查三板斧：
1. `Get-CimInstance Win32_Process`（注意 CommandLine 为空的高级进程会被 `like '*main.py*'` 过滤漏掉，按创建时间兜底对账）；
2. `netstat -ano | findstr 8765` 出现**两个 LISTENING PID** 即双实例实锤；
3. 日志里 `[启动]` 行出现次数 ≠ 已知重启次数，按时间戳对账。
纪律：**只允许一个监控实例**；改版后验证要看"最新一条推送"由哪个进程发出（debug/last_push.md 的 mtime 对日志时间戳）。磁盘代码是对的但推送还是旧格式 ⇒ 必有旧进程活着，先查进程再查代码。

### 5. qunar 间隔终值：8s + 去末尾空等
登录态连续零失败后 MIN_GAP 12→8 安全落地；更大的隐藏浪费是 `_fetch_inner` 每个日期后的 `_sleep()`（配置 5-15s）——末条日期后的等待是纯空转（fetch() 的 MIN_GAP 已兜住礼貌间隔），只保留日期间的 _sleep。单轮 qunar 净省约 1 分钟。

### 6. 钉钉 -1 高发日的表现
同日多次 `{"errcode":-1,"errmsg":"系统繁忙"}`，消息实际入群（幽灵送达）——单发不重试策略正确，勿因高频 -1 加回重试。

### 7. 页面级 JS ReferenceError 被 fetch 的 catch 吞成「服务未启动」
控制台曾长期半瘫：渠道角标之后全部不渲染（表格空、走势图空白），页头却显示「服务未启动」——真相是 buildChips 引用了未定义的 `MAINT` 常量，render() 抛异常被 load() 的 catch 吃掉，错误语义完全误导（服务明明正常，数据都在）。
教训：
1. **fetch 链路与 render 链路分开 try/catch**，渲染异常要显式暴露（console.error + 页面提示「渲染异常: …」），别让两类故障共用一个含混文案；
2. 前端无构建链（纯 HTML 字符串）没有语法兜底——改完必做两步验证：`new Function(脚本全文)` 查语法 + 页面内手动调 `render()` 捕获运行时错误；
3. 「功能消失但页面还活着」优先怀疑 JS 半途抛错，其次才是服务问题。

## 十一、控制台"虚报达标"与交互卡顿

### 1. 聚合 KPI 的阈值必须随最优航班所属航线（两层坑）
用户截图反馈"虚报"：控制台显示"直飞 ￥1760（线 ￥1900）✅ 可出手"，但 1760 是乌→上 10/04 的价，那条线是 1600——**全局最低价配 routes[0] 的线**判达标。修完第一层又暴露第二层：`route_by_pair` 按城市对索引，**同城市对不同日期互相覆盖**（10/04 的 1600 被 10/05 的 1900 盖掉），逐行 qual 判定同样中招。
终局修法：① best 简报带 `th`（该航班所属航线的阈值），前端标签/进度条/文案全用它；② 航线索引键 = `(from, to, date)` 精确匹配、城市对兜底；③ pill/标题用逐行 `any(f.qual)`（与推送同语义）。这是六.5"唯一键带日期维度"家族的第三起——**每次引入聚合展示都要全链路排查索引维度**。

### 2. 行交互禁止全量重建表格
600+ 行表格每次点击行都 `innerHTML` 全量重建（100-500ms 卡顿感）：展开/收起改**外科手术式 DOM**——只 `insertAdjacentHTML`/`remove` 一个 `<tr>`（实测 4.2ms/0ms）。通用律：交互反馈路径只动增量节点；全量重建只留给排序/筛选这类结果集真变的操作。

## 十二、热加载的最后一环与缓存签名

### 1. 热重载换的是"对象"，闭包捕获的是"快照"
`reload_config` 里 `cfg = load_config(...)` 让 main 作用域看到新 dict，但 `make_sweep_job(cfg, ...)` 的形参是**另一个绑定**，仍指启动快照——爬虫超时/错峰/UA、日报时刻、图床配置热保存后静默不生效（headless 清了缓存，重建实例读的还是旧 dict）。铁律：**跨热重载的可变配置必须走单一事实源容器**（本项目的 `rt["cfg"]`），闭包/长生命周期函数一律从容器现读，不持有 cfg 形参直引。

### 2. 缓存签名禁用 `id(对象)`
给 `/api/state` 加签名缓存时若用 `id(st.users)`：热重载释放旧 list 后新 list **很可能分配到同一地址**（CPython id 复用），新配置撞上旧签名 → 改了阈值页面纹丝不动。用内容摘要（users 的 JSON 哈希，dataclass 经 `default=str` 进 repr）或显式代数递增，不用对象身份。

### 3. "外科手术式 DOM"仍会被扩展击穿：点击路径要零 childList 变更
用户实测"每点一行卡数秒"但干净 Chromium 探针全绿（JS 0ms/零长任务）——真凶是**翻译/比价类 Chrome 扩展监听 MutationObserver，任何 childList 插入都触发全页重扫**，652 行表格上每次"插/删一个展开行"都被放大成秒级卡顿。终局修法：展开行改为**渲染期预置隐藏行（display:none），点击只切 display**——childList 零变更（attribute 变更不在默认 Observer 过滤内），预置成本仅每行一个空 tr。通用律：面向用户浏览器的页面，交互路径避免任何节点插拔；"只插一个节点"的优化在扩展面前不算数。

## 十三、渠道 PC 化：方法论与证据

### 1. "token 刷新成功但接口 1999" = 接口级风控升级，别在 token 上打转
qunar H5 的 Bella token 每轮都成功刷新（长度 911）却 121 连拒 1999——**风控升级发生在接口校验层，与 token 新鲜度无关**。判据：拦截到的请求带合法 token + 响应仍是风控码 ⇒ 换路径（换端/换接口），不重试、不逆向新校验。

### 2. 同族接口的 PC 版结构差异清单（qunar wbdflightlist 实测）
H5 touchInnerList 与 PC wbdflightlist 同族但有三处不同，照搬 H5 解析器必错：
① `data.flights` 是普通数组（H5 是字符串化 JSON）；
② **中转整体到达时刻在 `binfo2.arrTime`**（binfo1.arr 是中转段到达——H5 的 binfoX 语义不同）；
③ 无 `mixFlightName`，显示名用 `binfo.shortName+airCode` 拼；直飞时长在 `binfo.flightTime`（"5h30m" 需转 "5时30分"）。
另：Python `str.format` 里 `{from}` 是非法占位符（关键字参数），模板命名避开关键字。

### 3. 渠道 PC 化要"逐渠道定证"，不是一刀切
- **qunar**：H5 死 ⇒ PC 必换（救活，72 条明细实测）；
- **ctrip**：PC 版 302→432 风拒 ⇒ 保留 H5（登录态路径），改动即打破现状；
- **tongcheng**：PC 接口 getflightlist 带易盾 openDun、无头下列表卡片不渲染、价格口径未证实（日历价 2600 与 H5 存量一致 ⇒ H5 口径正确）⇒ 保留 H5，路由/接口/响应证据存 debug/tc_pc_list.json 备查；
- **tuniu**：无独立 PC 机票页，纯 httpx API 性能最优 ⇒ 保留；
- **fliggy**：PC SSR 直读，本就是 PC。
通用律：**"以 PC 为准"的正确姿势是给每个渠道拿证据做决策**——能救活的救活（qunar），已优的保留（tuniu/fliggy），有疑点的存证不动（tongcheng/ctrip）。SPA 404 页返回完整壳 ≠ 路由不存在（前端路由接管）；同程 PC 路由从 JS bundle 里 grep `itinerary` 得来（/flights/itinerary/oneway/:code，少个斜杠就是 404）。

### 4. CLI 交互搬进 Web 的关键：把"按回车"换成"事件置位"
--login 的本质是"有头持久化上下文 + 阻塞等用户信号"。搬进网页登录时无需重写浏览器逻辑——`_login_window(done_evt)` 本就吃 Event：Web 层只要 `POST /api/login` 起线程弹窗、`POST /api/login-finish` 置 Event 即可，会话保存/窗口关闭全部复用既有链路。注意两点：① user_data 是 Chrome profile 独占锁——采集进行中弹登录窗（或反之）会 Profile 冲突，靠 safe_fetch 自吞 + 健康条纹可见，UI 文案提示"采集进行中稍后再试"；② 会话落盘后**下轮采集自动生效**，本就热加载，无需任何刷新机制。

### 5. 发版流程的两个隐形坑
① **版本号 bump 必须与功能改动同批**：tag 写了新版本而 main.py 内嵌版本还是旧的 → 页脚/测试推送显示旧版，"tag 与运行版本不一致"。bump 放进发版批次的第一个动作。
② **目检前先杀旧演示服**：8799 被旧进程占用时新演示服启动即失败（_Srv 禁复用会抛错但后台 `&` 吞掉），浏览器连到的是**旧代码页面**——"改了没生效"的假象。目检脚本开头先按端口清进程（同 uitest 的 free_port）。

## 十四、骨架级重塑：长页→工作台/面板

### 1. "换汤不换药"的根因：只做 cosmetics 不动信息架构
配置页多轮质感迭代（分区骨架→登录卡/参数格/通道卡）后用户仍一句"一直都是大长页"点破——**表单再精致，堆成一条长滚动就是工具页，不是产品页**。设置类页面的产品级形态是"左导航=视图切换器，同屏只显一个分区"；监控类页面是"常驻英雄区+子视图 tab"。改骨架一次胜过改样式十次。

### 2. display 切换的三个连带坑（一次全踩，一次修完）
① **canvas 在隐藏容器里 offsetWidth=0**：chart() 开头加 `if(!c.offsetWidth)return` 跳绘，tab 切回时显式重绘——否则画出 0 尺寸废图或切回后空白；
② **徽标随面板隐藏**：cfgDirty 在用户面板工具行里，切到全局面板后 is_visible=False——"守卫失效"其实是断言看错了地方，守卫状态以常驻 savebar 为准；
③ **锚点断言假绿**：`cnav[data-t=sec-globals]` 指向不存在的 id（实际叫 sec-globals-card），getElementById 返回 null 被 if(t) 静默吞掉，而 scrollY>80 于是前文内容残留恰好为真——**跳转类断言必须先回零位再断言目标入视口**（或直接改断言切换后的可见性）。

### 3. 可观察性数据要在采集现场取，别从日志倒推
健康时间线解析 monitor.log（文本、轮窗口猜、维护态锁存），脉冲则直接在 sweep 的 futures 包装处计时——`_timed_fetch` 一行拿到每渠道行数/耗时，Pulse 环形缓冲进程内即弃。**结构化数据在产生点捕获，日志解析只留给历史**（没有脉冲前的轮次）。

### 4. 搜索过滤与视图切换要互相成全而不是互相打架
面板化后搜索面临"命中的字段在隐藏面板里"的矛盾——解法：**搜索态临时展开全部分区（只留命中字段+命中计数），清空即还原单面板**。二者共享 display 切换原语，互不打架。凡"过滤/导航/切换"类功能叠加，先画清楚各自控制哪一层 display。

### 5. 推文详情链接复用同一份存档
Windows 弹窗 launch 与钉钉"完整详情"共用 `_archive_notify` 返回的 /notify/{nid}——**存档先行，链接后拼**（desp 在进 _send_urgent 前追加链接，随后钉钉主推/风暴同一 desp 自然携带）。一处存档，三端（弹窗/群消息/详情页）同源。

### 6. netstat 输出被 PYTHONUTF8 强解崩掉读线程
`subprocess.run(text=True)` 在 PYTHONUTF8=1 环境用 utf-8 解 GBK 的 netstat 输出 → UnicodeDecodeError 在 reader 线程里炸。**外部命令输出一律字节捕获 + errors="ignore" 解码**（只要匹配 ASCII 关键字就安全）。

### 6. 渠道 PC 化是"半程迁移"重灾区：爬虫换了，用户链接没换
qunar 爬虫迁到 PC wbdflightlist 主路径后，`_build_view_url`（推送价格链接/控制台 ↗）仍指 touch H5——接口风控死页，用户点开"挂羊头卖狗肉"（用户实报）。**任何渠道路径迁移，必须全仓 grep 该渠道 URL 并清点"给人点的链接"**；正确姿势是链接与爬虫同源（爬虫在哪拿到数据，人就跳到哪页）。webui `_view_url` 助手统一出口，并按航班数据来源渠道出链而非一律 qunar。

### 7. "一切可配置"的诚实边界：热载与启动级要如实标注，别假装
把 config 全量键暴露进控制台（/api/config globals 从 4 键扩到 13 键）。关键纪律：**每一项都标真实生效方式**——热载的标 🔥（保存即生效），启动级的标 ♻ 只读展示（db/log/user_data_dir，改 config.yaml 后重启），半热的写清生效时机（run_on_start="下次启动生效"）。产品话术统一说"全部热生效"而不标注例外，就是在制造下一轮"我改了为什么不生效"的信任透支。配套：每个通道一个真实测试按钮（钉钉/ntfy 用表单值实测、Windows 弹窗真发一条），让"配置对了"变成可自证的事实，而非信仰。

## 十五、僵尸演示进程、坏根提交与剥离函数的箭头陷阱

### 1. 会话遗留的 --demo 僵尸：截图与探针的"全链路假象"
上次会话的 `python webui.py --demo --port 8799` 僵尸进程活了两天，README 截图脚本与预览探针全部打到旧代码——预览弹「本轮数据为空」、走势图空白，每个症状都能在当前代码里"对上号"，极具迷惑性；而进程内同路径复现却全绿。**起 demo / 跑 screenshot.py 前先 `netstat -ano | grep :端口`**；同端口重启时新进程 10048 静默退场、旧进程继续应答，"重启了还是旧行为"先看 bind 失败日志。会话收尾杀掉自己的 demo。

### 2. 提交信息会撒谎，树不会：发版终验必须抽查树内容
曾出现"提交信息写新版本、树却是旧版本时代内容"的坏根提交（add 不完整时 commit 照样落盘），且 Release 照常建出、挂了一整天。**三件套终验之外加一条：`git show HEAD:main.py | grep __version__`**（或 API 对比关键文件 blob）——提交信息、tag、Release 存在性都可能"对"，只有树内容是事实。资产对、仓库错也可能并存：exe 从工作区打包 ≠ 提交树。同族延伸：**`commit --amend` 的 stat 输出同样不可当树对账口径**——amend 汇报的「files changed/create」可能包含与树真实差异无关的条目，两棵树的唯一真相是 `git diff <旧hash> <新hash> --stat`；对账、终验、接力收编一律以树对树 diff 为准，不读命令的汇总输出。

### 3. emoji 剥离函数的反向陷阱：它连箭头一起剥
`_no_emoji` 的剥离区间含 `←-⇿`(U+2190-21FF)，`→` 正在其中——拿它"顺手"清理含箭头的拼接文本，会把「08:30→13:50」剥成「08:3013:50」。**剥离函数只用于确定含 emoji 的调用点，且要知道它的区间边界**；结构化数据（dict 字段）比预拼字符串更安全——比价行因此从预拼文本改为结构化渲染，emoji/截断两个问题一起消失。

### 4. 语义正确 ≠ 观感正确：达标仪表的全空格
破线类别的进度条渲染全 `⬜`（超线 0% 的数学正确结果），用户看到的是"一格都没填=没数据"。**边界态的视觉表达要按"读的人脑中先问什么"设计**：达标态下人先问"能不能出手"，于是 🟩 满格 > 空格；图例同步一句「🟩 满格 = 已破线可出手」。

## 十六、质感迭代的普适律

### 1. 组件样式进容器先查"谁会误伤我"（CSS 优先级覆盖）
全局参数卡 `.glcell input{width:100%}`（特异度 0,1,1）压过组件 `.switch{width:36px}`（0,1,0），checkbox 被拉成通栏宽条、同行文案被挤成一字竖列溢出卡外。修法 `:not(.switch)` 排除。**往带元素级 width 规则的容器里塞新组件，先查容器选择器的特异度与命中面**。

### 2. 说明文字必须出现在它解释的对象之前（或就近）
进度条图例曾排在钉钉消息全文末尾——读者在第一条航线见到 🟦⬜ 时没有任何解释。图例/图注/图例性说明的位置错误=没有。

### 3. 语义色改值先 grep 全部引用点
`C_QUAL` 一色两用（达标价格 + 比价组头），从红改绿会把比价组红带配成绿字。拆成 C_QUAL（达标绿）/C_CMP（比价警示红）两个语义常量。**改任何语义色/语义字段的值，先枚举引用再分派**。

姊妹律（提亮/降档类"批量改色"规则的射程）：为对比度做「容器内全部子元素统一提亮」类规则（如暗色达标行内次级小字提灰）时，**枚举射程内已有的语义色档并逐档豁免**——「衔接达标」小字是 .ok 绿语义档而非中性次级档，被提亮灰覆盖后跨端失语（推送 PNG 同语义恒绿），且缺陷要等真机 computed 抽查才显形（静态钉只锁字符串在场，锁不住层叠胜负）。反向同理：**新增语义色档时先查它落不落在既有批量规则的射程内**，射程交集必须在落档同轮给出豁免或论证。

### 3b. 几何常量的兄弟消费点：单源变量 + 裸表达式残留计数钉
K 线双系列偏移收紧下限时只迁了蜡烛绘制一处，环标、「低」标锚、命中计数三处兄弟消费点仍手抄裸表达式——窄画布上环偏离所属蜡烛中心，且新注释宣称的「环标互叠缓解」与实现不符（错认知随注释传给下一轮，比不修更糟）。**同一几何/语义常量有多处消费点时先提为单源变量，改动时以「裸表达式全文残留计数」钉收口（count==1 即只剩定义处）**——半迁移在宽档零差异、只在触发档显形，行为测试与截图目检都容易放过。

词面域同族变体：把「补位时长」从裸 `:.0f` 表达式收口为单源词面函数时，**降级链里的 `replace(f"...{:.0f}h前", "")` 剥段表达式也是消费点**——词面改了、replace 匹配串没改，剥段静默失效（不炸、不留痕，只在「该行超宽需要剥段」的触发档显形）。replace 类消费点的匹配串与产出词面必须同出一源，收口后 grep 旧词面字面量至零残留。

### 4. 常态不加状态标识，异常才提示
明细页渠道 chips 的「新」角标（数据 <0.5h）在 15 分钟扫描周期下全员常年「新」——常态可见的状态标=零信息量+视觉噪音。「Xh前」老化、「维护」保留。同理：❌/🚨 emoji 状态与删除按钮 ✕ 视觉相撞（误读成可点关闭），改 .udot 状态点（达标绿呼吸、未达标灰静默）。

### 5. 轻页面必须共享主站主题体系
/notify 落地页只跟 `prefers-color-scheme`，主站手动切暗色后点弹窗进来是亮色——主题体验断裂。head 内联引导脚本读同一 localStorage key 落 `data-theme`（渲染前执行防闪白），CSS 用 `:root[data-theme=dark]` + `@media{:root:not([data-theme=light])}` 双通道。

### 6. CLI 向导的输入校验：正则只验形状不验存在
向导日期 `\d{4}-\d{2}-\d{2}` 放过了「13 月 99 日」这类形状合法语义非法的输入（下游全渠道零数据且难排查）；轮询间隔未验数字（"abc" 进 int() 即崩）；到达时刻不验 HH:MM。**问答式向导每个输入都要 while 循环 + 语义校验 + 友好重试**；城市匹配做归一化（剥「市」）与前缀联想，失败别刷全量列表。

### 7. 演示/静态语境要如实标注运行环境
静态演示站页脚曾写「本地服务 127.0.0.1:8765」——对 GitHub Pages 静态页是误导。凡界面文案提及端口/服务/数据来源，都要过一遍 demo/静态分支（`s.demo` 切换文案）。

### 8. 日报与主推送是两条独立文案路径，要分别审
build_and_push（日报）与 _digest_payload（达标聚合）结构无共享：日报曾缺 H1、航线顺序随字典序跳变、走势图被明细表压后、尾部「生成于」与头部「数据截至」重复。**同产品的多推送类型逐条取全文审**（/api/preview 取真实数据读文本，比看渲染截图更容易发现措辞/结构问题）。

### 9. 「先画终帧再擦除」的入场动画是零视觉产出
入场动画若先把终帧全量画满、再用逐帧 clip 重绘同内容，每一帧都覆盖在同一幅完整画面上——观感是「没有动画」，还白付几十次全量重绘。**动画类改动的行为验证必须采样动画中段的区域像素**：真擦除的中段远端应仍等于旧帧（或空布），随擦除推进才变为终帧；中段远端恒等于终帧=动画不存在。只验「终帧与静态重绘一致」的钉罩不住这类缺陷（终帧本来就对，错的只是过程）。

### 10. 「防 X」联动式的方向要先算目标带边界：取小中轴在目标带恒锁死旧值=修复零实效
高度联动式 `clamp(下限, min(38vh,28vw), 上限)` 意在治「宽短窗画布拉扁」——但目标带（宽视口+短视高）里 28vw 恒大于 38vh，取小恒落在 38vh：修复发版后同带实测与病灶逐字节相同，且取小在窄高窗反向把既有高度砍矮（一支恒大于另一支时，取小的行为=恒取那一支，联动名存实亡）。**联动式落笔前先算各带的边界值表：哪支在目标带恒大、取大/取小各把行为锁在哪支**——「随视口变宽而抬升」的语义只有取大能表达。修复的验收是在病灶带复测**原症状指标**（本案=画布宽高比实测），不是修复点钉绿；「修了没实效」与「修错方向」只能被病灶带的行为实测分辨，且这类修复常反向伤害另一带（窄高窗 342→240），边界带巡检是验收的一部分。

### 11. 齐「线」前先问对偶件与语义轴：窄带的偶然同线不是设计语言
宽屏带两件「左缘差 18px」的审计发现，两种修法方向完全相反（对齐 A 到 B 或 B 到 A），选错方向会把正确的通线布局改破。裁决依据有三：①枚举两件各自所属的**语义轴**——带背景/边框的盒（含裸排的胶囊卡）属于「盒轴」，卡内文字属于「文字轴」，跨轴对齐本身就是结构差不是破口；②窄带里两件「恒同线」可能只是几何巧合（负出血恰好抵消内边距），巧合随带宽消失是必然，不能当设计意图的证词；③**既有钉组是设计语言的执行面**——一组「全部常驻块左缘同线」的钉锁着盒轴通线时，单案审计发现与钉组冲突，先重读钉组语义再动手，修复让钉组齐红的当下就是修法方向错的强信号（行为变对了旧钉不会红）。裁决为「备案不修」时，两修法为何皆新害要写进现场注释，防下一轮审计再立同案。

## 十七、质感终局律

### 1. PNG 文字平整：统一字体，绝不中西逐字符混排
明细总表「数字用等宽 Consolas、中文回退 msyh」的逐字符混排，因两种字体基线/字高/字距不同，渲染结果歪歪扭扭（用户实锤「不要歪歪扭扭的字体」）。**平整压倒等宽**：统一微软雅黑，对齐靠布局（窄列居中/价格右对齐/表头同向），不靠字体切换。`_mono/_draw_mixed/_mixed_w` 全部回退删除。

> 备案例外：WebUI 航班明细的价格列是**首列**且带 🔥/税前等前缀徽章，左对齐与「表头同向」内部自洽——「价格右对齐」标尺出自推送 PNG 总表的价格列语境（尾列、纯数值），两处语境不同各自成立，勿跨语境互判。

### 2. `.gitignore` 的 `_*.py` 会误伤 `__init__.py`
`_` 前缀通配命中 `_init__.py`——crawlers/core 的包初始化文件从未入库，主工作区打包侥幸可用，**fresh clone / git worktree 打包必出 ImportError 空包 exe**。修法：规则改 `/_*.py` 限定根目录 + `git add -f` 入库。改 ignore 通配后用 `git check-ignore -v` 抽查包初始化文件。

### 3. 发行包必须基于提交树打包（worktree 流程）
工作区可能有并行会话的半成品——`git worktree add _rel <commit>` 打包、产物与提交树一致、`git worktree remove` 收尾。打包前 `git status` 过一遍非自己的 M 文件。

### 4. 移动端触控基准 36px，且规则必须声明在基础规则之后
`.mtab{padding:9px 14px}` 写进 ≤760px 媒体查询却无效——`.tabs span` 基础规则声明在文件更后位置，同特异性后者覆盖。触控增强规则统一放样式区末尾的媒体查询块（或提高特异性）。全覆盖清单：mtab/chips/rngchip/#tabs span/mchip/抽屉输入。家族变体：**ID 选择器（1,1,0）恒压类选择器触控增强块（0,2,0），声明序救不了**——被 ID 块定义的元素（如吸顶条内 `.mtab`），36px 地板值由该 ID 块自身承载，几何行为钉验收。

### 5. 保守筛选的诚实边界
「直挂」筛选（transfer_baggage=direct）下，渠道未标注的班次按不满足处理——需托运的人只信明确标注；同时特性矩阵如实写明数据源现状（仅 qunar PC 有 transitServiceLabel），用户反馈"推送变少"有排查入口。

### 6. CJK 无断词边界：词组粒度 nowrap 是断词孤字的唯一解
中文文本行在窄容器里逐字折行（CJK 每个字符都是合法断点），「经郑州」被折成「经郑/州」的孤字形态且伴随徽标掉行——**含语义的中文词组（中转城市/机场名/航司名）渲染进可折行容器时整词包 `white-space:nowrap`**，空间不足时整段掉行而非断字；断词孤字的裁片截图是最直接的证据形态。

### 7. flex-wrap 的 shrink 不跨折行线：末行孤格要换 grid 等分，不是调 max-width
`flex:1 1 74px; max-width:112px` 的格带在容器 1106px 时首行恰放 14 格（14×74+13×5=1101），第 15 格必折行——**flexbox 规范里 shrink 只作用于同一行内的项目，不会收缩首行来容纳更多项目**，调 basis/max-width 只能挪折行点不能消孤格。N 格恒单行的终解是媒体查询带内改 `display:grid; grid-template-columns:repeat(auto-fit,minmax(0,1fr))`（格数多少恒单行、等宽填满，前提是带内每格宽度高于内容下限）；窄档多格折行与宽档自然单行保持原形零回归面。

## 十八、测试时效、发版执行与收编纪律

### 1. 时间敏感测试的日历自爆：fetched_at 硬编码 × 相对窗口
价带测试硬编码 fetched_at=某个固定时刻 + hours=48 窗按系统时间算——固定时刻一过样本滑出窗口，测试「上午绿下午红」（非代码回归）。**凡带相对时间窗（N 小时/天）的测试，样本时间一律 datetime.now()-Δ 动态生成**，离窗界留足余量（≥1h）。

### 2. 「tag 先行」的执行细节：refspec 歧义会让 main 先到
本地误建与 tag 同名的分支后， 报 src refspec matches more than one 而失败，同一条命令链里的 main 推送却成功——CI 立即在 tag 缺失下跑版本门禁（git describe failed）必红。**push tag 与 push main 分两条命令先后执行，tag push 失败必须中止后续**；红了 rerun 即绿（同款先例）。

### 3. 打包环境无 zip 命令：python zipfile 兜底
Git Bash 环境无 zip/unzip CLI 时发行包用  + zipfile.ZIP_DEFLATED 打包（arcname 用 relpath 去 dist 前缀），抽验用  解压后实跑 exe --version。脚本里  + 管道 tail 会掩盖非零退出码（管道返回 tail 的 0）——**发版脚本检查关键中间产物存在性，勿只看管道退出码**。

### 4. 双会话赛马轮的收编纪律
并行会话持续写盘时 Edit 必报 modified-since-read——以树为准勿信叙事：每次写前重读目标文件、git diff --stat 盘对方增量、pytest/uitest 全量复跑当唯一真相、发版动作前 ls-remote 查远端防撞车。已落盘的调研产出（_scratch/audit_*/push_*/observe_*）直接收编勿重派。

### 5. 发版竞速撞上后到修复：资产级接力替换，别让资产落后于指针
两会话同跑一轮各自发版，先到者完成提交/Release/资产上传/重启生产后，后到者手中还有先到者提交时刻之后的程序修复——此时 force 挪 main 与 tag 是恒态纪律内的标准动作（单提交 amend 语义不变，先到者的终验按「树内容对=事实」照样通过），**但先到者已上传的资产是从旧树打包的，资产落后于指针**：必须重打包替换同名资产（删旧传新），zip 抽 exe 实跑验版本同源；仅文档级增量可援引「程序面同源资产不重打」先例，程序面改动一律重打。撞车防护靠时序：force 推送两分钟内完成，打包慢工与对方的收尾动作（deployments 清零/观测）天然错峰；pidfile 与 LISTENING 不一致=对方重启在前而本侧 start 撞端口静默退场（LESSONS 十五§1），按 netstat 实际监听者修 pidfile 后再重启一次。**「资产字节数与上一版完全相同」是未重打的强信号**：Release 文案与资产是两个独立对象，文案更新不蕴含资产重打——终验位把「本版资产字节数 vs 上一版」列入对照单，全同即拦下（真巧合的重打同字节数概率可忽略，抽 exe 内嵌版本实跑是第二证）。

### 6. 行为钉插入自检流水线的位置本身就是前置状态变量：新钉段放流程末尾
往大而全的 UI 自检脚本里加新钉段，插在「自己觉得语义相关」的段落（如监控概览段后面）会**污染后续全部测试段的前置状态**：钉内做的搜索过滤、面板切换、临时节点注入，让下游段落拿到的页面不再是它们撰写时假定的初始态——症状是「加了钉之后一堆八竿子打不着的既有钉齐红 + 某处 click 超时中断」，而新钉自身全绿。**行为钉段的插入位置是状态变量：一律放流程最末（全部既有断言跑完、统计落盘之前）**，段内自带的复位只防段内相互污染，防不了对下游的污染。

### 7. 钉会隐式依赖另一个缺陷的副作用：修复让行为变正确，过时的钉才现形
某术语钉断言「页面文本含 X 且不含 Y」，长期绿——真因是前序段落遗留的搜索过滤态恰好让 X 所在分区保持可见（那正是导航不复位搜索态这个**缺陷的副作用**）。修复导航复位后，分区回到单面板语义、X 退出 innerText，钉骤红：红因「修复」而非回归。**审查一颗「多年绿」的钉时先问它依赖了哪些前序状态；修复类改动后的骤红，先定性钉面是否钉在缺陷行为上，再谈改码**——钉面随行为演进改写（显式落位到目标状态再断言），缺陷修复本身不动摇。

### 8. Agent 审计产出的立案要过现场复核关
审计/调研 agent 报告的「缺陷」结论落地前先读码现场复核：报告与代码矛盾时以代码为事实源——「功能缺失」类结论可能只是漏读（实现在案且行为钉俱在），照单改码会产出重复实现。审计给出的删除/收口面也可能不完整，两个方向各有实证：删除类改动落地时对「同选择器/同字面量」全仓 grep 补枚举，同族残留备案入清理池而非当轮扩大删除面（超出审计实证范围的删除，live computed 复测先行）；收编类改动锁「单模块内零字面量」不算闭合——其他模块的剥注/转写表里手抄同词面时，「词面改版日只改此处」的承诺在跨模块边界静默失效，且钉着旧字面量的测试不会红。**全仓 grep 字面量本身（而非只 grep 本模块）才是收口面的验收口径。**复核自己的 grep 也有形态盲区：「某键零消费」类断言必须枚举该键的**全部访问形态**（下标 `x["k"]`、`.get("k")`、解构/遍历投影）逐形态查——只按下标形态 grep 会把 `.get` 形态的真实消费点漏成「孤儿键」假案（有防退化钉在场的，全量红当场揭穿；没有钉在场的就直接误删上线）。姊妹律（值域扩充类改动）：下游消费点不止「读这个键」，还有「拿键值做等值判定」的形态——等值门（`== "X"`）、排除元组（`not in ("X", ...)`）、子串反证原子，三形态对新值的敏感性不同：子串形态天然吞新值（常是守卫的第 2 重短路），等值门与元组必须逐个核对新值落点，漏枚举一处等值形态就是守卫语义静默翻转（实录：渠道品牌舱位词入 cabin 值域，调研报了三处消费点，主修全仓 grep 等值/元组形态补出第四处「售罄守卫豁免元组」；终局靠「反证原子是子串匹配」的短路论证判死档不扩元组，但全仓枚举动作本身不可省——枚举出死档与漏枚举是两回事，前者有论证在案，后者是静默缺口）。

### 9. 退役类改动的钉面改写是「双段断言」：禁复活 + 实效档在场
死代码（被源码序覆盖的声明、不可达档位）退役时，锁着它的存在性钉会骤红——改写不是简单删断言，而是拆成两段：**旧形态「禁复活」断言**（防死代码回归，死档复活=任何视口不可达的假实现）+ **实效档在场断言**（锁住真正承载设计意图的现行形态，防「删了旧的、新的也丢了」）。同族钉会散落多个测试文件（按同一字面量 grep 全部命中点），漏改任何一颗都要等全量红才现形——退役动笔前先列钉面清单同批改写。钉的注释要写清各档的带归属与层叠胜者，带归属写反的注释比没有注释更误人（实测 computed 值反推带归属，不按源码位置推演）。

### 10. 纯文本计数钉的口径是「整个文件是字符流」：注释与字符串里的字面量同被计数
计数钉 `src.count("X")` 对 Python 源码做纯文本统计——注释里为解释钉面而手抄的同字面量（如「由 .fbar .switch::before 覆盖」）会被一并计入，钉在声明数不变时假红，且红因极难联想到「自己刚写的注释」。**往被计数钉看守的文件里写注释，先 grep 该注释是否含钉面字面量；含则改写措辞（「上方 fbar 开关热区行」指代式），或在钉面排除注释形态（按行首空白+选择器开头的声明行计数）**——计数钉锁的是「声明枚举」，注释不是声明。姊妹律：钉面自己的断言串也常是字面量，给它写失败消息时抄同串会让 assert 的 diff 噪音翻倍；断言串一律从源码 repr 逐字节复制而非手写——f-string 缝隙（`={IDENT}` 的等号与标识符之间隔着花括号）、尾空格词面（表定义列「行情价 」带尾空格）这类一字符差会让钉「找不到子串」直接 ValueError，肉眼看源码却「明明在场」。

### 11. 测试断言的「先清洗再断言」会造出恒真式：断言对象必须是清洗前的原始产物
验证「截尾悬垂冒号已剥」时写 `head.rstrip("：: ").endswith("￥1680")`——rstrip 把待剥字符先剥掉了，断言对象从「产物是否干净」偷换成「剥完是否还剩什么」，缺陷在场也恒绿（实锤：产物 `￥1680:` 悬垂在场，断言照过）。**断言必须作用于清洗前的原始产物**（`not head.rstrip().endswith(("：", ":", " "))` 锁「无悬垂」），或拆两段先断「清洗等价于无操作」；写完断言先做一次心理变异——「把缺陷注入产物，这条断言会红吗」，答不会的就是恒真式。

### 12. 「选择器不命中」类修复的新选择器，实效必须在同轮实测：字面 count 钉锁不住死选择器
修「收编选择器恒不命中（死选择器）」缺陷时，替换上的新选择器若按读码推断 DOM 层级落笔，可以引入同族新死选择器——而锁它的钉若只断言「该字面串在源码出现 N 次」（count 钉），选择器在页面上命中 0 个元素也照样全绿：钉锁的是字面在场，不是选择器实效（两代同族病相继：子代选择器不命中→换「读码推断的另一个子代选择器」照旧不命中，字面钉双双恒绿）。**修复动笔前先在真实渲染页 `querySelectorAll(新选择器).length` 实测命中数（>0 才是修复），层级结论以实测为准、不认读码推断；钉面必须行为级——源码侧「专类/选择器与模板串两段互锁」+ 渲染侧行为钉（搜索/交互后元素真实可见），任何单侧字面断言都是恒绿死钉的候选。** 审计报告给出的 DOM 层级结论（「X 是 Y 的直接子级」）同受本律：不实测就采信，等于把推断当事实传给修复。

### 13. GitHub Release 资产的直查/删除端点不带 release 段：嵌套形态恒 404
Release API 的资产操作端点是 `/repos/{o}/{r}/releases/assets/{asset_id}`（**不带 release_id 段**）——按列表 URL 直觉拼 `/releases/{release_id}/assets/{asset_id}` 的嵌套形态，GET/DELETE 恒 404 而「列表接口明明能看到这个资产」，极易误判成 token 写权限缺失。**删除/直查资产一律从资产列表返回的 `url` 字段取权威端点**；上传仍走 `uploads.github.com` 的 `/releases/{release_id}/assets?name=` 嵌套形态（两个域的形态刻意不同）。删旧传新同名资产的顺序：先 DELETE（204）后上传，两步间无需等待。

## 十九、守卫链设计、行为归因与竞态收编

### 1. `_fit_line` 的「全超取末档」语义：守卫链必须有恒达标的地板档
`_fit_line` 全部 fallback 超预算时**原样取最后一个 fallback（不管超不超）**——降级链没有地板档时守卫静默失效。行宽预算案：brief 本体守卫 40 但消费点拼「- 渠道 最低 」前缀后整行 44-48 超宽（20/2546 行），budget 收紧后超长航班名（双程「航司｜航司号」36+ 半角）连旧末档也超。**凡行宽守卫链，链尾必须有预算内恒达标的地板档（本案=`￥价格`，价格是核心判据最小集）**；降级链的每一档都要按「最坏输入」预演而非按典型输入。

### 2. 行宽预算的单位是「最终渲染整行」不是「本次拼的片段」
`_fmt_brief` 只对 brief 本体守卫、不知道消费点会拼前缀——**守卫离渲染点越远越容易漏算**。同函数 else 分支早就修过同病（前缀并进守卫），tops 分支漏网两轮。新拼行时先问「这行的完整渲染形态谁负责 ≤40」；分段守卫必须在消费点做总预算扣减（`budget=max(6, 40-_dw(pre))`，max 地板防未知长键把预算扣成负数）。

### 3. orphan 单提交历史下 `git log -S` 零信息量：版本归因改走产物实证
force 归零后本地历史只剩最新 orphan 提交，`git log -S "字符串"` 只命中一个提交，**无法证明该字符串是本轮引入**（差点把日报 ⏱ 行误判成新引入形态）。行为归因用产物时间线实证：push_history 逐日抽同位置内容对比形态演变（本案：连续四天日报 ⏱ 行都带日期=既有形态）。

### 4. 重放矩阵的违例要逐条定性后再写「PASS」：上轮漏走的账本轮还在
上一轮重放输出里 L8 实为 2 条违例，报告却写「11/11 PASS 零违例」——**下一轮重放同检测器再次抓到同形态才暴露**。检测器口径本身也要审：L8 动机是图例行 40 半角塞不下档位词条（去日期），日报 ⏱ 时间注行无词条 ≈30 半角、日期=跨天辨识信息，属检测器过宽（备案不改码）。逐条违例给「修/备案/假阳」三选一结论，别让「零违例」成为没逐条看过的断言。

### 5. 测试数据写「生产不可能的形态」先查生产构造函数
platform_mins 测试值写 None 触发 sorted TypeError——生产构造（`p.price` 恒 float）不可能出 None。**造边界测试数据前先读上游赋值点**，把「我以为的边界」换成「生产可达的边界」，否则测的是臆想防御、还错怪真防御冗余。

### 6. 工作树层赛马新变种：HEAD 不动、无提交、纯文件 mtime 竞态
前三起赛马都在提交/远端层（HEAD 变化、force 互覆盖），第四起是**纯工作树层**：两会话各自跑同一 /goal，全程 HEAD 恒不动、无人提交，改动直接落共享工作区——git log 完全察觉不了。发现信号补两条：**git status 出现陌生文件（对方命名与本侧测试文件同构）+ 文件 mtime 分秒级新鲜度（读 alerter.py 到 git diff 它只隔 90 秒已被改）**。分文件作业天然零冲突（webui/uitest/webui 钉一侧、alerter/main/旧钉适配/重烘一侧）；同名 _scratch 产物互相覆写（曾出现 0 字节）但调研结论已进对话不损失；**对方主动适配我改坏的旧源码钉＝双向收编收敛信号**——合并树双门禁复跑当唯一真相，文档/LESSONS 先占坑者赢、后到者补同章余条。

第五变种是**暂存区共享**：共享工作区里 index 也是公共状态——本侧 `git add` 暂存的改动，会被并行会话的下一步 `commit --amend` 一并收编进它的单提交（本侧无任何提交动作，HEAD 却已包含自己的全部暂存）。发现信号：`git status` 从「M+?? 一片」变干净、`git worktree list` 冒出陌生 _rel、ls-remote 指针已前移。**暂存被收编是双向收敛的良性信号，勿重复 amend/重推**；对账三步：`git show <hash>:<file>` 抽验本侧关键改动真实入树（提交会撒谎，树不会）→ 本地双门禁复跑 → 对方发版动作（资产/重启）落地后做远端资产逐字节下载+抽 exe 实跑的独立终验。竞态高危期（提交/打包/推标签）前的 `git add` 前先 `ls-remote` 对账一次。

### 7. PAGE 探针 JS 字符串里禁写 Python 语法；行为钉选择器必须「可聚焦可见」
独立 playwright 单测把 Python 条件表达式（`'ok' if ok else`）写进 evaluate 的 JS 字符串＝eval 直接抛错。行为钉抓焦点类断言时用「首个 [id] 元素」会命中不可聚焦件/折叠隐藏件（航线卡默认折叠、cfgglobals 与 cfgform 是两个容器）——**标签白名单（INPUT/BUTTON/SELECT/TEXTAREA/A）+ offsetParent 过滤**，先走真实展开路径（foldCh click）再断言，测完自带状态复位（FOLD.route={}+applyFolds；CHR.i 状态复位律第三次实战）。

### 8. display:none 容器内的布局量纲全是死档：可见性切换点必须重跑判定
health() 首渲在隐藏 tab 容器里量 scrollWidth/clientWidth 恒 0——「渲染时量一次」模式在 tab 化页面必踩（默认加载→点健康这条最常见路径上横滚暗示恒不挂）。**量纲型 affordance（横滚暗示/弹性铺满/溢出检测）的判定要挂在「变得可见」的切换点重跑**（showMonTab/switchView 补一拍），只挂数据渲染点罩不住。flex 收缩归零坑是同族（容器不可见＝几何全零假象）。

### 9. 降级链的档序是语义优先级声明：辨识信息先于次要信号被丢
KPI 行2 降级链原序「先丢跨天括注、再丢涨跌」，在两档都超宽时两者双双丢掉——跨天班读不出「+1天」，读者按到达时刻误判当日达（决策级辨识信息），涨跌只是次要信号，档序却让辨识信息先死。正确排法：**先列「读者最后才能失去的字段」，倒序即档序**——辨识信息档在最前、次要信号档先丢、地板档恒落（§1）。档序修复收进单源 helper，调用点内联 fallback 列表是档序悄悄回退的温床（源码钉锁调用点必须走 helper）。

剥名档的「名字分段符」要按全形态枚举：剥档只认一种分段符（「｜」营销双名）时，同语义的另一常态分段（「/」联程双航司名）整族不可达——超宽直落地板逐字截，到达时刻烂尾+跨天括注整体消失（正是本条要保的辨识信息最后才丢的反面实录）。**凡「剥 X 段保 Y」档，先枚举 Y 之前全部可剥段的现实分段形态再落链**；混合形态（双名+联程并存）的档序=剥次要程度递增（营销名→联程首段），新档落地按死档判据（§16）变异验证可达性。

### 10. 脚本内存改写源码的「变异验证」会与并行 bake/import 交错：中间态进 pyc 与重烘产物，服务端吐「磁盘上不存在的页面」
变异验证把源码临时改到旧形态、跑红、再写回——若并行会话恰在此窗口内做 demo 重烘或任何 `import webui`，**中间态源码会被编译进 `__pycache__` 并被后续启动的进程按 stat 签名采信**：磁盘是终态、进程内存是中间态，重启两次仍吐旧页面，curl 与 grep 各执一词；同一窗口的 demo_build 还会把中间态模板烤进静态演示站。排查抓手：服务端 HTML 与磁盘源码各抽一个「本轮新增标志串+旧序字面」各数一遍，两边同时半新半旧=中间态产物实锤。**纪律：变异验证优先走内存态（import 后改对象/源码钉正则推演），必须落盘时，跑完立即删对应 `__pycache__/*.pyc` 并重跑 demo_build，再以「服务端 marker 抽查」收口**——文件 mtime 恢复正确不等于编译产物干净。

### 11. 变异验证的还原动作禁用 `git checkout <file>`：共享工作树赛马期 HEAD 随时被 amend 前移，checkout 还原到的是「新 HEAD」并把全部未提交在途增量一并抹掉
变异验证落盘改写后需要还原，`git checkout -- <file>` 在单会话独占仓库时等价于「撤销本次改动」，但在共享工作树里它的语义是「还原到当前 HEAD」——而 HEAD 可能已被并行会话 amend 前移到包含你先前工作的新提交。实例：会话 A 完成增量落盘未提交，并行会话 B amend 收编工作树发版使 HEAD 前移；A 变异验证后 checkout 该文件，得到的是 B 的新 HEAD 版本——A 自己从未提交的增量（修复、注释、重排）全部蒸发，且因为文件「看起来是最新的」毫无异样，直到复跑测试或 grep 关键字才发现。**还原动作只有两种合法形态：逐字节反向 patch（把变异替换原样改回，assert 变异串在还原前仍在），或事先 `git stash create`/复制副本再回写；checkout/reset 只在「确认 HEAD 停在自己最后一次提交」的前提下可用。**变异前的自检口令：`git rev-parse HEAD` 与自己记忆的 hash 一致吗？`git status` 里未提交的是不是全是自己的？两问有一否，还原一律走反向 patch。

### 12. 行为钉「调用前捕获容器、调用后断言」读到的是 stale null
页面容器由首次使用时动态创建（如 toast 容器）时，检查代码若在触发前捕获容器引用、在触发后断言内容，首次运行的捕获值恒 null——触发创建的是新容器，旧引用不更新，断言假红且红因与被测行为无关。**取件必须在触发之后**；需要防前序残留假绿时，触发前清空容器内容、触发后重新获取再断言。「单测绿全量红」家族的另一变体：红在钉自身的数据流，不在被测行为。

### 13. 宽度守卫模型要用真实渲染字体实测校准；校准落地的同轮有三件连带必做
行宽守卫按「全角=2 半角=1」计宽时，ASCII 字符的真实 advance 与 1 半角基准可以有 6%-12%（数字）乃至 75%（%）的低估——「恰卡 40/40」的行在真实字体渲染下超红线（实测 20.5 全角），守卫模型判合规的行恰是会折行的行。校准动作本身只是起点，**同轮三件连带缺一即翻车**：
① **逐字截断循环必须换浮点原始宽累计**——ceil 后的单字符值把数字 1.125 放大成 2（放大 78%），截断点系统性提前，词面烂尾（「标注缺失」截成「缺(截)」、到达时刻截成 21:10→0）。行级判定取整、字符级累计浮点，两者不可混用；
② **降级链在「整词档」与「硬截档」之间通常缺中间档**——校准让大批恰卡线行塌进硬截档，截烂的不是冗余而是决策信息。补档的取材顺序是「结构内冗余先剥」：双名前缀（「新海航｜海南航空」的营销名段）→ 包装括号对（全角（）4 半角纯装饰）→ 让位标记（截断标记与首渠道名争预算时渠道名优先，标记缺席由「全量对账循控制台」的既有备案兜底）。档序律投影：时刻/跨天这类辨识信息宁可剥名字段也不可被逐字截吃掉；
③ **锁旧档位的钉同轮全量复审**——「输入 X 落在档 Y」的钉是在旧模型下定的档，校准后这些行理应降档，钉红不是回归是模型变准。逐颗按「真实渲染宽」定性：行为正确信息无损的改断言（线值挪引用行=与姊妹形态统一），行为暴露链缺陷的修链，样本贴线的调样本预算。**审计/调研报告里的宽度推演同受本律：报告手算「≈13 半角恰卡线」的降级档，按真实模型实测可以恒超两条半角带（全角空格与空格各 2/1 半角最易漏计）——按手算落档即产出数学死档。凡「插一档让某词面可落位」的设计，落笔前先对候选词面逐个跑真实计宽函数选形，报告的估算数字不当设计依据。**

### 14. 改共享渲染路径时只钉主干=空分支假绿；全链探不到的分支要单元直调
改段落分隔/降档这类共享渲染逻辑时，「有数据」夹具只覆盖主干分支——「暂无数据」「无候选」等空分支共享同一改动点，但补偿结构不同（主干行间 `\n\n` 化时一并退役的前导/组尾空行，恰是空分支的段落分隔唯一补偿位），漏盘点即粘段墙回归。且空分支常在全链推送里被预算截断竞争吃掉内容，「全链跑一遍没红」测不到它——**执行级钉要直调分支所在方法**（单元级构造空桶 section），钉住每个分支的输出形态。同构姊妹点同轮盘点：组尾核减的兄弟消费点（比价组尾）留着对称的冗余尾换行，同样漏在主干夹具视野外。

### 15. 地板档自身超预算时，「恒达标」的正确裁决是备案而非强行修
行宽守卫链的地板档（`￥价格` 形态的核心判据最小集）在极限小预算（消费点前缀吃满 34 半角以上才可达）下自身超预算——两个看似自然的修法都引入新害：提高预算地板（`max(6)`→`max(8)`）会让整行突破上限，越界只是从前缀挪到整行；把地板档改为逐字截会截烂价格数字，决策信息损坏比超宽更糟。**恒达标律（§1）约束的是「现实可达的最坏输入」，不是数学上无穷的输入域——触发前提只在配置域病理形态（超长平台键）下可达时，维持备案并写明「两修法为何皆新害」，优于强行修出一个新缺陷**；真要收口时修的是让前缀自身进预算（截前缀腾空间），而不是动地板档。§1 的隐含前提是地板档宽度 ≤ 预算下限，前提破时先审前提是否现实可达再决定修与不修。

### 16. 降级链增设档位前，先证「与邻档的输出差异」：变异不红的直落钉=死档信号
为收窄某个降级档的语义（如「剥渠道保完整码」）在链中插一档时，光验「样本确实落在新档」还不够——新档可能与地板档**数学等价**：新档放行 ⟺ 地板档不截码也放得下同一内容，两档输出逐字相同；新档放不下 ⟺ 内容本就超出无截码形态，地板档照样截码落地。两个方向都推不出可分辨的输出，档位本身零产出，只白付一条 fallback 与读链心智。**判据是变异验证而非落档观察：构造「恰卡新档」的样本加直落钉，摘除新档后钉不红=死档实锤**——此时正解是撤档并在链尾注释写明等价论证，把钉面花在真实分档（有/无渠道段、括号/裸词）的可辨形态上；等价论证随档除一并归档，防下轮照图样再造死档。配套：直落钉的样本空间要网格实证而非手拼——宽度模型带校准膨胀（数字 1.125/字符），手算恰卡线十有八九偏一档（§13）。

## 二十、共享 DOM 状态与两道测试门

### 1. 共享 DOM 件的属性被任一入口写过后，静态初始值就是假单源
推送弹层三入口共用 `#pvMask .pvcard`，aria-label 只在 HTML 上写一次「钉钉推送预览」，showLog/pushLog 各自 setAttribute 切换——**previewPush「保持现值」的修法在多入口会话里必漏**：showLog 先开过，属性就停在「渠道轮日志」，previewPush 再开读屏名失配。凡多个入口共享同一 DOM 件的可变属性，**每个入口开面板时都要显式回设自己的值**（三处各 1 行 setAttribute），静态初始值只兜「页面刷新后第一次」。复核确认：回设必须放在数据成功分支内、开弹层之前（失败提前 return 不开面板，无暴露面）。

### 2. 「先单测再全量」不是冗余：两道门的捕获面互补
previewPush aria 案单测全绿、全量红——单测按**孤立路径**跑（previewPush 是第一个开的弹层），全量按**真实会话次序**跑（健康格日志先开、预览后开）。状态污染类缺陷恰好只在后一种暴露。uitest 新钉先 playwright 单测再全量的纪律（四度实战）价值正在于此：单测快速定位行为正确性，全量捕获会话级交互次序；**单测绿≠全量绿，红在哪道门本身就是根因线索**（红在全量=状态残留/次序依赖；红在单测=行为本身错）。

## 二十一、CSS 层叠与几何断言

### 1. CSS 媒体块没有「更严条件更后胜」：同特异性只看源码顺序，解锁块放进早前媒体块必被后续块覆盖
1440 断点缝修复把 `.statline,#pulseLegend,.pulsewrap{max-width:none}` 下放进 `@media(min-width:1440px)` 的 wrap 块（L814，文件较前），自以为「1440 条件比 600 严、应当赢」——实际 `.statline{max-width:var(--kpiw)}` 在更靠后的 `@media(min-width:600px)` 块里，同特异性后者胜，解锁被无声盖回，1440-1919 带空腔原样（≥1920 块之所以一直生效，只因它在文件尾部）。**媒体查询不是特异性加分项：断点解锁/覆写块的生效域由「源码顺序 × 断点区间包含关系」共同决定**，同类覆写规则必须放在所有同选择器声明之后（追加置尾纪律对媒体块同样成立）。uitest 全量红、源码钉绿——源码钉只验「字符串在场」，验不了层叠胜负，几何/computed 类行为钉是唯一真相。同族：**「同值补档」的声明族（多个媒体块重复同一声明）新增或修补成员时全族清点**——只补一档，姊妹块同缺陷残留，且「与上方块同值」类注释同步失准。

置尾纪律有双刃面：每一块新增按置尾生效，同时也可能**反杀早前的同选择器块**。窄窗「独立成行」块按置尾追加后，早前的触屏隐藏块（`pointer:coarse` 隐藏快捷键教学）被同选择器同特异性的后者盖回——真机手机（coarse+窄屏双命中）上无键盘设备看到快捷键教学复活，而代码注释还写着「真实手机已被上块隐藏」。**每次按置尾追加覆写块，先重查与既有同选择器块的交集**：两者都命中的设备以谁为准、语义是否互斥；互斥语义（隐藏 vs 显示）的层叠序是行为本身，锁定它的钉要锁「级联实际胜者的位置」（rindex 级源码钉或 computed 行为钉），不能只锁字符串在场。

### 2. uitest 几何断言必须先固定视图上下文：display 翻转架构下非活动视图量纲全零或异形
1500 档「statline 跟卡全宽」几何断言直接写 `pc.width-st.width<40`，在断言所在位置（日历/走势测试段之后）pulsecard 处于非概览布局态，几何不可靠恒红；探针在默认概览视图下同断言 diff=38 全绿。**凡量几何（宽/高/位置），断言前先落到量纲有意义的视图**（`switchView('mon')`+对应 tab），或者改钉 computed 值（maxWidth/cursor/display——元素恒在 DOM、不随视图翻转）。「同一断言探针绿、全量红」=视图上下文差异，不是修复无效（LESSONS 二十 §2 的姊妹律：那 条讲会话次序，本条讲视图状态）。

### 3. `overflow-x:auto` 强制 `overflow-y:auto`：横滚容器把纵向外扩的触控热区裁回原形
横滚容器内格子用 `::after` 纵向外扩（inset 负值）补足 37px 触控热区时，容器声明的 `overflow-x:auto` 按 CSS 规范把 `overflow-y` 一并强制为 `auto`——热区溢出部分被裁剪框吃掉，实际触控高度回到格子本体，且伴随一条隐藏的纵向滚动条。修法三件套：容器纵向 padding 外衬让热区落回裁剪框内 + margin 负值回收（行高零漂移）+ 容器 `pointer-events:none`、格本体 `auto`（衬垫区不吞点击、不挡下层）。**触控热区这类「可达性声明」要按裁剪框验收（elementFromPoint 实测命中），声明值不等于可达。** `pointer-events:none` 有备案级副作用：容器自身的滚动条拖拽一并失效、衬垫/格缝区的滚轮事件穿透——窄条带在桌面宽度不溢出（无滚动条可拖）、触屏设备本就不拖滚动条时，代价为零；落这个修法前先量「溢出到底发生在哪些档位」。

### 4. colspan 行的折行受「td 宽=全表宽」钳制：短内容永不折行，改内容序优于改容器宽
同班比价展开行（colspan=9）挂了 `white-space:normal` 想让渠道链在窄屏折行、把链尾结论句带进首屏——真机实测**链没折、结论句仍在视口外 ~200px**：colspan 单元格的宽度=整张表的内容宽（各 nowrap 列撑出来的 690px），不是视口宽，折行断点落在 690px 处，链短于全表宽时永远单行。**几何断言要量 td 的实际盒宽，不要假设它等于可视容器**；此类「链尾摘要进首屏」需求，正解是把摘要**前置到链头**（该行已退出首列吸附，链头=横滚零位，任何屏宽首屏即见），容器宽是表格布局决定的、不是样式能单独约束的。

### 5. 密集条带的命中错位，第三修法是容器级几何最近邻重判：CSS 外扩治覆盖、触屏加宽治尺寸、重判治判定
密集图表件（脉冲柱 4-9px 宽、健康时间线格 5-6px）的触控命中问题有两层：热区小于指尖分辨率（覆盖不足）与**命中判定本身错位**——格间缝的死区、邻格伪元素横向外扩吃缝（指尖点格 N 右缘修正带、事件目标是 N+1，系统性 off-by-one 开错关联详情）。伪元素外扩过缝会互串邻格（同族判例：相邻格热区互相覆盖，点 A 响应 B），触屏档加宽则改变视觉密度、密集条带加不动。第三修法是**接管判定而非扩大命中**：粗指针环境下容器捕获阶段截获点击，按「点击坐标到各动作格本体矩形的距离」最近邻重判（等距取先遍历=左格），命中后直调其 `onclick`（不走事件传播，无递归）；原生 `onclick` 与桌面鼠标路径零改动。三个工程细节缺一不可：监听委托挂**恒存容器**（`innerHTML` 重建子树不丢监听）；无动作格不入候选（映射结果恒可响应）；媒体特性动态查询放 handler 内（触屏仿真/设备旋转即时生效）。审计面注意：热区清单类审计按选择器枚举会漏「伪元素吃缝」这类命中判定错位——要用 `elementFromPoint` 对**格缘修正带**做逐点命中采样，量「声明热区」更要量「实际命中谁」。

### 6. 几何断言的参照系是布局视口，不是 innerWidth
样式化滚动条（`::-webkit-scrollbar` 定宽）在桌面内核吃布局宽（390 视口 html 实宽 380），真机 overlay 滚条不占宽（390）——拿 innerWidth 当基准，同一份测量会得出「伪空隙」与「真满血」两个互相矛盾的结论。满血铺贴/出血类断言以「目标盒左缘=0 且右缘=容器边盒右」为不变量，两种滚条语境同真；负 margin 外扩类修复的验收先核参照系再判缺陷真伪。

### 7. 偏移锚定「内容依赖的实高」时固定像素是环境校准：动态单源是终局，带内覆写是追不完的长尾
吸顶偏移按固定像素校准（校准环境=演示实例，参照件 header 无某动态内容），而生产环境同一参照件因内容折行（倒计时文案在场）实高 72→109 浮动——固定值在内容变化处全带错位（768 实测吸顶条被不透明 header 盖住 33px、窄带与 header 间透缝 0↔22px 随文案逐轮漂移），且演示/自检环境恰缺那个动态内容时探针全绿：「单测绿、生产红」的环境差异型。**凡偏移/补偿锚定「实高或宽度会随内容漂移的参照件」，用 ResizeObserver 实时写 CSS 变量做动态单源**（`--hdh` 形态：`offsetHeight` 写 `:root`，消费点 `top:var(--hdh,fallback)`，JS 失效 fallback 保旧值零退化）；既有带内固定覆写块随之退役而非保留——为每种内容形态各校准一个带内覆写值是追不完的长尾，变量贴实高后固定校准全部成为冗余覆写。行为钉量「目标件贴参照件底」（`m.top≈h.bottom`）而非任何固定数，固定值断言在动态化当日即成假钉。环境差异还有一个反向实锤：锁定「固定抬升 96px」的行为钉长期全绿，探针一量参照件实高才发现校准假设（40px）与环境实况（57px）差了 17px——**固定值钉的「绿」只证「值没变」，不证「值对」**；动态化改造落地的同轮，把同域固定值行为钉改写为相对关系断言（目标底 ≥ 参照件顶+呼吸缝），绝对像素从钉面全部退场。探针与验证脚本同受本律：断带锚定的绝对值（如「窄带左缘恒 10px」）不可平移到布局态随视口变化的带（宽屏居中限宽后同一对元素的左缘随视口宽浮动）——**凡量左缘/宽度的断言，恒断「两件同线」的关系，绝对值锚只留在真有固定语义的带**；探针假红先量「关系是否成立」再信 FAIL。

### 8. canvas 绘制量探针的两处时序陷阱：入场动画帧与焦点态来源
钩 `CanvasRenderingContext2D` 原型统计绘制量（Y 轴标签计数类断言）时，图表的入场动画把绘制摊进 rAF 帧——同步 `finally` 还原钩子的写法在动画首帧前就撤了钩，计数恒零、钉恒假红。**钩子必须窗口化**：安装后经 `Promise+setTimeout(~1s)` 收集跨帧计数再还原；只有「终态逐位等」类断言才可同步取样（二十七§6 同族）。键盘焦点类断言靠 Tab 序抵达目标受前序小节的焦点残留影响（activeElement 起点漂移、有限次 Tab 未必落在目标元素，钉红原因与被测行为无关）——程序化 `focus({focusVisible:true})` 直焦目标并强制 `:focus-visible`（Chromium 86+），并配「环在位」双证（transitionDuration==='0s' 单证可能恰好来自别处）。

### 9. CSS 自定义属性的「消费带 × 定义带」分离：var() 无 fallback 且定义在更窄媒体块 = 整条声明塌陷
scroll-padding 在中宽带消费 `var(--mtabsh)`，而该变量的 `:root` 定义只写在最窄带的媒体块里——中宽带变量未定义且无 fallback，**整条 calc 声明在 computed 时塌为 initial（值=auto/0），不是「沿用最近定义」也不是报错**，锚点补偿静默失效、落点被吸顶件遮挡，且源码阅读时「消费与定义都在文件里」极具迷惑性。修法按语义定方向：中宽带**需要**该值（同带存在吸顶件）→ 定义随消费带补齐（同值多带各自 `:root` 声明）；中宽带**不需要**（纯残留消费）→ 消费点补 `var(--x, 0px)` fallback。配套钉两件：源码钉锁「定义所在媒体块覆盖全部消费带」（块内 `:root` 声明的位置断言），行为钉量 computed 值非 initial（`parseFloat(computed)>=阈值` 对 NaN/0 双态皆红）。**同类覆写看层叠序（§1），变量缺失看作用域带——「值错了」与「值没了」是两族缺陷，前者的钉抓不住后者。**

### 10. 工具类 CSS 类常被作用域限定在首个消费容器：同族新消费点必须同容器粒度补声明
词组 nowrap 类 `.nw` 的规则写成 `.kpi .fb .nw{white-space:nowrap}`——**类选择器带着首收编时的容器前缀**，页面上同 class 的其他容器（用户卡头 routes 分段）渲染出 class 却不命中任何规则，computed 恒 normal，断词孤字照旧。误判路径很诱人：探针按 class 查到元素、抽查首个实例恰好落在原容器内全绿。**复用既有工具类前先 grep 它的全部声明形态——带容器前缀的工具类是「局部约定」不是「全局工具」**；新消费点在同容器粒度补声明（或评估放宽为全局类，后者需清点全部既有命中面防误伤），行为钉按 computed 断言而非 class 在场。

### 11. 支持 CSS 嵌套的内核里，`cssRules` 属性的存在不再蕴含「这是容器规则」：规则表遍历必须判长度
样式表规则表递归遍历（对比度扫描/规则在钉类探针）写 `if(r.cssRules){walk(r.cssRules);continue;}` 时，支持 CSS 嵌套语法的内核给每个 CSSStyleRule 都挂了 `cssRules` 属性（空 CSSRuleList 也是 truthy 对象）——所有样式规则被当作容器走 continue，本体检查永不执行，钉恒红且红因与被测样式无关。**容器判定要 `r.cssRules && r.cssRules.length`**：「有子容器属性」与「是容器」在语言能力演进后是两件事；这类遍历器是共享工具，修一处时 grep 全部同构遍历器同轮对齐。

### 12. 双系列图的坐标映射单位是「时刻」不是「系列内索引」：索引式 X 在点数不齐时压稀疏系列、错配读数
折线/K线混画的共享画布把 X 坐标写成 `i/(N-1)`（N=双系列点数最大值）时，两个隐含前提各会破：①「各系列第 i 点在同一时刻」——「宁漏不虚报」过滤让某系列稀疏（仅窗尾 2 点）时整条系列被压到画布左缘，低点标注/档位环/回落标全错位；②hover/键盘按同索引取两系列——十字线在窗尾读出窗头价（时刻+档位双重误读）。**终局形态是共享时间轴：双系列全部时刻排序去重建轴，X 的索引语义统一为「轴刻度索引」，系列内索引经换算表落位**；刻度循环、绘制、命中反查（点/桶预挂轴索引）、键盘步进（轴点数=并集数）全部随之换语义。改法的连带两坑：轴构造依赖的系列变量在赋值点之后才声明（const TDZ——图例/注释块随声明序后移，空态门在其后清空语义不变）；满系列（双系列点数恒等）时并集=各自长度，新旧映射逐位等价=零回归面，钉面用稀疏样本才抓得到差异。

### 13. CSS 形制扩带时，锚定旧带前提的 JS 伴生门必须同轮同域
吸顶筛选条这类「CSS 形制 + JS 伴生行为」组合件，形制的媒体门扩带（≤540→≤760）时，所有以「该形制只在旧带存在」为前提的 JS 门（抽屉在流展开时的顶拉 assist）必须同轮随族——漏随形态是「新带获得形制的能力面（吸顶条常可见），却拿不到伴生行为面（深滚开抽屉自动拉到可视位）」，且行为钉只钉 CSS 半边时全绿（灯照不到 JS 缺口）。反向连带：锁门数的计数钉中「某门恒属旧带」的例外注释随扩带一并改写——例外前提消失后，例外本身成为新缺陷。

### 14. 容器限定工具类放宽为全局类时，压制面与渲染源要连着一起审
词组 nowrap 类（`.nw`）从容器限定（`.kpi .fb .nw`）放宽为全局单条声明是消除同族漏收的正解——新消费点逐个补容器限定是追不完的长尾。但放宽当轮有两个不生效点必须同查：①同一批新消费点落在「放开换行」的容器里（`td .stl{white-space:normal}`，特异度 0,1,1 且源码序在后），全局类（0,1,0）被无声压制——放开换行的容器对词组豁免要显式升特异度（`td .stl.nw`）；②改了静态 HTML 的 class 而该节点被运行时 `textContent=` 整体重写——多入口共享件「静态初始值是假单源」在类名维度同样成立，真实渲染源在哪，改动就要落在哪（textContent 改 innerHTML 以承载词组 span 是配套动作，静态常量无注入面）。

### 15. 折行检测的 rect 不等于行：span 边界多 rect 与 inline 基线错位都是误报源
`Range.getClientRects` 返回的是布局矩形片段不是行：nowrap 容器内多个 inline 子件各自产出同 Y 的独立 rect（span 边界切割），inline-block/emoji 与相邻文字的 vertical-align 基线错位产出 Y 差 1-3px 的 rect——两者都不是折行。孤字/断词检测器要按「Y 差 ≥ 字号量级的容差聚类」先归行再判（`Math.round(top)` 精确分组与「rect 数=行数」两种天真实现都会把正常单行误报成断词）；同理「宽<2.5em 且首行>3×末行」的判定只在真折行形态下有效。

## 二十二、多通道图片载体与 MIME 组装

### 1. 同一份 desp 推多通道时，图片载体按通道能力分轨：钉钉=图床外链是唯一通路，邮件=CID 内嵌才零外网请求
用户实报「邮箱图片加载慢、疑似免费网站 URL」——邮件通道收的本来就是钉钉那份 desp（明细总表/走势/明细表/日报四类图全走 upload_chart 图床外链），_md_inline_html 把 `![](url)` 原样渲染成外链 `<img>`：QQ/163 网页版对 http 外链图默认折叠（手点「显示图片」）+免费图床直链加载慢。**钉钉机器人 markdown 只认公网 URL，图床的慢在钉钉端不可消除；邮件有 MIME 附件通路，同一个慢只在「外链」形态才成立**——解法不是换图床，是邮件发送端把图下载后并进 console-shot 同一条 multipart/related（收件端零外网请求，钉钉端原样不动）。「同一内容多通道路由」的改动先逐通道问内容载体的能力上限，再按能力分轨，勿一刀切也勿因一通道受累全链换药。

### 2. 通道专属后处理挂发送端组装层，勿动 send() 协议面
cid 改写放在 EmailNotifier._build_msg 内完成（纯文本 part 恒用 desp 原文、HTML part 换 cid、推送历史与钉钉等其余通道拿到的都是原文）——**send() 协议形参一个没加**：Composite 七通道+全部测试 fake 的「协议形参三端同轮对齐」雷区（既有沉淀律）整体绕开。配套降级律：下载失败/魔数不认（png/jpeg 之外）→ 保留外链（收件端旧行为兜底），宁慢勿缺；多张共享总时限（25s）防图床悬挂拖住推送轮；风暴延迟重发按实际发送时刻重下载，读到的恒是图床当前内容（杜绝「本地文件已被下轮覆盖」竞态）。实现坑存档：cid 替换 lambda 曾漏 `cid:` 前缀产出半截引用 `](push-img-1)`——**替换类改动的断言必须锚完整引用形态**（含 scheme），新测试当场抓获。

## 二十三、异步失败分支与测试模拟

### 1. 错误分支是静态骨架的「第二主人」：异步失败路径不盘点，加载态就是永不到达的假等待
页面骨架的静态「加载中…」只兜「第一次成功前」——一旦 fetch 失败走 catch，catch 只刷新了自己直接管的 pill/updated，明细表/登录卡/全局参数三处静态骨架无人认领，永远停在「加载中…」：pill 说服务未启动、表体说加载中，同一屏两处语义互相矛盾，而「加载中」的承诺（马上被真实数据替换）永不到达。**新增异步失败分支时，把「页面上所有静态初始态」当失败分支的输出面盘点一遍**：要么同步置错误态（恢复轮重写自愈），要么显式论证「保持加载态合理」。姊妹律：二十一 §1（多入口共享件的静态初始值是假单源）讲「谁最后写谁生效」，本条讲「失败分支也要写」——两合一定式：静态初始值只是占位，每个异步终点（成功/失败）都要有自己的落点。

### 2. 模拟网络失败用「业务层失败」而非「资源层失败」：abort 的 ERR_FAILED 会污染零 JS 错门禁
uitest 模拟服务失联首选 `route.fulfill(200, text/plain, 非 JSON body)`——r.text() 成功而 JSON.parse 抛错，与真实世界 502/错误页同形，走进同一个 catch；**不要用 route.abort**：资源级 `net::ERR_FAILED` 会以 console error 进套件的零 JS 错收集器，218 项全过也会因 errors 非空退出码 1（假失败）。配套复盘律：审计探针报「Esc 后焦点不回送」疑阳，键盘路径复测两轮全绿、源码实链（焦点回送机制在位）俱在——**探针疑阳与源码实链矛盾时先怀疑探针检测点错位，复测真实路径后撤案转正面钉**（防未来重构丢失），勿照疑阳改码。


### 3. 失败分支的落点矩阵与签名失效：保旧不能挡住恢复
fetch 类轮询的失败终点 ×（有/无旧数据）是 2×2 落点矩阵——有旧数据→保旧只标注（与「healthcard 可见=保陈旧」政策同轨，交互不失效），无旧数据→错误态骨架；只修一个象限（如只修错误体分支）则 catch 分支的「无脑掀骨架」还在。配套第二坑：**「跳过同文本」类内容签名优化，失败路径必须显式失效签名**——失败体不入签名则恢复轮同文本被跳过，「服务异常」词面驻留到下轮数据变化才退场（行为钉实抓：旧代码靠「污染签名」偶然恢复，修掉污染的同时必须补 `签名=''`，否则修 A 引入 B）；失败体入签名则同体重试被静默跳过。两害相权：清签名（恢复必处理，重复失败只是幂等重写落点）优于污染签名。

### 4. 触屏媒体查询的测试模拟走 CDP 触屏仿真，不走 setEmulatedMedia 的 features
大屏触控（`pointer:coarse`）类 CSS 清单的行为钉需要模拟粗指针环境：CDP `Emulation.setEmulatedMedia` 的 `features` 数组对 `pointer` 特性**静默不生效**（`matchMedia('(pointer:coarse)').matches` 恒 False，无报错）——媒体特性模拟只覆盖 color-scheme 等少数项。生效路径是 `Emulation.setTouchEmulationEnabled {enabled:true, maxTouchPoints:5}`：触屏仿真开启后 Chromium 将主指针判为 coarse，断言完成后 `enabled:false` 复位（共享 page 的状态复位律同前）。「模拟调用了但断言恒假」先验证 `matchMedia(...).matches` 再怀疑选择器，静默失效的模拟比抛错的更费排查时间。

### 5. 异步打开的弹层要有「取消与换代」令牌：单布尔取消标志会被新请求重置
弹层内容由 fetch 填充时（慢接口+点击即弹的交互），用户在弹层可见前按 Esc 的语义是「别弹了」——但 Esc 级联处理器只在弹层已开时有定义，在途请求照旧开层（慢路径把不可取消窗放大两个数量级时，用户「改主意后无任何退出手段，半分钟后弹层不期而至」）。单布尔取消标志修一半：取消后立刻重新触发同一入口，新请求会把标志清回「未取消」，被取消请求的迟到响应照样开层、覆盖新请求的结果。**统一形态是代数递增的序号令牌：入口发起时捕获当前令牌、响应返回时令牌失配即静默弃放；Esc 取消=令牌递增，重新触发=同一递增——「取消」与「换代」在令牌语义下是同一件事。**配套两点：迟到响应的失败 toast 同样按令牌静默（旧请求的失败提示盖在新交互上是噪音）；「是否在途」粗标志只由最新令牌的终点清位，旧请求 finally 不得动它。

### 6. 量纲源吞掉空态分支：入口判定的「非空」要把数据信号与装饰性信号分开
图表空态分支判「量纲源非空」而量纲源把参考线（达标阈值）一并并入时，参考线在场即非空——「已配置未扫描」的航线（真实数据为零、阈值在场）画出的只有两条达标虚线的空坐标系，空态文案永不可达，且服务端对未扫描航线照常产出路由条目，**每个新用户首轮扫描前必现**。**渲染入口的分支判定只认真实数据点计数；装饰性信号（阈值线/基准线/图例）只在通过入口后参与量纲与绘制**——「有参考线」不构成「画图」的理由。同族审计口：凡 `if(!X.length)` 形态的空态守卫，先问 X 的构造式里有没有非数据项被 concat/filter 进来；守卫的失败模式不是抛错而是「永假的空态分支」（死代码形态的缺陷），测试要构造「装饰信号在场 × 数据为零」的组合样本才抓得住。

### 7. 折叠详情里的探针目标要先走真实展开路径；展开会唤醒休眠资源，外域请求要 route 拦截
弹层记录列表是「条目头折叠 + 详情默认 display:none」形态时，探针按选择器找到的链接藏在折叠详情里——`offsetParent` 为 null、程序化 focus 静默失焦（activeElement 不转移），焦点环断言恒假红。**探针必须先触发条目头的真实展开动作再取件**。连带第二坑：展开让详情里的外域图链开始加载，资源级 `ERR_CONNECTION_REFUSED` 以 console error 进套件的零 JS 错收集器（与 §2 的 route.abort 污染同族）——**测试语境里对非本机请求注册 route.fulfill 空响应**（探针收尾 unroute），既断掉污染源也不改变被测行为；探针诊断串随结果落盘，「钉红是环境差还是行为差」当场可辨。

### 8. mock 必须尊重被测函数的公共契约，而不是「每次调用记一笔」
把「达标分发」函数替换成无条件记数的 fake 后，去抖修复的行为钉报「第二轮仍在拨」——真相是第二轮以**空 hits 列表**调用（真函数 `if not hits: 早退`，本就不拨），fake 无视契约把每次调用都记成拨号，功能正确的实现被误报为失效，排查反转三次。**fake 的行为面 = 被测函数的公共契约**（早退分支、返回值语义、参数含义），录制的应是「可观察的外部效果」（真实拨号、真实发送），不是「调用本身」；写 fake 前先读被测函数的早退守卫，把同样的门复刻进 fake。

### 9. 错误分档按「服务是否应答」定界，不按「哪个环节抛错」定界
轮询链路上「HTTP 应答到达但响应体不是 JSON（502 错误页/网关截断体）」与「网络不可达（fetch 直接抛错）」是两类故障：前者服务在线，后者服务失联。两者共用一个 catch 时，前者的词面被误报成「服务未启动」，把在线服务引向「进程死了」的错误排查方向（错误语义误导家族）。解法：解析门独立 try——应答体解析失败显式归「服务异常」档并与 500 JSON 错误体同轨，网络抛错保留「服务未启动」档；解析失败体不入内容签名（恢复轮同文本必须被处理，§3）。测试模拟随分档走：业务层失败（fulfill 非 JSON 200 体）覆盖「应答了」档，资源层 abort 的 console 污染使「未启动」档不可在零 JS 错套件里直测（§2）——两档各配词面钉与恢复轮钉，「未启动」档以反断言形态守护。


## 二十四、报文深挖、指纹语义与推送预算

### 1. 报文里「不可读的键」可能是压缩金矿：存疑项先做纯本地解压验证
渠道报文中高频在场却不可读的字段（base64 形态、乱码前缀）别急着排除——可能是双层编码的结构化数据。排查动作很便宜：对样本试 base64 解码后看魔数（zstd=(µ/ý），命中即临时装解码库批量解压统计内部键值域。实锤案例：某渠道行级 notes 内嵌 base64+zstd 双层压缩的策略明细，解压后得到限制类型细分 flags（限龄/限卡/限购）、权益属性、结构化 policyId——其中「限龄」结构化标记与另一处文案源在全部样本航班上同现，最终零新依赖取文案源（自带细分与价格前缀），结构化源留作语义佐证。**存疑项的「复验方法=活体抓包」不总是对的：纯本地解压零成本零风控，先做完本地能做的。**

「本机没有解码库」不构成放弃理由：Node.js 内置 zlib 自带 zstd 解压（`zstdDecompressSync`，gzip 走 `gunzipSync`），一个十几行的 Node 脚本即可对全部 dump 批量解包定性——Python 侧要不要为此引第三方依赖，等定性结论出来再权衡（结构化源语义闭合但仅挂观测时，零依赖是更优解）。同族推论：「推翻旧备案」的最便宜路径常常是新运行时自带能力，盘点工具箱先于盘点依赖。

Python 侧解码的两个工程细节：`ZstdDecompressor().decompress(blob)` 依赖帧头内嵌内容尺寸——压缩方去掉尺寸头（zstd CLI 默认可关）即「could not determine content size」全量静默失效，`decompressobj().decompress(blob)` 不依赖帧头是韧性形态；依赖的 import 用 try/except 收口为 None 哨兵，缺失时采集器整体跳过该字段而非炸掉整渠道。**落地新载荷解析后，必须用生产 dump 做真实回放（green 级验证）：解析器落值分布与调研探针的统计逐桶全等（出勤数/值域分布/特例行），合成样本测试只证明协议理解，回放全等才证明读层与结构没错位。**

### 2. 聚合指纹的「宽」是特性还是缺陷，看跨渠道协议依赖什么
「同刻异号 codeshare 班混入同组」看似指纹缺陷（指纹不含航班号），实则跨渠道补全/比价正是**依赖时刻指纹**才能跨渠道配对——同一物理班在不同渠道给不同航班号（营销号 vs 执飞号），把航班号加进指纹即打断跨渠道补全。多值冲突有「值冲突不补」守卫拦着、等值场景写值无数额后果时，宽指纹的误配面远小于收窄指纹的断裂面。**收窄聚合键前先枚举「谁在依赖这个键做跨源匹配」；键上每加一个维度都要回答「这个维度跨源一致吗」。**

### 3. 推送正文要有字节预算：构建端降级优于发送端截断
钉钉类通道有硬字节上限、截断保头部——尾部恰是明细总表（比价唯一载体）与 @手机号 段。发送端截断只留一条泛化「已截断」尾注，不说明丢了什么。正确姿势在构建端：预算内小节原样、超限后非关键小节降为单行 mini（价格/差额/链接核心判据保留），**mini 行是地板档恒落位**（守卫链尾地板档纪律在推送字节数上的投影），并出说明行防「推送数据缺失」观感；发送端截断尾注补丢失面语义（「尾部明细总表/对账段未收入」）作为最后防线。降级是构建产物形态选择，与重发/重试无涉——单发零重试铁律不受影响。

### 4. 合并键的「或」回退是漏合并温床：跨源写法差先归一再进键
合并键写成 `(code or name, ...)` 时，一端 code 缺失回退 name、另一端 code 有值——同一物理班因渠道写法差（营销名全称 vs 裸航班号）键不等而漏合并，「同价×N」角标丢失、TOP5 双槽被同班占。修法是 code 缺失时从 name 尾部正则提取航班号参与键（与既有收口先例同款正则），同班不同价仍不合并（价格在键内，价差即比价信息）。**凡「或」回退构造的键，枚举两端真实形态对齐验证一次。**

### 5. 筛选 chips「默认全亮」稀释选中语义：空集=全部就该空集呈现
集合型筛选若过滤语义是「空集=全部」（守卫 `size && !has`），初始回填全选就是视觉撒谎——满屏实心选中片让「只看一个」的降选动作失去对比。初始空集即可：语义不变、视觉中性、选中动作才有意义。配套确认三件事：过滤消费点的空集语义真实在案、防「未初始化回填」的标志位仍工作、「全选档」单选器（时段类）不在此列（真单选的「全部」亮着语义正确）。

### 6. 同名配置在两种载体上（dict/对象）时，过滤条件必须双形态兼容
同一份「用户航线」在生产路径是 dict（含 enabled 等配置维度）、在演示路径是 dataclass 对象（字段子集）——过滤条件写 `r.get(...)` 在对象形态直接 AttributeError 炸掉整个接口；写 `getattr(r, ...)` 则生产 dict 路径失效。正确形态是入口处分支：`isinstance(r, dict)` 走 get、否则 getattr 带默认值。**改共享数据结构的过滤/读取前，先枚举它的全部构造来源（生产加载/演示合成/测试手造）。**

### 7. 交互按输入设备分路径：桌面 hover 即读数，触屏要「读数→确认」两拍
canvas 类「点击跳转」交互对触屏是陷阱：轻 tap 没有悬停预览、点了就离场，用户既读不到数值也无法「点一下看看」。双 tap 方案：首 tap 保留十字线读数并记锚，同点二次 tap 放行跳转，异点 tap 换锚重读；桌面鼠标路径不经过该状态机行为不变。实现要点：tap 的 click 在 touchend 后合成，放行标志（而非坐标比对）驱动跳转——「touchend 记锚 + click 判坐标」会把首 tap 误判为二次 tap（锚与点击必然同点）。

### 8. 审计建议也要过证据关：合并重复 CSS 块前先验证媒体条件语义
两段逐字相同的规则块可能不是冗余：一段是 `900px+粗指针`（平板保护）、一段是 `≤760px 任意指针`（窄屏），条件语义不同、删任意一段都留保护空窗。修正做法是注释互指防清单漂移，不是机械去重。**审计产出的「重复/冗余」结论，落地前先回答「这两段为什么会同时存在」。**

### 9. 本地探活必须绕系统代理
本机服务的健康探活（脚本 wait_up/启动等待）用默认 urllib/curl 时会被系统代理劫持（代理进程持连、回环地址照样被代理转发失败），症状是「服务明明活着、探活恒失败」。探活一律显式空代理（`ProxyHandler({})` / `curl --noproxy`）。环境变量层 NO_PROXY 没配回环地址时尤其必踩。

### 10. 渠道标签的单向定性会被静默推翻：双态化落地守两条约束
「渠道只标无餐食（负向）」的旧定性被下一轮 dump 机械 diff 推翻——同一标签位出现「有餐食」正向打标。渠道对标签语义边界（单向/双向）的扩展是静默的，代码侧无从预警，唯一防线是每轮全量键 diff 把旧定性一并复验。双向化落地守两条：值域并入既有键（零新键，消费端零改动）；多段合并遇两段异值时保守仲裁为负向——一段「无餐食」=全程存在无餐食段，正向优先会掩蔽这个事实。**「出现即真」的负向标签扩为双向时，逐消费点核对有没有按「非空=负向」写的门，别让正向值滑进负向分支。**同族变体：白名单的「排除依据」同样是需要复验的定性——「与既有出口同义不收」这类排除论证会被渠道静默扩展证伪（同一词面换了独立载体出现，而行内并无既有出口承载，不收则该权益信息永久缺失），每轮全量键 diff 要把「为什么不收」的依据一并复验，不只复验「收了什么」。裸词转正的证据分级也随之定界：**同结构槽已有同族映射在案（家族律自洽）+ 受限价与行内最低有票价互证 + 跨轮独立复现**的裸词可凭推证链收编（与无家族推证的裸词「宁缺勿错」分属两档）；同族双源并存时还要防同词面重复拼接（价格前缀形态与裸词形态同现一格，拼接须去重）。

### 11. 组合实体会继承单件字段的槽位：占位值域守卫要按「结构不可信」收口而不是逐渠道打补丁
准点率是单航班属性，但组合类行（两段拼接的中转）没有单一真值可填——渠道用 `0` 填槽，守卫若只盯另一渠道的恒值占位（如 20），`0` 族就从组合行流入库并渲染成「准点0%」假数据。**凡「组合/聚合行继承单件字段」的槽位，占位形态是结构性的：读层按真值域挡（≤0 置空，与脏值弃同律），消费端词面守卫收单源（0 族形态置空通吃存量行），两层各自独立成立——读层管新轮根治，消费端管库内存量与其他渠道的未来形态。**判别「哪些槽位有此风险」的口径：字段语义是单件级的，而行实体存在组合形态的，全部在列。

### 12. 真源槽位下发的占位值，要连同伪源一并置空
渠道给某字段设了「真源+伪源」双源时（真源=tag 词面抽取，伪源=另一结构槽恒两档值），真源下发占位值（组合行填 0%）而守卫只挡真源自身，伪源就会借「真源缺席」的空位兜底落库——渲染出比「准点0%」更隐蔽的「准点100%」（0 一眼假、100 像真的）。正确语义是「真源在场即定谳」：有值覆盖伪源、占位值连伪源一并置空，伪源永远没有兜底资格。配套观测律：占位挡修在「主链末尾」而「真源覆盖分支」在其后时，覆盖分支必须复用同一值域挡——守卫只挂在一条路径上是漏挂。

### 13. 曲线-列表对照是「同刻互证」，不是单调关系
对照脚本把「曲线尾桶 vs 列表每个历史桶」当对照，会产出 84/86 的系统性假分歧（历史桶价格当然可以≠尾桶）；对照的唯一合法形态是曲线点按时间戳建索引、与列表桶逐桶同刻对齐互证。复用上一轮观测骨架时，对照主循环要整段照搬逐桶对齐结构，不能「简化」成尾点比较。配套：对照脚本读配置的键名与生产 config 实际键名不一致（`from_code` vs `from`）时产出 0 桶假象——「整齐的零」先核脚本结构再信数据缺席（§1 同族）。

### 14. 落库满值可能是不透明上游的默认词面透传：双源 raw 形态对照后再定性
某渠道准点率落库「100」占比近两成，形似占位回流或解析缺陷——双源 raw 对照定谳：真源 raw 值域零 100、伪源恰只产 {100, 97}，且与另一渠道的 100 完全同步（同航班对全同值）——是渠道上游的默认词面透传，非占位、非解析错。**判定「可疑满值」前先取双源 raw 值域对照 + 跨渠道同步性证据：真源不在场而伪源恒档值=占位（置空），真源在场的满值=合法值，上游默认词面透传=渠道本态（屏蔽与否属产品决策，不是解析修复）**。三种形态共用同一词面，单看落库值不可分辨。

### 15. 并列数组的「按段」与「并列备选」判型：结构假设先过子结构载荷互证，再定扫描域
报文里同为「数组多元素」的舱位/旗标形态，语义可以是**按段**（每元素对应一个航段的舱位，政策价=各段之和）也可以是**并列备选**（同一座位的多个舱位档，价格只对应其一）——表象相同，扩扫行为天差地别：按段型任一元素的资格旗标对整行真实生效（整程含该段票即受制），备选型非对应元素的旗标是错挂的半假数据。判型证据在子结构载荷里：政策 zstd 载荷的段级 `(price,grade)` 与元素舱位字母位序一致=按段实锤，「元素数==段数」的结构门由此来。**「直接扩扫会错挂」的担忧本身要靠结构实证裁决，而不是靠保守放弃**——按段型被保守首元素门挡住时，字段是恒零出勤的死键（落地即未通电）。配套：元素数≠段数的形态属未证形状，维持单元素宁缺勿错，不随大流扩扫。

### 16. 候选字段的增量判定：先与已采出口做词面配对，同源即零增量不采
调研差集里的「独立结构化键」（如机型厂商字段）与已采展示键（机型名）做逐段配对后发现：厂商词面前缀与展示名词面**完全同源**（厂商=C919 的行，机型名前缀恰为 C919）——「未采」是幻觉，信息早已随展示键入库，再落一份数据孤儿或冗余标签。**差集候选的落地判据不是「报文里有、库里没有」，而是「读者能看到的信息增量」**：候选键的全部词面被既有出口覆盖时零增量不采（进不采清单防重复调研）；配对验证用真实样本值域（非键名推断），且要在两份以上独立 dump 复证。

### 17. 数字码→中文词的映射只在「词面复验通过期内」有效：渠道会静默重定义码槽
某渠道舱别码 cgrd 旧代 dump 实证 {0:经济,1:公务,2:头等}（有全班仅剩「头等」高价的真实样本背书），数代之后同码槽静默漂移为 {0,2} 两档且 2=公务——渠道词面（政策级舱别中文注记）与码映射全面矛盾，而按旧映射落库的高档参考价行近半数被错挂词面（价位倍率、舱位字母族、渠道词面、值域出场四个独立面同证）。**带词面的数字码，渠道自带词面是唯一权威：码→词映射每次全量键 diff 都要把「映射期」词面并现率一并复验；修正落码时同步枚举旧证据注释（它们陈述的是旧代事实，不删、标注代际前提），消费端透传词不设值域门就不破。**同族推论：demo/演示数据的样例值若属「语义修正后不可达的形态」，如实退役为可达值——演示面展示不可达形态=误导下一轮排查。

### 18. 恒档占位守卫的零误杀证据在历史值域里；读层+存量迁移是双半边，消费端词面守卫此时不可用
第二起渠道上游恒档透传（准点率全量塌缩为恒「50」，旧代同字段多值 {100,97,90} 健康在案）——「该值不在历史真值域」是比「与跨渠道同航班背离」更硬的零误杀证据：全表历史值域从未含 50，挡它不存在误杀真值的可能。处理与 tuniu 恒 20 同律但多出两个增量：**①伤害经告警链同指纹决策字段补全放大到其他渠道行（缺 prate 的行被补上假 50），定性伤害面时要追「库内合并/补全」这条放大路径，不止看本渠道渲染；②存量净化不能走消费端词面守卫——50 不是跨渠道恒假值（其他渠道真值域含 50），跨渠道单源守卫挡不住；正解是读层恒档置空（管新轮）+ 一次性 DB 迁移（管存量），且迁移要防「迁移后旧代码进程再落新脏」的竞态：守卫生效（进程重启）之后再迁，或迁完复查一次。」守卫本身挂观察哨：渠道值域恢复多值即撤守卫复采。**

## 二十五、观测脚本结构与地板档预算

### 1. 对存储结构做键统计前，先打印一次真实结构
观测/审计脚本对数据库半结构化字段（JSON extra）做键出勤统计时，若按「dict 直查键」实现而真实形态是「list 内嵌 dict」，`k in obj` 恒 False——报告产出全零假象，上一轮据此「验收通过」的结论全部作废。正确姿势：统计逻辑动笔前先对生产样本 `print(type(obj), list(obj)[:5])` 确认结构层次，再写遍历；报告出现「全部字段 0%」这类整齐划一的零，第一反应是脚本结构错位而非数据缺席（真数据缺席是逐字段有零有非零的锯齿状）。

### 2. 「地板档恒落位」在硬上限面前的正确形态：地板档总额预留制
降级链的地板档（mini 行）在「恒落位」纪律与「总字节硬上限」同时成立时，逐项落位再加预算判断会产生倒挂——全量档优先吃满预算后，地板档要么被吞（关键价蒸发，比不降级更糟）要么放行（顶穿切点，把更高优先级的尾部载体切掉）。正确形态是**预留制**：预算先全额扣除全部地板档的总量，全量档在剩余空间竞争，挤出的条目转地板档补位——每条数据至少保有关键字段，总字节恒闭合。「恒落位」的正确实现是「设计预算使其恒可落」，不是「无条件放行」。

### 3. 观测快照对实时文件抽验：样本必须剔除「晚于快照时刻」的记录，固定偏移拟合口径在逐点波动时不存在
push_history.jsonl 是实时追加文件，DB 快照是某一时刻的冷拷贝——环比抽验若不把「晚于快照时刻」的推送行剔除，会拿快照后落库的新轮数据复算快照前推送的环比标注，得出系统性假反转（实测 10 行假 REVERSE 经第二快照复验全部同值归零）。**抽验集的时间界以最旧的数据源为准**。配套：「固定偏移拟合」类口径（如按推送时刻减 N 分钟截断复算）在逐点上界波动（-1~-6 分钟不一）时不存在，此时改用「逐点敏感扫描定性」替代单口径判定——先回答「噪音还是真违例」，再谈口径。

方法侧三坑（观测脚本自审增补）：跨渠道同刻对齐**禁用同秒锚**（两渠道打点时刻秒级错位时首版全 None，先核各源时间粒度再定对齐键）；哨兵回算须按**单记录粒度**（末桶合并两日期行曾把两条真实告警合并误判成假火）；曲线-列表两端滑窗须**钉同一时刻**（窗口端点一端用 now() 一端用快照时刻，曾产出 1+1 窗界伪桶假分歧——「整齐的首尾分歧」先核两端取时再信数据）。

### 8. 「零记录」与「有记录 0 行」是两种故障形态：消费记录行的哨兵对前者天然失明
风控断供/接口失效形态下渠道**不产生任何记录行**（请求发出、返回空、无行可落）——凡以记录行为输入的观测面（行数历史池、空明细计数、字段命中率）对该形态双双失明：无记录→历史池不入池→塌方哨无基线；进程重启清空历史池后更是永久失明，「重启丢一轮基线不漏报持续故障」的注释只对「仍产记录」的渠道成立。**渠道级断供观测必须在「渠道行数聚合层」做**（本轮全部查询的合计行数，与记录行存在性解耦）：连续 ≥N 轮零记录才告警（单轮零返回是瞬时风控常态），当日去重防刷屏，恢复出数即归零。判别「哪些哨兵看不见零记录」的口径：逐一问每个哨兵的输入集合里有没有「本轮该出勤的渠道集合」——只有记录行没有预期集合的观测，都默认了「无消息=无故障」。

### 4. before/after 双代对比的基线环境必须真实分离：「两组结果全同」是基线失效的强信号
双代重放对比用「版本控制系统的父代内容构建基线导入树」时，基线目录必须插在项目根**之前**（模块检索按 path 顺序解析；顺序颠倒会让 before 悄悄跑在 after 代码上，产出「零差异」假结案）。**真有增量的两代不可能逐键全同——「全同」先怀疑基线没切换，再信数据**。同族坑：基线树要按被测包的 import 闭包补全（包初始化文件全量导入兄弟模块时，缺一个模块=整树加载失败，报错点却常在毫不相干的下游 import）。

### 5. 写库静默≠轮已收尾：静默门之上加轮界锚
「db_max 双读 25s 不变」的静默门会撞进轮中渠道慢查询/重试圈的写库间隙提前通过（对齐时刻非轮界），互证窗口按 420s 断口轮带切时与 payload 端的「每渠道日期最新轮+stale 门」口径错切，产出整轮 PF-only 伪分歧（分歧桶行集逐行在库=铁证）。**静默门之上加轮界锚：db_max 所在轮的「本轮扫描结束」日志行必须已落**（`db_max ≤ 轮界 ≤ db_max+轮时长余量` 才认对齐）——写库静止是轮收尾的必要条件而非充分条件，轮闭合的唯一权威是日志轮界行；快照对齐语义是「对齐一个已完成的轮」，不是「对齐一个静止的瞬间」。

### 6. 行为归因先核「进程加载态」与「行路径形态」：工作树源码不是生产行为的证词
观测/审计对生产行为变异做归因时，两道错锚高频出现，且都能产出「证据链自洽」的错误结论：
- **拿工作树源码当生产证词**：审计脚本读盘上的解析器代码，看到「代码里已无此产出」就断言「生产不再产出」——运行进程加载的是**启动时刻**的快照，热重载不重新 import 模块（三.5），磁盘代码对 ≠ 进程内存对（十.4 同族）。归因前先对账进程 CreationDate 与文件 mtime：行为变化界早于在途改动写盘时刻的，变化来自上一代代码；「进程启动早于末次写盘」时，旗标型改动（不触发即无痕）在磁盘与运行态可以长期并存两种行为。
- **跨路径行为混窗统计**：同渠道多路径（PC 主路径/H5 兜底）产出同族行时，仅凭「键在场率骤降 + 重启时刻对齐」归因「某路径撤伪已生效」，实际可能是**另一路径**的同族键在更早的部署里已撤——夜间轮走的恰是兜底路径，路径未分流前总量出勤没有归因力。判定某代码变更「已生效」需要证据链闭环到**具体路径的行形态**（行级路径标记键先分流再统计），而非总量出勤或推送词面 A/B。
- **「停摆/断供」类警报先核配置启停态再定性**：航线/通道级启停开关是「预期静默」的合法来源——用户停用全部航线后，末次落库时刻冻结、进程空转零写入，是用户决策的直接后果而非调度缺陷。观测/调研 agent 对「末次落库距今 N 小时」类信号立案前，先读配置的启停位并核对停用动作时刻：`max(fetched_at) ≈ 停用时刻` 且停用后零写入零报错 = 预期静默；停用态下仍有零星写入或报错才是真故障。该假案会在每轮新派的 agent 上重复「发现」——每轮调研 prompt 都要预埋此判例，否则它就是观测面的常驻误报源。

### 7. 聚合出勤率的分母必须按行群分流：异质行群稀释制造跨渠道错归属
「字段出勤率」把结构异质的行群（如直飞行与中转行）合进同一分母时，低聚合值可能只是某行群结构性无源（中转行天然无该字段载体）稀释了满勤行群（直飞行 100%）——聚合读数与任何单一真实面都不对应；跨渠道横向对账时，这个聚合值还会被张冠李戴到别的渠道头上，据此立的「寻源」挂账方向天然是错的。**出勤类指标的分子分母先按行群切分再聚合**：聚合值只作总览，定位与归因一律用分流后口径；多渠道横向比较前先核各渠道「分母行群构成」是否同构，不同构的数字不可互比。引用既有报告的数字立新挂账时，先复算分子分母的行群构成再立案——数字本身对，归属错了照样把几轮调查引向死胡同。
实现侧三细节（哨兵分流落地实录）：**分子分母必须同口径切到同一行群**——分子留全行命中而分母只数直飞=比率虚高、断链观测钝化；**观测门槛随分母平移**（行群样本不足的本轮整批不观测，行群观测的样本就是行群自身，混回全行门槛=稀释面从比率挪进门槛判定）；**收编既有统计块时按「桶键→行键」映射逐键核对**——桶名与报文行键存在历史命名差（psize 桶读 planeSize 行键型），统一 `f.get(k)` 遍历会把映射差静默读成恒空（伪缺勤要靠值域全零的整齐假象反查）。

### 8b. 观察哨的立案前提本身要过证据关：「dump 在案」的断言先核语料代际与输入形态
观察哨挂账时写的「某形态在 dump 在案」可能把测试注释、历史调研里的实证案例误当作现行语料——复核回放时冻结 dump 全量缺席、关键词面计数全零，哨的翻身前提建立在不存在的语料上=哨位空转，下一轮按哨位复核会从假前提出发白走一轮。回放类核验另有输入形态错位坑：解析器吃的是渲染后文本而快照落的是页面源码，回放 0 行时先核「喂的形态对不对」再下「分支不可达」结论（0 行可能是样本构造错位而非数据缺席，「整齐的零」先怀疑脚本）。配套：哨的结案要在原报告就地补注记（前提不实/已验证/维持+证据），让下一轮看到的是结案态而不是悬置态；哨词面计数为「整齐的零」时先换关键词与多编码探测再定性语料缺席。

### 9. 配置面预期与异常面共用一个告警词面＝排查误导：空产物路径按「启用实体数」二分归因
「图床无可用通路，本报告未发」以 WARNING 级每轮刷进日志的实录里，真实成因是用户停用了全部航线（配置面预期静默），词面里的另一因「图床断路」从未发生——后续观测据此误定性为「图床缺路」立案，直到核对上传层日志（真断路必有细粒度失败记录而全零命中）才翻转定性。**空产物（无图/无数据/无报告）的归因词面若把「配置面预期」（实体全停用/未配置）与「异常面」（有实体但渲染/上传/查询失败）合并成一句，日志自身就不再可归因：预期态刷成告警级是噪音源，异常态被词面带偏是误诊源。**修法是在空产物分支按「启用实体数」二分：零启用实体打 INFO 静默词面（明说「停用或未配置」），有启用实体而零产物才保留告警词面；归因判据与产出端过滤共用同一单源口径（启用实体过滤 helper），防两处口径漂移。

## 二十六、协议镜像与缓存时延

### 1. 解析类测试的样本形态必须取自生产 dump 实证结构
某渠道「平均延误」字段在报文中的真值位于 `binfo/binfo1` 分段层，读层却按 flight 顶层取——发版时的回归测试把样本值**自造在顶层**，测试全绿、生产落库 0 命中。测试 fake 是协议对齐的双向镜：它只照了写侧（出口键存在），没照读侧（报文真实层级），绿测试保护的是臆想协议。**写解析测试前先打开生产 dump 定位字段的真实层级；「在码但 0 命中」类问题，第一反应是打印一层样本核对读层与结构是否错位。**配套律：修读层时同步修正旧样本形态（旧用例的注入位置也要跟着真值层走），并在变异验证中确认守卫分支真红过。

### 2. 缓存重建窗口内的「数据丢失」先排除 stale-while-revalidate 时延
签名缓存的全量重建以分钟计（全历史 extra JSON 逐条解析），新轮落库后的短暂窗口内，API 返回的是上一签名快照——「DB 直读有值、API 读无值」并非丢键 bug，而是 SWR 时延假象。**两侧取证必须时序对齐：先触发重建、等完成信号（或延迟数分钟）再读 API；DB 直读与 API 读在同一时刻做，结论才可比。**观测类判据同理：环比计算时刻、打点时刻、推送时刻是三个不同时点，以中间字段当组装时刻做截断复算会得到系统性噪音。

### 3. 图床选型的双端约束：上传端可达 ≠ 显示端可达
上传发生在服务器（可以有代理），显示发生在读者手机（必须读者网络直连可达）——两端网络条件不同，同一图床两端的结论可以相反。服务器走代理对图链取到 200，证明不了读者手机拉得到；「读者实报看不到图」是一手证据，优先级高于服务器侧任何探活结论。图床备选按「**显示端读者网络直连可达**」筛选（实测口径：绕开一切代理 curl），上传端直连不通时走代理兜底即可。当下通路：GitHub Contents API 传公开图库 + jsDelivr 显示（路径含时分戳防 CDN 陈旧缓存，新文件首取即回源）；免注册图床会封禁/失稳，付费接盘不可取，自家基础设施（自有 GitHub 库）是长期解。

### 4. 资产获取的第三条路：本地已有就不下载——路由级劣化换域名无效
发送端把推送图下载回来内嵌（邮件 cid 通路）时，下载失败率若高达四分之三且两个候选图床域名实测同为间歇可达（各四分之一成功率），不稳的是**本机出口路由**而非单一主机——换域名、调超时、加单次重试都救不了路由。此时先问「这份资产本地是否已经存在」：图在推送前几秒刚在本地渲染落盘，URL 尾段文件名与本地文件名存在确定性映射（远端 `{stem}_{时分}.png` ↔ 本地 `{stem}.png`），直读本地归零失败面，网络下载只留作本地 miss 的兜底。**直嵌本地必须带防陈旧门（文件 mtime 超过覆盖周期不直嵌）——延迟重发场景本地文件已被下一轮渲染覆盖，图文不同源比丢图更糟：宁慢勿错在资产层的投影。**

### 5. 远端资产路径的写入唯一性：时间戳粒度要覆盖最短重传间隔
心跳推送与日报同一轮各自渲染上传同名趋势图，远端路径时间戳只到分钟——后到者对已存在路径 PUT 缺 sha 被网盘 422 拒绝，日报该图整节蒸发（文本兜底在，图缺失）。**远端资产路径必须「一次写入永不重写」：文件名里的易变段（时间戳）粒度要小于任何两次同内容上传的最小间隔**；粒度收紧后，消费端按 URL 尾段反推本地文件的确定性映射要同步兼容新旧双态（存量推送记录里的旧形态 URL 在延迟重发场景仍会被解析）。同内容重传在「路径恒新」下天然无害——每次都是新文件，无需删除或覆盖语义。

## 二十七、虚拟化渲染与聚合拓扑

### 1. 增量加载与「跳到底」语义互斥：键盘跳转必须显式补全量，不依赖滚动事件接力
明细表切片化（首屏 N 行、滚动近底续载）后，键盘 End 跳底在演示数据上侥幸可用、真机大数据上落点距真底数千 px：按一次 End，浏览器平滑滚动到**当时的**底边并触发滚动事件，续载补出的新内容把底边推远一整个切片，而「落点距底 <600px 才续载」的触发条件被这次续载**自己**破坏（距底瞬间变成数千 px），循环第一片后就退出；同时内容增长会终止平滑滚动动画，滚动位置冻结在旧底。演示环境数据少（两三片即全量）、续载次数少，事件接力偶尔走通——**小数据上的侥幸通过是这类交互缺陷的标准假阳性**。正确形态：键盘跳转类交互（End/翻页尾跳）在切片/虚拟化容器上必须走显式路径——一次性补完全量、再滚到端点、并交接端点焦点（连续按键不落空）；滚动事件的增量续载只服务拖拽与惯性滚动的连续接力，两条路径别混。

### 2. 聚合器拓扑会吞掉成员的通道级信号：上层守卫读什么，包装器就要透传什么
日报「-1 幽灵送达按已推落账」防重发守卫读 `notifier.last_errcode`——单通道时代钉钉 notifier 自留痕，守卫工作；换成多通道并联聚合器后，聚合器没透传该属性，`getattr` 恒取默认值，守卫静默休眠（钉钉幽灵+其余通道同轮失败时日报重推）。**在成员对象上留痕的语义信号，聚合/包装层必须显式上浮（透传时每轮先清防跨轮残留，成员异常路径同步清成员留痕防旧值被拾取）；上层守卫的消费点枚举要核对「现网实际注入的是哪层对象」——审查时对守卫的 getattr 链逐层走一遍，别只看单通道类有没有这个属性。**

### 3. 吸顶与内滚双滚动架构并存互不兑现：触发点必须在几何上可达，源码钉绿不证行为生效
吸顶（sticky）声明的触发前提是「页面可滚到元素自然位以上偏移量」，而表格容器的内滚 `max-height` 把页面总高限死时，吸顶触发点可以**结构性**地超出页面最大滚动量（差口随视口缩小扩大）——声明在案、源码钉绿、实测永不触发，是「死代码」而非「已实现」。两种滚动机制并存时各自的触发前提可能互相消灭，修复必须二选一：放开内滚让内容跟页滚（同轮把续载监听/键盘跳底/滚动位恢复三条内滚路径全部重接线到页面滚动，双容器监听加互斥门防水平滚动伪事件），或撤吸顶改表内表头常驻。**吸顶类改动的验收钉必须是几何行为钉（滚到深处后量 `getBoundingClientRect` 是否钉在目标偏移），源码钉（字符串存在性）只证声明在场；且几何钉要在「容器内容高不足」与「触发点不可达」两种反例上验过会红。**

### 4. 触屏媒体态会被截图动作本身污染：移动档几何断言必须在任何截图之前采集
移动仿真上下文（`is_mobile`+触控模拟）里执行全页截图，Chromium 会把 `pointer:coarse` 翻转回 `fine` 且不可自愈——截图之后量到的触控命中区、chip 密度全是污染态。**媒体查询类断言与截图共享同一个页面状态时，先测后拍；批量截图产出的「排版失真」若与几何测量批结论冲突，以先于截图的测量为准，并把该伪影记入探针备忘防下轮误判。**

### 5. 进程重启边界的单桶分歧：跨代快照对比先核「桶是否跨重启」，等全桶同源再定性
采集进程重启后，曲线端最后数桶由旧进程写入、列表端从 DB 复算会取到新进程首扫落库的行——同一时间桶两侧认定的「渠道最新价」可以跨代不一致（单桶、小额差值）。**曲线-列表互证出现孤立分歧桶时，第一反应核对该桶时刻是否横跨进程重启边界（对照进程 CreationDate）；跨界桶属交接缝时序假象，等出现全桶由同一进程产出的轮次复测归零再关案，勿据单桶立案改码。**

### 6. canvas 入场动画的揭示矩形必须覆盖全部常驻内容带：钳零断根因，揭示域定终态
入场动画用「clip 矩形随进度增长」实现揭示时，矩形起点若落在图体左缘，坐标轴标签这类「常驻内容带」（每帧都必须在场的非揭示内容）就从未进入 clip——动画只应揭示图体，不该连带决定标签的生死。负进度钳零只修掉「负宽矩形按 canvas 规范反向归一、恰好罩住标签带」的首帧事故（归一形态反而比钳零后多画了标签中段切片），**真正的终态锚是「动画末帧与非动画全绘逐位等」**：不满足即揭示域本身设错，改矩形起点而非只堵边界。配套两条：①「边界值输入」（rAF 首帧时间戳可早于 performance.now()，负 p 是真实可达路径非臆想防御）；②行为验证的时点采样会撞上页面周期自刷新——轮询重绘可在断言窗口内偷偷做一次全绘把墨迹补齐，产生「修没修都对」的假绿，墨迹类断言要么以终态为锚，要么先冻结刷新源再采样。

### 7. 同一事件批次内轻量动作排在重绘制之后：探针等待余量按最坏数据量取
视口变化批次里全量图表重绘在横滚暗示重判之前同步执行——演示数据重绘毫秒级，生产全量历史重绘秒级，「改变视口后等固定毫秒再断言」的行为钉在演示环境全绿、生产同窗口读到「重判未执行」（批次还阻塞在重绘里），下一秒才挂上，症状是「功能正常、探针矛盾」。**同一事件批次内把量纲重判这类轻量动作排在重绘制之前（或与绘制解耦），跨环境行为验证的等待余量按最坏数据量取；「演示 true、生产 false」的探针矛盾先查批次内执行序与数据量差，再怀疑功能本身。**

## 二十八、词面工程与跨语言边界

### 1. 修复词面的新形态先过字符禁律，别让第一处例外开进推送正文
「距线不足半点」的档位词修正曾拟用「<1%」——按 HTML5 解析 `<数字` 不开标签、桌面渲染实测无恙，但钉钉 markdown 渲染器行为不可实测，而尖括号家族是全禁律（曾把后续文字整段吞掉）。**拟入推送正文的每个新字符都要过「确定安全字符集」白名单，解析器规格上的安全不等于渲染端实测的安全；有零风险等价词面（「不足1%」）时绝不开禁律第一例外。**配套：派生律的姊妹点要同轮全量清——同一「四舍五入到 0%」病在 KPI 摘要、建议行、KPI 行1 尾注三处各自独立存在，修单源只收口直接消费点，grep 同病形态逐点定性（收口或备案）。

### 2. 跨语言同源词面的数值边界要按「舍入结果」定义，不按「原始值域」定义
Python `.0f` 半点走 banker 舍入（0.5→0），JS `Math.round` 半点向上（0.5→1）——「<0.5 出修正词面」的边界定义在恰 0.5 处两端分叉。**两端必须同语言的词面，边界条件按最终输出定义（「舍整为 0」→ Python `round(pct)==0`、JS `np<=0.5` 显式含边界），并配恰边界值的双端用例**——单端绿测试护不住另一端的舍入语义差。

### 3. 测试钉的存活依赖消费点：孤儿键转正时钉面从「不许存在」翻转为「必须带消费」
某 brief 字段曾因前端零消费被删并钉「不得存在」；后续 delta 按日期精确匹配需要它时加回，旧钉即翻红。**「防孤儿键」类钉的语义是「无消费点不得存在」而非「永久不存在」——字段转正时同步把钉改写为「必须带且被消费」（断言消费点真实在案），防未来再退化为孤儿**；否则后人在旧钉与新技术需求之间只能删钉逃避，钉的防退化价值归零。同族：全写点计数钉（replaceState 计数、send 计数）随合法新写点同轮 +1 并注明来源，计数钉锁的是「写点受控枚举」不是「永恒数字」。转义纪律族姊妹：钉锁「字段过 he() 转义」时，渲染形态演进（整体直出改分段 map）后钉面要随形态改写但**转义语义断言保留**（逐段 he 在案），形态字面与语义担保是两层。

## 二十九、落地可连性与伪语义出口

### 1. 特性落地前必须用真实 dump 端到端 replay：fixture 构造的载体形态可能根本不可达
某渠道行级 notes 里稀疏出现的接驳提示句被立为新特性，测试用「带航班号+有票政策」的 fixture 全绿落地——而真实 dump 里该句的载体行全部**无航班号且无有票政策**（空铁联运占位行），解析器的上游守卫（无航班号整行弃行）在新增提取逻辑之前就把载体丢掉了：端到端 replay 冻结 dump 两轮 0 行命中，特性落地即死代码，配套消费端与测试全部陪葬。**fixture 只证明协议理解，回放全等才证明读层与结构没错位——新提取逻辑落地前，先跑真实冻结 dump 过真实解析器入口数命中数**；解析链上游的任何一个守卫分支都可能让「结构上在场」的字段在链路上不可达（廿六§1 的落地侧孪生：那条管测试样本形态，这条管特性本体）。fixture 与生产载体形态不一致本身就是立案信号：问「生产里这字段长在什么行上」。

### 2. 默认映射惯例会遮蔽伪语义出口：被显示惯例「兜住没出事」的键也要进值域漂移复验
某渠道中转行的舱位代码键被推断为「同义舱位代码」移植，其值域长期停在几个字母上，展示层「未知字母默认经济舱」的惯例把错误语义伪装成合法「经济舱」显示——多年无恙。值域静默漂移进高档舱字母映射后爆雷：经济舱价位行被推成「头等舱」、比价组被误判跨舱位假离群。dump 解剖定谳：该键只在中转行出现、值域含两字符形态、价位与映射语义差 3-5 倍——是段级折扣桶（多来自廉航第二段）而非行级舱位，移植当初的语义推断即错。**语义靠推断（非报文/页面实证）的键是伪语义出口：值域分布 × 价位等级 × 行形态三面互证定性；定性为「无害」要连同「为什么无害」一起复验——靠显示惯例兜住的无害是延迟引爆，不是安全**（廿四§10 的姊妹律：那条讲定性被静默推翻，这条讲错误定性被惯例遮蔽）。

### 3. 跨政策聚合守卫把「错配」降级成「缺勤」：出勤率基线异动是配对缺陷的第二信号
某渠道舱位代码走「全政策列表聚合恰一个代码才落」的宁缺勿错守卫，多政策并存行恒不落——出勤率长期在低位随渠道行为漂移，被当「渠道下发行为变化」观测数轮；改为随选中价政策聚合后，同字段出勤立刻恒定满格且零错配。**凡「配对类信息 × 跨实体聚合守卫」的组合，出勤率异动要先回查守卫几何是否遮蔽了本可配对的信息，再归因渠道**；同族：舱名取「首个有值政策」而价格取「最低价政策」的隐式错配，正是靠聚合守卫的缺勤面掩护了多年（配对纪律：舱名/折扣/舱码/运价全部随选中价所在政策提取，一个遍历出全 tuple，防二次遍历口径分叉）。

### 4. 「无值不落键」的门型是字段级实证结论：int 槽位用空串哨兵门（`!= ""`），不用 truthy 门——0 在这个槽位是真值、在那个槽位是占位
给「空串也落键」的载荷卫生收口时，门写 `if x:` 还是 `if x != "":` 不是风格：truthy 门把显式 0 一并丢弃。同一数字在不同槽位语义相反——准点率 0 是组合行占位（丢弃正确），取消率/廊桥率 0 是渠道显式真值（丢弃=该值族出勤塌方，且哨兵「键在场」口径被静默改写成「非零值在场」，全 0% 日期将以「键名失效」词面误报）。**0 的真伪逐字段实证（值域分布 × 行形态 × 在案判例），门型跟着结论走；真值族照落的门要配零值落键的正向钉，防下一轮「卫生化」把 0 再吞掉**。连带两律：推翻在案判例（如「0 为渠道显式真值」的旧备案）必须证据记录在案，旧备案 docstring、消费端协议注释、引据注释三处在案记录同轮对齐；拿同族渠道的门做引据前先打开引用点核对语义——引据失实时理由建立在不存在的面上，真实行为（丢 0）无一处陈述。

## 三十、调研差集收口与降级链对账

### 1. 内部旗标族按「有无读者词面」一族并案，不逐个重复调研
某渠道中转政策层挂着一族英文内部旗标（联程语义嫌疑、最低价标记、供货类型码等十余词）——逐个判定会每轮重来一遍。**英文内部码无中文词面=读者侧零信息，语义未证不采，同政策层的整族并案进不采清单**（与「键名推断不构成口径变更依据」同律：词面都不存在，谈不上读者增量）；并案时防漏「旗标与既有出口的并现率」核对——某旗标既非直挂充分也非必要条件，说明直挂语义已有别源承载，恰是不采的旁证。配套手法：**对「唯一可能翻身的域」挂观察哨**（判死时写明「若渠道实发非零值/按政策分化，按某既有出口键回归」）——渠道对标签语义边界的扩展是静默的，观察哨是把「下轮从零重查」降为「按哨点位复核」。

### 2. 渲染宽模型已不计的成分，降级链不得再为它降级
行宽守卫把 markdown 链接 `[t](url)` 还原为 t 计宽（URL 不占渲染宽）时，降级链里「剥链接保裸价」档就是过度保守：可达预算内的链接被无条件剥掉，而链接是该日期唯一文本跳转入口（图挂兜底日尤甚），违背「跳转文案才用文本」的可达性前提。**守卫链的每一档都要对「这个降级动作丢了什么」对账——先试原样再降级，剥除档只对「真超宽」触发；逐字截只对剥除后的裸文本做（对原文截会截出 markdown 半截）**。同族推论：链接完整性应做成钉（文本行情行必带可达链接），防下一轮新增降级档再静默剥链接。

### 3. 同产品的多推送路径是「能力对称」问题，不只是「分别审」问题
日报与达标聚合两条文案路径结构无共享，新能力（同价多渠道合并、运维对账注）落地时只落告警路径——日报（每日唯一综合视图）的有效信息容量反而低于告警总表（同班复读占 TOP5 槽位、渠道缺勤静默）。**「两条独立文案路径逐条取全文审」抓的是既有缺陷，「能力对称收编」抓的是增量缺陷：凡在一条路径新增的去重/补偿/对账能力，grep 另一条路径有无同构消费点，同轮对齐**——共享同一组装函数（组头/池拆分收进单源）是让对称性免费的方法。

### 4. 配置取值域的声明处与实现的容量处必须互钉
配置界面给某项声明了取值域（如 1-5），实现却是硬编码两档延迟表切片——域内 4/5 静默无效（切片超界不报错，配置了就是没生效）。**取值域是「配置语义」的一部分：声明域的控件与消费域的实现任何一方扩改，另一方同轮对齐；钉面锁「表长 ≥ 域上限 − 1」这类结构关系，不只锁默认值行为**（默认值恰好的行为绿测试护不住域内其它档）。

### 5. 本地产物文件名的唯一性维度 = 租户 × 对象
按对象（航线/日期）命名的本地产物（渲染 PNG 等）在多租户下同名互覆——消费端按确定性映射反推本地直读（零网络优化）时，30 分钟新鲜门内会嵌到别家同对象图：互覆是数据面事故，不是显示面瑕疵。**产物命名带租户段（空租户返空串，单用户部署文件名不变零回归）；租户段进文件名前做字符消毒（用户名是配置自由文本，路径分隔/非法字符剥除）；消费端反推若是通用 stem 还原（URL 尾段 ↔ 本地名），产物名带段后零改动自动兼容——改命名前先枚举反推链，别为兼容写死双态**。推论：律立之前已存在的同构产物面（走势图等更早的命名面）在收口时同律处理——律的普适性不因「旧面先于律存在」而豁免。

### 6. 「恒写键」退役的收口面是三段式：产出路径全枚举、直查消费点同轮扫、前提注释对照真实调用链
渠道「属性不适用即落空串」的恒写键改为无值不落时，伴生面有三段，缺一即埋雷：①同键的全部产出路径同轮收口（直飞与中转重构路径常各有一份组装字典——漏一条，收口键的空串面只清一半，按「收口键零流入」口径复核时产出假火）；②全仓直查下标消费点同步 .get 化（键从恒在场变可缺席后，任何 `row["k"]` 形态读点在缺席行上 KeyError——包括不触推送面的日志组装路径，它们不在渲染测试的行路径上，炸面只在特定轮显形）；③注释与测试文档里的行为前提（「行不经 normalize」「键恒写」）落笔前对照真实调用链核实——前提写错的注释会把错误因果传给下一轮排查（本案真因是 normalize 缺起降时刻的早退分支不写键，注释却写了「行不经 normalize」）。配套对账：哨兵出勤口径为「非空值」时收口前后分子分母不变、无需清状态文件；「键在场」口径才需要清哨。

### 7. 收口覆盖面的验收窗也要按产出路径分流：单路径观测窗证明不了「全路径已收口」
「无值不落键」收口轮的验收观测窗恰逢主路径独占产出（如 PC 复活期的日窗轮）时，兜底路径（H5/降级链）的行根本不在窗内——「新代零残留」的 PASS 只证「主路径已收口」，兜底路径行构造器里的同族恒落键照样逐轮落空串，等兜底路径轮显形才暴露为收口余量；其中部分键还可能被旧钉钉着「空串落地」的旧行为（fullmatch 拒脏形后落空串曾被钉为「宁缺勿错」的预期形态），修复必须连钉面一起改写。**判定「某键族已全量收口」的证据窗必须覆盖该键的全部产出路径；做不到时 PASS 结论改写为「主路径窗内已收口」并把兜底路径列入观察哨；收口动笔前先枚举同渠道全部行构造器（主路径与兜底路径各一份组装字典是常态），枚举不到路径等于没枚举。**

### 8. 预算循环的产出段是消费契约：留痕标记混入数据段=冒充切片位
「按预算逐条取、以分隔符拼段」的 join 函数被顺手加进「等N条」留痕标记后，调用端「分隔符计数+1」的切片消费会把标记当成数据位多跳一条，尾部内容静默丢失——标记在宽预算下恰好融入段尾，行为测试与截图目检都容易放过。解法两件：**产出段恒纯**——join 只吐数据位，任何留痕/标记归上层「预算循环+尾注」单源承担（余量并回度量、装不下独立成行、容器高按行数参数化），纯度用 AST 钉锁死（函数体不得出现标记字面量）；**多路消费点同轮收编同一单源**——summary 与运维注两路各养一份预算循环时，「留痕」能力只会长在其中一路（能力不对称），共享单源是让能力对称免费的方法。

### 9. 行级池与元素级池的渠道构成可以不同：守卫对齐是判定粒度对齐，不是参数对齐
同一道跨渠道幻影守卫，列表/告警链按「行」判（每渠道的行价入锚池），曲线按「元素」判（桶内元素入锚池）——中转明细恒缺的渠道只进行级池、不入元素池，两池的渠道构成天然不同。单渠道污染时两端判定一致；**双渠道同轮污染时元素级锚被毒价互拖**（毒价入锚压低中位，另一渠道的毒元素逃过比率判定成为曲线最低点，甚至挂上「行情破线」旗标），而行级池因渠道更多、锚更稳正确拦截——结果就是「图有列无」与「毒价上图」并存。「曲线与列表必须同一可信口径」的落地不是同参同过滤参数，而是**守卫判定粒度对齐**：曲线桶构建先按行级守卫整行剔除（与列表同判据同输入），元素级守卫保留作第二层防渠道内解析窗口毒元素。实现时行身份要随元素进桶（行级剔除按行号整行出局），守卫调用次数随桶数恒定增长而非随元素数（性能钉的预算上界随新守卫同轮校准，否则未来 fixture 加中转即红、还会误导后来者「删守卫修预算」）。

### 9b. 分类池守卫的双渠道互抬穿透：混合池补层，机理是锚供给变宽
跨渠道孤低价守卫按直飞/中转分池判（锚=其他渠道同类最低中位）防的是两类互相误杀，但**同轮双渠道毒价会互抬对方锚**：某类明细的锚供给方只有少数渠道时，两个毒价互相进 others 压住中位、双双逃过比率线直通达标推送（不可购价幻影达标=决策级误报，推送触达面成倍放大）。混合池补层（直飞+中转合并按同函数同比率再判一遍）与分池层互补——分池拦「单渠道毒」，混合池拦「低价渠道对互抬」；**互抬对的解救机理是锚供给变宽**：直飞行价进池把中位对抬过比率线（同案实锤：同伙毒价面对的锚从分类池 1647 抬到混合池 2241）。落地三坑：
① **单遍定版，勿造「迭代收口」外衣**：互抬对的解救靠锚供给变宽，不靠「拦一个再拦另一个」——薄锚池首轮全逃时无标可收敛、迭代无起点（死锁）；厚锚池首轮即双拦无需第二轮。pmin 锚模型下迭代与单遍行为等价，「已标行退出锚池再判」的循环若 break 判据量错对象（量列表长度而非标记数）还会是恒真式的假迭代——**注释卖的机制必须存在，否则宁删机制勿留外衣**（探针实证：假迭代的调用次数钉/第二轮钉都会当场揭穿）。
② **混合池误杀面用全史重放分位实证，不信理论推演**：中转价天然低于直飞，混池判的理论误杀面看似很大；全史重放（十几万中转明细）实测误杀率千分之一以下且全部落在毒价家族，真降价案（多渠道同水位）零误杀。「宁拦促销勿放毒价」（不可购价幻影达标的伤害大于错失促销）的产品定论是这个面的裁决依据。
③ **锚供给不足时互抬是纯统计无解的数学边界**（两条毒价恰似真实双渠道价差），守卫依赖健康锚进得了中位对；测试样本的渠道构成要按真实轮还原——样本少一个健康锚，同伙毒价就差半角档假红，先怀疑样本再怀疑实现。边界形态本身配「不拦」钉（锁死后来者为个案引入假迭代/假守卫）。
④ **比率线的可分边界=「毒价 < 比率×健康锚中位」**：同一毒价家族在不同日期面对不同锚带，落入 0.5~0.8× 健康带的成员单轮统计不可分（真中转价常态就在这个带）——守卫拦得干净的部分如实报告，拦不住的部分备案并挂更细粒度的观察哨（如同指纹跨轮价摇摆），不为个案收窄比率放大误杀面。

## 三十一、配对语义、token 边界与窗口钉

### 1. 同屏矛盾收口在「配对语义」不在「词面」：两个消费点各自手拼配对时，词面单源救不了
同一航班实体在 KPI 行3 显示「经兰州 停2:05」、hits 行显示「经停庆阳 停22:55」——词面函数早已单源，错的是两个调用方各自选了不同的优先键拼装（一处 transCity 优先、一处 stopCity 优先），中转行双键同带时各自配到的「停多久」来源不同：停留时长被配到经停城市，读者按决策行误读「在庆阳停 22 小时」。**凡「A 词 + B 值」的复合词面，A 与 B 的配对关系本身就是语义：先枚举全部消费点的配对取数路径，把「配哪个值」收进单源函数（而不是只收「词怎么写」）**；收口方向对齐到信息承载最全的消费点（此处=总表图：经停徽标与 stopTimeT 配对、中转列与停留配对），文本侧随之。

### 2. 时刻类 token 不许被逐字截半：拆 token 让「整删」语义可达，首 token 超预算才逐字截
行宽地板逐字截把「停2:05」截成「停2:」——半截时刻是纯噪音（读者既读不到值又确知曾有值）。**含时刻/数字的复合 token 在降级链里先拆成独立 token（分隔符随中文排版惯例全角空格，词面钉面同轮随迁），地板装载按 token 边界贪心：装不下的整 token 丢弃（时刻要么完整要么缺席，城市名等主辨识信息靠前保）；唯独首 token 自身超预算（病理长城市名）时保持逐字截保前缀——地板档恒落位律不允许行内容净失。**拆分对正常形态零变化（join 分隔符本就全角空格），只在触发档显形——行为钉要构造「恰卡半截」的精确宽度样本（按 _dw_raw 校准宽累计到截点），且夹具必须让被测行真实进入渲染链（缺省到达约束曾把中转行判出局、断言对空输出恒真=修复无行为锁，变异不红的钉先验夹具可达性。**本律投影到航班号码段：行宽地板对「航司名+字母数字码」复合码逐字截时，截点落进字母数字段中即产半截码（「川航3U8」形）——半截码比无码更有害（读者以为读到了码）。截点两侧都是字母数字即切在段中，此时整段回退到段起点（全字母数字码=裸航班号行整码丢弃），价格+时刻+跨天地板不受影响恒落位；回退只会变短，恒达标性自证。触发样本要用真函数网格探找（价位数×跨天×停留组合才卡进截码带，手拼典型样本恰落在整词界=测试假绿）。**

### 3. 窗口截断型源码钉对插入敏感：窗口长度是实现细节，锚结构才是钉面
源码钉用「从块头切片 N 字符找断言目标」时，任何合规注释增厚都会把目标推出窗口——钉红像回归实为窗口太紧。**这类钉的窗口长度只服务「块内」语义，应放宽到块边界（下一个 @media/def）而非固定字符数**；写钉时问一句「块内合法增厚 200 字符会不会红」，会红的钉是给未来维护者埋的假警报。

### 4. 「随最低价政策配对」的键族在「成为新最低」分支必须整组复位：复位组靠族谱枚举，不靠逐案补丁
多政策取最低价的解析链里，「新低价胜出」分支会把配对键重赋值——但键族的成员是历代增量长出来的（余票/紧俏度/行李旗标/产品词/舱位名/折扣/航司中转标注/服务承诺……），每新收一个「随最低价政策配对」的键就要同轮进复位组；漏一个就是「高价政策词面残留到低价行」的脏携带（恒落键×条件赋值组合的键最危险：新政策缺该载体时残留无阻）。**判定某键该不该进复位组的口径只有一个：它的语义是不是「最低价政策的属性」——是，就在「price 被刷新」的同一分支无条件复位（含恒落键的）；键族清单靠 grep 同一赋值循环内的全部配对赋值点整组枚举，镜像路径（直飞/中转各一份组装循环）同轮盘点，先写「缺键残留」的复现钉再修。**
