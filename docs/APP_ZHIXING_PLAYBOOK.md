# 智行 App 采集手册（2026-11-09 实战定案）

> 目的：把今天在智行 App 上踩过的坑、验证过的手法、以及**明确的能力边界**固定下来，
> 下次（或别人）接手时不用再走一遍弯路。
> 全部结论都有真机证据；证据文件位置写在最后一节。

## 一、一句话结论

**智行能出数。** 国内近端日历一次可拿 **60+ 天**；国际明细（如 SHA→NRT）也能拿到
真实航班/时刻/价格。之前"整体 0"不是能力问题，是**三个自己的 bug 叠加**。

## 二、三个叠加的 bug（按发生顺序）

| # | Bug | 表现 | 修法 | 提交 |
|---|---|---|---|---|
| 1 | 日历限频后，明细第一步仍假设"日期弹层还开着" | `明细 no-priced-rows` 大幅上升（我一度误判成"国际未适配"） | `_enter_detail_and_parse(dialog_open=...)`：日历被跳过时让明细自己开弹层 | `T232` |
| 2 | 国际航线失败**计入连败** → 熔断 30 分钟 → 后续国内航线一起 0 | "时好时坏"、整体 0 | 国际 + `no-priced-rows` 记 `unsupported` 且**不累加连败**；国际标记在**明细入口**处算 | `T237` |
| 3 | **日历滚动方向与 App 相反** | 请求 11 月/1 月，日历却停在 2027年2月→5月→6月；选不到目标日 | 对调 swipe 方向（`down`=想看更早 → 手指**上划** 1300→500） | `T245` |

## 三、必读的坐标/方向约定（**不要按直觉改回**）

```python
# crawlers/app_zhixing_nav.py::_scroll_calendar
if direction == "down":        # down = 想看更早日期
    return dev.swipe(450, 1300, 450, 500, 400)   # 手指上划
return dev.swipe(450, 500, 450, 1300, 400)       # 想看更晚：手指下划
```

* 智行的「选择日期」是**分页列表**，手指下划 = 翻到下一段（**更晚**）；
* 目标在 2 个月外时，一次翻页可能只到"目标月标题出现、格子还没渲染"，
  所以 `_tap_calendar_cell` 的尝试次数已从 5 提到 **8**；
* 弹层可能**停在上一条航线的月份**：找不到格子时会**重开一次弹层**（`_reopened` 守卫）。

## 四、其他两条实操要点

1. **App 停在上一条航线的列表页** → `app-route timeout 首页未就绪`（等 14 帧/48s 也没用）。
   现在遇到这个原因会 **force-stop + 重启 App 并重试一次**；
2. **日历弹层一次渲染 61–77 格 → 整窗收割**（`app_calendar_harvest_all`，默认开），
   一次抓取可入库 50–62 个日期；这比明细更值钱，所以日历**限频 1 小时**
   （`app_calendar_min_gap_s=3600`），把设备配额让给明细。

## 五、能力边界（已实测，别再试）

| 边界 | 证据 | 处理 |
|---|---|---|
| 远日期（>45 天）明细不稳定 | 01-29（81 天）多次 `no-priced-rows` | 用户决定"春节日期只走浏览器"，App 视野 **45 天**，远日期 0 秒交浏览器 |
| 国际日历有时 0 价 | 同一弹层：一次 56 格有价、一次 0 格 | 如实记 `unsupported`，不重试、不熔断 |
| 频繁调用会让 App 自退 | 连续探针后 `App 自行退出后熔断中` | **同一渠道 1 小时内探针 ≤3 次**；连续验证走定时轮次 |

## 七、取证文件在哪（重要）

| 文件 | 含义 |
|---|---|
| `user_data/_diag/app_zhixing/app_detail_fail_*_pick.xml` | 选日期失败（看弹层停在哪个月） |
| `..._nobtn.xml` | 找不到「机票查询」按钮 |
| `..._wait.xml` | 点了查询 30 秒没进列表 |
| `user_data/_diag/app_zhixing/app_cal_noprice_*.xml` | 日历格子有但没有价 |

> 取证**故意写在 `_diag/`**，不在 profile 目录：profile 会被自动备份改名
> （`app_zhixing.bak_*_auto`），写在里面等于丢证据。

## 八、教训（写给下一个人）

1. **"连续 N 次为 0"不等于能力边界** —— 先按天拉历史，若历史上是通的，就是**回归**；
2. **别按滚动直觉改坐标** —— 用两份 dump 的"可见月份"对比确认方向；
3. **一个分桶能省半天** —— 按"距今天数 / 航线类型 / 端"分桶看成功率
   （今天就是靠它发现"远日期只有 10%"）；
4. **静默跳过 = 不可验收** —— 任何决策型逻辑每轮都要留一行可读结论。
