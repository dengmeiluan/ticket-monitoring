# ticket-monitoring v1.5.295 · 2026-10-24

> 自托管的多渠道机票价格监控：五平台明细采集 → 钉钉图文推送 → 达标四层强提醒。
> 国内航线与国际航线（五洲目的地）同一套采集-判定-推送链路。
> 数据留在本机，配置全在网页，开源免费。

本版收口「监控真正持续运行、提醒只基于同口径新低、诊断有证据、来源可追溯」，
并完成控制台圆角/价格语法/登录表面统一与移动折叠修复；性能门禁首次以 4× CPU
可复现数据为准。

## 特价监控闭环

- 修复生产配置丢弃 `special_radar` 的 P0：自动轮询现在能读到用户航线/日期范围；启动 90 秒首轮，之后每 2 小时。
- 快照按 `航线+日期范围+渠道` 的 query key 分域，切换条件不再把旧日期/旧渠道串进新查询；每次运行另写 `radar_runs`，缓存/回退/空/失败只留运行账本，不污染价格历史。
- 新增降价提醒：首轮只播种；同口径新低达到最小降幅且过冷却才推送；阈值提醒一次后重新武装；渠道/口径切换只重置不误报；演示模式、缓存/回退/部分失败不发送。
- 提醒配置在特价监控条件区内联保存（开关/降幅/阈值/冷却），推送包含低价日、渠道、口径与已采集真实航班；无明细时明确“日历价不能生成航班”。

## 渠道诊断与证据

- 诊断分类移到 `core/health_diag.py` 单源：未扫描、正常、仅日历、部分成功、维护、登录失效、Cookie 过期、验证码、IP/频率风控、超时、空结果、待核对。
- 途牛 `179991` 等 IP 标记不再被 40 字截断；去哪儿 `1999` + “没有符合条件的航班”归空结果，不误报登录；部分成功不再整渠道判失败。
- 本地 Cookie 过期只读检查（不输出 Cookie 值）；每渠道“自检”追加 `logs/channel_evidence.jsonl` 证据，不发起外网请求、不绕过验证码。
- 健康 UI 直接渲染服务端诊断卡，不再用前端正则猜；无证据不显示绿色。

## 来源可追溯

- 扫描与探针写入 `fetch_paths` 与行级 `prov`（入口 PC/H5/API、路径状态、证据级别）；旧行缺失标 `unknown`，不回填。
- 详情“采集入口”、检索 CSV、证据 CSV、雷达低价航班都消费同一来源字段。
- RAW 明确标为“解析 extra（非原始响应）”，不再宣称逐项等于 HTTP 原始响应；本轮不伪造 `raw_http`。

## 设计语言与移动

- 单一圆角令牌（卡片 14 / 容器 12 / 控件 8）、单一价格字号阶梯；关注航班去掉重复标题；登录卡从三层表面收为两层。
- 新增 Sector Strip 签派轨（概览关注卡、关注台焦点轨、特价低日卡）：航线、目标缺口、价格戳、状态同屏；渠道 logo 仍是唯一多彩元素。
- 折叠按钮统一同步 `aria-expanded/aria-controls`、文案与 localStorage；刷新后状态一致。
- 320/390 折叠按钮不再压说明；901–1024 五源条横向滚动且名称不压计数；390 特价日历有横向提示并把选中日滚入可见区；监控走势补隐藏数据表；低日航班 ≤360 两行不重叠。
