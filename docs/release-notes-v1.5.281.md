# v1.5.281 — 数据诚实收口：日历价不再冒充达标，轮次与图表口径统一

## 本轮解决什么

v1.5.280 打通携程国际航班列表后，并发审计发现几处“有数据但口径不诚实”的问题。本轮按 P0/P1 收口：

### 1. 日历价不得进入推送命中（P0）

`core/alerter.py` 的分类池此前按 `transCity` 分直飞/中转，携程日历最低价
（`name=日历最低价`、起降时刻双空、无 `transCity`）被分进直飞池，￥719 日历价
直接触发「真达标 · 建议出手」推送。现在：

- 推送分类池先剔除时刻双空的日历/薄行（补位池同样过滤），只保留可出手机票；
- `_collect_hits` 再做一次防御性日历行守卫；
- 日历价仍可在控制台以「日历」展示，但永不参与达标/告警/TOP/同班比价。

### 2. 轮次标记取代 420s 断口（P0）

同一轮多航线按顺序完成可跨 8–10 分钟；旧 `420s` 行间断口把先完成的 NRT/BKK
判成“补位”，IJ004 ￥972（线￥2500）被标 `stale=0.3h`、`qual=false`，概览
“0 条本轮明细”。现在 `main.py` 每轮写 `data/last_scan.json`，控制台以本轮
开始时刻划轮；标记陈旧/缺失才回退 420s。实测 NRT 行 `stale=0`、`isStale=false`、
`qual=true`，全库 stale 由 1089 降到 444。

### 3. 补位行恢复真实 provenance（P0）

`report.recent_platform_flights` 的补位查询只取 platform/extra/fetched_at，
详情/CSV 的 `rowId/rawIdx` 全空，1432 行被误标「未采」。现在 SQL 带回
`id`，逐元素挂 `_row_id/_raw_idx`，三重对齐可回放真实 raw。

### 4. 携程国际范围/时区/等待时序（P1）

- 机场级路线（PVG→NRT、LHR）只保留目标机场：Ctrip 城市搜索 TYO 混入 HND，
  LHR 混入 LGW/STN/LCY；不再让“上海→成田”趋势/告警/同班混入羽田。
- 时区按航班日取 DST（LHR 2026-11-16 为 UTC+0，不再按抓取日 10 月盖 +60）。
- 首包有行后的 9s 宽限从首行到达起算，避免 pull 补量前早退丢行；解析
  `finished` 容忍空白；逐日整页导航后不再叠加 5–15s 随机 sleep，14 日窗
  耗时明显下降。

### 5. 图表与关注台口径（P0/P1）

- 长窗（30/90/180 天）日桶后端 flag=0，前端 `TIER` 不再按 `v≤tv` 回退成
  真达标环；hover 不再把长窗低价标「擦边/真达标」。
- `/api/trend` 下发日桶真实 OHLC（open/close/hi/lo），K 线不再把单日 lo
  复制成开=收=高=低。
- 关注台 stale 报价、暂停/范围外关注、DB 历史报价不再显示“已达标”；
  `srxWatchTargetStateOf` 同步收口。
- 关注台 K 线按窗口内“采集天数最多”的渠道选源（当前渠道仅 1 天时不再只画
  一根）；涨红跌绿与航线 K 线统一。

### 6. 公共面

- README 中英下载体积改为 60–94MB；关注台截图标注为演示合成数据；五渠道
  明细改为“携程国际 PC 列表/国内 H5”。
- 演示健康种子不再把携程写成“日历价 3（无航班明细）”，与 v1.5.280 的真实
  航班能力一致。
