## 四、归因更正（重要，别被数字带跑）

初稿把 `tuniu/H5/API 59.3 → 49.2` 写成"该通路靠登录态，未登录就会掉"。**这是错的**。
按小时查库（2026-11-09）：

```
tuniu H5/API：
  00点 ok n=3 rows=99     01点 ok n=2 rows=52
  07点 ok n=3 rows=87     08点 ok n=4 rows=136      ← 全 ok，没有 login
  21点 login n=1 / ok n=3 rows=230
  23点 ok n=6 rows=303                              ← PC·国际 还没参与时，效率最高

tuniu 各通路（07-08 点）：
  PC·国际 ok 4/小时      ← 先跑，把国际日期吃掉了
  H5/API  ok 3~4/小时    ← 只剩缺口日期，行数自然少
```

**真实原因：通路分工变了**——`PC·国际` 排在前面并先吃到国际大单，
`H5/API` 只处理剩下的日期，所以"行/次"这个比值**不可跨配置直接比较**。

### 由此立一条测量纪律

- 通路效率（行/次）只在**同一分工**下可比；分工一变，必须改成比
  **同一日期/同一航线**的产出，或直接看**失败面构成**（哪类原因在涨/在跌）；
- 任何"变好/变坏"的结论，先问一句：**是不是分母（谁在干哪段活）变了？**
