# ticket-monitoring 初版 · 持续更新

> 自托管的多渠道机票价格监控：五平台明细采集 → 钉钉图文推送 → 达标四层强提醒。
> 国内航线与国际航线（五洲目的地）同一套采集-判定-推送链路。
> 数据留在本机，配置全在网页，开源免费。

> **时效边界**：本文是 v1.5.304 当次发版快照，不是现状——渠道可用性、
> 版本号、测试计数都以仓库 HEAD 与 `docs/EXECUTION_SPEC_LATEST.md` 为准。

**当前版本：v1.5.304 · 2026-10-27**（初版首发 2026-10-23）

本版重心是**账本只写有证据的结论**：渠道没拿到数据、被门拒、要求登录、确实没票，这四种情况此前会互相冒充，现在分开记账；顺带补上采集节流、路径级健康与几处深链/字段标注修正。

## 诚实性（本版主线）

- **「没票」必须有明确证据**：以往层层兜底的最后落点会写成「无票」，把请求失败、解析失败包装成业务空结论。现在 `empty` 只能由站点的明确无票证据支撑，其余一律记 `error` 并保留现场。
- **门拒不等于会话失效**：去哪儿「当前搜索无航线」等通道级门拒不再被当成真无票，也不再触发退避重试或提示重新登录；「该重登」和「该重试」分开。
- **携程国际、去哪儿 HTTP 回退**：请求无响应、未解析出内容时不再记成真无票。
- **有行无价**：解析出航班行但取不到价格时，不再因空序列抛异常留下「无证据的空」。
- **登录墙不冒充错误**：登录墙记 `login` 而不是 `error`，面板据此提示重新登录而不是重试。
- **证据不跨域**：一个日期/一条路径的判定不再污染另一个日期或另一条路径。
- **路径溯源**：路径账补上 `request_url`，出问题能直接点开复现，不靠截图猜。
- **历史行按证据改判**：早先记成「登录失败」的 1999/444 行，按实际证据改判为软拒，面板不再催重登完好的会话。

## 采集节流与健康

- 采集限流防护与路径级成功率治理：并发契约（闸门不死锁、不超全局配额）、限速混合读写。
- 路径劣化按国内/国际分域提示，避免整家渠道被误判；干预后每 30 分钟趋势与回落告警（先好后坏＝一致性不成立）。
- 陈旧路径样本超过 180 分钟不再参与劣化判定；本轮覆盖率区分「没发」与「全失败」。
- 静默窗结束即补采，不再陈旧半小时；窗内不再建议「立即扫描」。

## 数据与字段

- 同程窗历是**城市级**最低价，落库标注 `cityLevel`，防止被读成该机场价。
- 渠道不提供舱位/行李时标注「舱位未标」「行李未标」，不让人误判是否含托运或高端舱。
- 飞猪国际中转卡片无航班号即被丢弃的问题已补解析（明细 14→82 / 6→150 条）；中转段数改从「N 程航班」取。
- 去哪儿国际按流式分页收齐多包；60 条缺口经复核为真实价差，不是漏采。
- 原始明细保留期 14 天→8 天并受控 VACUUM，真实库 406MB → 192MB。

## 链接与安全

- 撤回无痕会话一律跳登录页的国际深链（同程），去哪儿/途牛国际死链一并撤为无链接；只对实测可出价的渠道出链。
- GitHub 图床连续失败熔断：一轮多图只撞一次。
- 登录判定只认真登录墙，页脚「扫码下载 App」不再误判。

## 边界

- 日历价只作参考，不等于航班明细；同程国际窗历为城市级最低价。
- 走势只来自真实监控快照；补位行只作展示，不参与达标/同班比价/推送。
- 不绕过验证码/滑块/风控；演示/在线站仍为合成数据。

## 安装与运行

- Windows：下载 `ticket-monitoring-win64.zip`，解压后运行 `TicketMonitor.exe`。
- Linux：下载 `ticket-monitoring-linux-x64.zip`，解压后运行 `TicketMonitor`。
- macOS：Apple Silicon 用 `ticket-monitoring-macos-arm64.zip`，Intel 用 `ticket-monitoring-macos-x64.zip`。
- 也可从源码运行：`pip install -r requirements.txt`，然后 `python main.py`；控制台默认在 `http://127.0.0.1:8765`。
- 首次启动会检查/安装 Chromium 内核；配置、数据库、登录态和日志均在本地目录。
