# ticket-monitoring v1.5.285 · 2026-10-22

> 自托管的多渠道机票价格监控：五平台明细采集 → 钉钉图文推送 → 达标四层强提醒。
> 数据留本机，配置全在网页，开源免费。

本轮不是再加一个按钮，而是把「检索」从一次性等待改成可观察的真实任务：阶段、逐渠道进度、阻塞原因、增量结果、取消与重试都来自后端真实事件；同时修正了首次进入被旧条件清空、草稿污染结果、日历价冒充明细和登录态与结果混写四类正确性问题。

**实时探针全过程可观察**
- 新增后台任务 `/api/probe/start`、`/api/probe/task`、`/api/probe/cancel`；页面每 1.5 秒读取真实任务快照，不再等待一次性响应。
- 按「本次运行 → 航线/日期 → 渠道」展示：排队、请求渠道、解析明细、完成/无结果/失败/超时/取消，以及渠道记录数 → 有效明细数、日历数、耗时和错误原因。
- 某渠道就绪后结果立即进入列表（实测第 3 个渠道完成时已有 503 行可见），不等待最慢渠道；最终汇总与增量去重一致。
- 收起进度不停止任务；刷新/重新进入按任务 ID 重新关联并补齐结果；取消传递到后端，未启动子任务停止、执行中协作收敛，保留已完成结果；失败/超时/取消组合可针对性重试，不覆盖成功结果。
- 没有假进度、假日志或按定时器增长的百分比；剩余时间未知时只显示阶段、已用时间和最近事件。

**中性首屏、计数与条件分离**
- 首次进入不再静默套用上次的航线/日期/渠道/关键词/筛选；只恢复排序与视图偏好。旧条件以「上次条件未自动应用」说明并给出显式「恢复上次条件」入口。
- 「清除结果筛选」不再改已提交探针日期或请求渠道；「全部日期」「查看有数据日期」「用探针查询该日期」均为显式动作。
- 探针表单是待提交草稿；修改出发/到达/日期/渠道不会改变正在展示的结果。提交后才形成任务快照，结果筛选与请求渠道分开保存。
- 计数区分「全部日期 / 所选日期 / 筛选后 / 唯一航班 / 渠道报价」，例如 `531 / 531 行 · 所选 2026-11-16`；所选日期未采时明确说明其他日期有数据，不自动换日。
- 空态区分未采、原站无结果、请求失败、日期无数据和筛选为空；筛选为空列出全部生效条件。

**布局与渠道状态**
- 探针首次直接可操作；展开时出发/到达/日期/启动为主操作区，渠道紧随查询控件；收起为紧凑工具条。探针模式隐藏重复的价带/五源条，空日期价带收敛为单行说明，零明细时 KPI 收敛为一行。
- 「本次渠道状态」只描述本次查询产物：航班明细 / 补位明细 / 仅日历参考 / 本次无结果 / 本次失败 / 未请求；登录态另列「会话已保存 / 待验证 / 可能失效」，空结果不再推断需要重登。
- 飞猪国际从「仅日历价」补齐为 PC 列表明细：实测上海→曼谷 28 条完整航班（时刻/机场/含税价），最低含税 ￥745；列表空、未登录或往返仍回退日历并明确标注。
- 飞猪、同程登录保存后，检索页与配置页共用 `/api/login-state` 即时同步；渠道登录卡按钮统一底部对齐，长状态文案不再撑高卡片。
- 途牛国内 `listFlight` 实测返回 `710114 请登录`，属于账号态门，不是无票；本轮已注入已保存会话并识别登录墙，未登录时如实提示，不再空转重试。
