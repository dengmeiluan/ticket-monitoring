## 2026-11-10 滚动修复（同版本号重建）

### 登录与核验（对应 issue #15）

- **核验一直不通过**（飞猪 PC 已登录仍提示需登录、携程登录不了）：核验时打开的
  本来就是登录页 `passport.*` / `/login`，而判定把 **URL 命中** 当成"需要登录"的证据，
  与是否已登录无关。现在槽位核验只按页面正文判断；未登录仍能正确识别。
- **核验成功却仍提示核验**：核验结果此前只在 H5 槽位生效，PC 槽位没有读取。
  现在卡片显示「核验于 HH:MM」；"页面可达但未出数"的按钮改为「再核验」并说明原因。
- 登录窗口不再重复弹/闪：同槽位的打开请求会排队，超时会把僵尸窗口关掉。

### 升级（新增能力）

- **不再需要卸载重装**：`python -m core.update --check / --download / --apply`
  或面板「检查更新 / 立即升级」一键完成（下载 → 备份 → 覆盖 → 失败回滚），
  完成后重启即可。**不会覆盖** `config.yaml`、`user_data`、`data`、`logs`。
- 面板常显当前版本，可随时手动检查更新（结果缓存 6 小时）。

### 渠道采集

- **智行 App**：整窗日历收割（一次 50–62 天有价）；日历限频 1 小时避免烧设备配额；
  国际明细恢复出数（此前因日历滚动方向反了而必然选不中目标日期）；
  国际航线拿不到价不再拖累其它航线（此前会触发 30 分钟熔断把国内也挡掉）。
- **携程 / 飞猪**：周历收割跨日期低价条（飞猪周历页无价已默认关闭）。
- 死链路自动退役：连续 24 小时 0 成功率自动标记退役并在面板说明原因。

### 观测与诊断（都在浏览器里）

- 「通路耗时」：每条通路的平均/最慢耗时（判断该先跑谁）。
- 「距离分桶」：按"距今天数"分桶的成功率（判断是不是我们把日期给太远了）。
- 日历覆盖天数、通路弱环、降级原因、本轮耗时分解（墙钟/有效工作/闸门等待）。

### 稳定性

- 修跨天脆弱：沿用"今天"的用例在跨日后会成片变红，已改为相对日期/可注入时钟。
- 修升级包"包装层"误判：只有 `core/` 的 zip 曾会把文件摊到项目根。
- 修 `/api/update/check?force=1` 路由漏匹配导致的空响应。

### 登录槽位（H5 与 PC 各自独立）

- **「我 h5 明明登录了，页面却没变」已修**：H5 槽位的"明细可用"此前被写死为否，
  也不参与状态判定——即使该端面昨天真出过数，卡片仍停在「已保存·待验证」。
  现在按**该端面自己的通路账本**判定（真出过数才算），并显示「核验于 HH:MM」。
  被拦（验证码/需登录）仍然优先，不会因为"昨天出过数"被盖掉。
- 双端弹窗顺序固定为 **PC 在前、H5 在后**，并注明"两域会话不共享，需分别登录"。

### 观测与建议（都在浏览器里）

- 面板底部新增 **通路耗时** / **距离分桶** 两个视图（也可命令行
  `python -m core.channel_matrix --ms|--dist`）。
- 新增**结构性建议**：同一家"近端能成、远端明显不行"时会直接提示
  （例：`tuniu 远日期成功率 49%，近端 100%（124 次样本）：建议把该家视野收窄、远端交浏览器`），
  点这句可跳到「配置 · 全局参数 · App 日期视野」。
- 该建议的阈值可配：`crawler.advice_distance_min_n`（默认 6）、
  `crawler.advice_distance_gap`（默认 0.25）。不配即默认，零配置可用。

### 两个容易误读的指标（已加口径说明）

- `App 登录 xx%`：这是**登录墙探测**（每次搜索是否被要求登录），
  **不是账号登录状态**——携程 App 搜索强制手机验证码时它恒为 0%。
- `独立日期数`：数的是**请求过的日期**；整窗收割（如智行一次 62 天）的额外日期
  在 `flight_prices` 里，真实覆盖请看面板「日历覆盖」或 `--dates`。

### 配置生效说明

- 面板里改**任意 crawler 选项，保存后即生效**（此前只更新了主程序那份配置，
  面板改完其实不生效）。
- 直接改 `config.yaml` 文件仍需重启（没有文件监听）。
