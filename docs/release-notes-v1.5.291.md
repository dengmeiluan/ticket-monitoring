# ticket-monitoring v1.5.291 · 2026-10-23

本版在 v1.5.290 基础上，按全项目语义、筛选、走势与首次进入审计结果收口。只记录已实现并能用测试或真实数据复核的变化；未完成项在文末单列。

## 关注航线 / 关注航班

- 关注航班改为配置关注航线 + 同日期的采集明细子集：新增/改身份必须命中已配置且启用的航线/日期。
- 停用航线不再作为父级；历史关注保留身份与走势，标记为范围外，可重新绑定。
- 新增/改身份校验同时查 `flight_daily` 与近 2 日 `flight_prices` raw，覆盖“已采集、日桶尚未刷新”的窗口；不存在的身份仍拒绝。
- 某一轮未采集到该航班时，不再误判为范围外；状态显示“本轮未采集”，继续按下一轮更新。
- 关注清单上限 100 条显式报错；移除静默截断。
- 全站文案统一为“关注航班 = 配置关注航线 + 同日期明细中的指定航班”。

## 筛选

- 明细“更多筛选”的仅共享/仅经停/仅风险价/隐藏日历价/仅达标五项真正参与过滤、重置与角标计数。
- “清除共同筛选”不再清除证据类 `safe` 条件；提示与行为一致。
- 文本/下拉筛选变更延迟一拍重绘，修复价格输入后第一次点“清除”被重绘吞掉的问题。
- 检索命中数分母改为当前航线 + 日期 + 渠道范围，不再拿全库行数作分母。
- 关注台/配置台目标状态新增“等待/无数据”；配置台航线切换按航线 + 日期分组。
- 恢复上次条件时校验日期仍在当前数据中；日期失效只恢复其余条件并明确提示。
- 30/90/180 天走势请求加 9 秒超时，不再无限“正在加载”。

## 走势

- 30/90/180 天航线走势优先读取 `flight_daily` 真实航班级日桶，不再把日历最低价混入直飞/中转最低价；无航班级日桶时才回退旧行情池，并在图注明确“含日历价”。
- 长窗图注区分“真实航班当日最低价（不含日历价）”与“行情池当日最低价（含日历价）”。
- 关注台图表状态新增“本轮未采集”；异步趋势回调在离开关注台后不再重绘隐藏画布。
- 关注台名册筛选（状态/目标/航司/直飞/渠道/舱位/时段/价格/关键词）同步约束图表序列，图注明确“图表仅画名册筛选结果”；目标达标判定改用接口有效价 `eff`，与明细目标口径一致。
- 走势横轴改为按采集时间真实比例落位，不再按数据点序号等距排布；折线按中位间隔拆段，跨缺口不连线、不填面积。
- 长窗图注改为“数据覆盖 起→止（所选 N 天窗，未采日期不补点）”，如实呈现覆盖范围，不再把未采区间画成连续趋势。
- 从概览进入完整走势时保留用户已选时间范围（48h/7d/30d/90d/180d）；从未选过范围时仍按概览卡语义落 7d，并同步范围按钮与标题。

## 首次进入、返回与异步

- 视图与页签切换使用 pushState，浏览器后退可回到上一页签/视图；hashchange 回放使用 replaceState，不叠栈。
- `#search` 深链可刷新并保持检索页，不再被 localStorage 的页签恢复覆写；非法 hash 清理保持当前视图。
- 关注台“编辑/添加”与“定位”延时回调带视图守卫，离开后不会再打开隐藏表单、遮罩或详情。
- `/api/trend` 长窗失败/超时有可见错误与重试入口。

## 会话状态与窄屏收口

- 探针命中明确登录/验证拒绝时，登录槽位即时显示“需登录”，不再沿用旧“近期明细可用”；空结果、日历价与超时不会反推登录失效，后续真实明细可自动恢复可用。
- 飞猪 H5 保存淘宝会话后，实时 `listingsearch` 取得 9C7293 ¥1461；飞猪 H5 仍为必须登录、PC/H5 独立会话。携程 H5 官方列表对国际/部分入口返回 30212 时，明细继续走已验证的 PC `batchSearch`，不伪造 H5 明细。
- 关注航线卡片在 320/390 宽下不再因 360px 最小列产生横向溢出；1920→320 八宽 × 100%/125%/200% × 监控/检索/配置 + 暗色复测页面横向溢出为 0。
- 取消后的晚到明细保留在旧任务，旧任务释放全局探针锁前新任务会被拒绝；已新增隔离测试。
- 验证票据支持 `#task=<id>` 深链：新浏览器打开即可切到检索页并恢复对应任务/票据，不再依赖原浏览器的 localStorage；用于跨窗口人工接管。
- 渠道入口与特价渠道链接改为弹窗打开：工作台保持在当前检索页，不再被新页面替换；Ctrl/Cmd/Shift 点击仍保留新标签页。

## 用户级关注与特价雷达

- 配置页 C 区更名「关注航线」；D「关注航班」把既有清单/筛选/添加表单直接内联展开在用户卡内（复用监控台组件），不弹层、不跳去监控台。
- E「特价雷达」按官方特价机票频道口径：任意出发/到达城市 + 日期范围 + 官方渠道（携程全国为独立选项），不要求也不联动关注航线；「查低价」在卡内直接出结果，点日期进入真实明细探针，并列出五家官方特价页直达入口，「在监控台打开」保留完整视图。
- 渠道选择统一使用官方渠道图标（携程/去哪儿/飞猪/同程/途牛），配置页与监控台雷达一致，不再用纯文字 chip。
- 监控台突出用户级范围：单用户也常显吸顶「👤 用户 · 用户视图」chip，多用户再加「用户：」pills 行；tab 更名为「关注航线走势 / 特价雷达 / 关注航班走势 / 关注航班明细」，与用户卡配置语义一一对应。明细页新增「只看关注」：按当前用户的关注清单只保留本轮真实明细行（demo 120→10 行/4 班），切用户自动复位。配置页 D/E/F 摘要按新 IA 刷新：D 不再显示特价状态，E 显示官方特价频道/低价提醒，F 显示通知渠道。
- 途牛国内逐日低价接入官方 H5 同源 `GET /query/flight/v1/calendar`（`type=1`、城市 IATA3、零登录/零签名）：SHA→BJS live 五渠道全部 8 个日期真实价；途牛价为**裸价（不含税）**，界面明确标注。国际线该接口无日历，保留出发地榜单与官方入口并如实 `empty`。
- 探针「重试失败项」跳过全局 60 秒冷却（仍尊重渠道验证冷却），避免任务结束后重试被无意义挡住；普通新任务继续受冷却保护。
- 低价查询稳定性：携程/同程每次实时取；飞猪/去哪儿成功后同条件 3 分钟内复用缓存（第二次查询 13.15s→1.29s）；飞猪 65B 软拒后冷却 60 秒、去哪儿风控失败后冷却 10 分钟，冷却期显示真实原因，不伪装成空结果。
- 低价源扩充：飞猪改用已验证的单航线 `cheapestCalendar`（含税，7 天窗口滚动）；同程接入 `queryCalendarLowestPrice`（免登录/免签名，国际 90 天、国内 180 天）；去哪儿接入官方 H5 特价页（页面 JS 生成签名，使用已保存去哪儿会话加载官方深链并读取真实 `getFlightCalendar` 响应；不逆向签名、不绕过验证码，风控失败如实报错并冷却 10 分钟）。SHA→BKK 同条件 live：携程/去哪儿/同程均返回 8 个日期真实价，飞猪在源限流时如实显示失败；途牛仍为出发地榜单（跟随出口 IP），榜内无该航线时为 `empty`。
- 雷达条件随 `/api/config` 保存到用户 `special_radar`（出发/到达/起止日期/渠道/全国），保存后热重载；重新打开页面或从用户卡进入时按保存值回填。监控态 `S.users` 只含运行时摘要，回填改从 `/api/config` 只读一次并缓存，保存成功即作废缓存。
- 中文国际城市名可直接作为雷达条件：`上海→曼谷` 解析为 SHA→BKK（`曼谷→BKK`、`大阪→OSA`、`大阪关西→KIX`），不再要求手填三字码。
- 扫描周期校验上限由 720 放宽到 10080 分钟（7 天）：live 配置的 10080 分钟此前被前端校验拒绝，导致任何配置保存（含雷达）都无法落盘；输入框同步按 5–10080 钳位。
- 明细按钮文案随所选渠道数变化（「查五渠道明细 / 查 N 渠道明细」），只对雷达中选中的渠道发起真实探针，不写死五渠道。

## 已知限制（未在本版关闭）

- 关注台名册筛选是否绑定图表序列仍需真实浏览器复核（代码已按名册过滤序列并标注图注，本轮尚未完成独立操作验收）。
