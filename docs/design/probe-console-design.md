## 0.10 r348 生产检索工作台（2026-10-21，当前落地）

### 0.10.1 信息架构（生产）

`#searchview` 已从 r340 的三段补丁重写为单一实现（旧 `renderSearch/srxSelect/…`
重复定义清零）：

1. **检索带**：用户/航线/日期/渠道/关键词/排序；主动探针可折叠（移动端默认收起）；
2. **14 日出发价带 + 五源现势**：出发日轴只在 DB 有 `depart_date` 行时出点，缺失保持
   「未采」；采集日轴单独标注，禁止当出发日；五源卡显示实时/日历/补位/未供、原页与 raw 数量；
3. **快筛 + 更多筛选 + 已选条**：直飞/中转、舱位、航司、起降时段、价格带、行李/餐食/
   廉航/共享/跨天/经停、有原页/有 raw/隐藏日历价/仅缺失/字段齐全/仅风险；筛选持久化；
4. **解析列表 / 航班×渠道矩阵**：13 格字段刻度、风险徽标、行内快览、同班聚合、
   加载更多；矩阵行=真实同班、列=5 渠道，缺失格=未供；
5. **原页镜像**：5 渠道 tab、列表/详情/四源；镜像值从**同一条 raw** 投影，缺键显示未供；
   页面明示「结构重绘、非原站截图/iframe」；
6. **探针城市输入**：出发/到达复用配置页城市索引（中文 / 拼音 / 三字码联想、方向键/回车选择、右侧箭头打开完整国内/国际城市面板）；桌面工作台左右同高、各自内滚，右栏不再出现大块空白。
7. **三重对齐详情**：解析 ⇄ 镜像(raw) ⇄ RAW 路径，`一致/未供/未采/不一致` 四态；
   价格/机场/舱位等派生字段标「口径差」；字段点击定位 raw 键；30 天走势、双轴日历、
   同班价梯（5 格）、结论/备注/复核、上一处/下一处（J/K）、证据 JSON、快照；
7. **五平台校准册**：5 渠道 × 列表/详情/日历/对照 + 四源同屏；空态不补样例；
8. **探针会话/页面状态/快照**：真实探针会话本机留存；`probe://srx` 状态串复制/粘贴还原；
   快照最多 12 条；
9. **导出**：CSV（查询日/航线/渠道/航班/解析价/raw 原页价/时刻/舱位/机型/行李/餐食/准点/
   余票/税费/退改/对齐/采集/原始行/证据指纹/落地页/结论/备注，BOM+RFC4180，公式注入防护）
   与证据 JSON（raw + provenance + sign）。

### 0.10.2 数据契约（新增）

- `/api/state` 行新增：`rowKey`（稳定身份，价格/时刻不参与）、`flightKey`（真实同班键，
  日历行空）、`isCal`、`isStale`、补位行真实 `fetchedAt`、`stale` 一位小数（0.1 地板）、
  `roundUpdated`；
- 日历薄行（无航班号/时刻）**永不判达标**，不参与 `hit`、同班价梯与矩阵；
- `/api/srx/calendar?from=&to=&date=&days=`：`departure`（出发日真实落库）与
  `observation`（采集日观测）双轴；
- `/api/srx/health?from=&to=&date=`：各渠道最近 3 条成功 raw extra 的键可得率 + 采集时刻，
  口径明示「不是值正确率」；
- `/api/srx/links?from=&to=&date=`：五渠道真实落地页；本态不供返回空串（国际途牛/同程）；
- 主动探针行带 `rowKey/flightKey/isCal/raw`，`th=0` 时 UI 标「探针未评估」；
  单次最多 3000 行，超限明示 `truncated`。

### 0.10.3 诚实边界（不允许为了让页面好看而补）

- 当前真实监控是 3/5 渠道（途牛明细 + 携程/飞猪日历薄行；去哪儿/同程 0）；
- 14 日出发价带当前只有 1/14 出发日有真实落库点，其余保持「未采」；
- 同班价梯只在航班号+日期+起降时刻+中转/跨天/经停全部真实时成组；
- 原站页面不 iframe、不截图；以「打开原页」+ raw 回放为证据；
- 探针不落库、不推送；结果只在当前页面/本机会话中，刷新即失（会话元数据本机留存）。

### 0.10.5 已知缺口 / 下一轮候选

1. 真实监控仍以单出发日为主；若要价带 14 日全亮，需要按出发日做真实日历采集/落库，
   不能用日因子或 mock 点补；
2. 逐渠道原页 DOM 框选仍不可诚实落地（登录墙/X-Frame-Options）；当前以深链 + raw 为准；
3. 服务端快照/结论台账尚未落库（本机 localStorage）；跨设备交接需新增 API/表；
4. 探针会话只保存元数据，结果不落库（符合「不入库」边界）；
5. 字段健康当前按 raw 键可得率，不是值正确率；若要值正确率需逐 dump re-parse 审计。

## 0.11 r352 关注航班台 / 航班维度历史（已落地，2026-10-21）

> 本机入口：`http://127.0.0.1:8765` → 监控 →「关注航班」。

### 0.11.1 信息架构
- **航线清单**：同宽可选卡；每卡显示航线、日期、当前最低、监控/达标/试看状态。默认第一条航线；切换即刷新走势与名册。
- **KPI**：关注航班 / 监控中 / 目标达标 / 渠道覆盖；试看态明确显示“试看 1、监控中 0”。
- **走势**：全宽 canvas；折线/K线；48h/7/30/90/180 天；目标虚线、最低/最高/最新点、悬停十字线与读数；x 轴首尾标签夹在画布内。
- **聚焦条**：身份、当前最低、目标价、渠道覆盖、采集点/核对行、状态；目标跑道（当前 vs 目标）；渠道逐项价格/未供；操作：检索台定位、编辑口径、暂停、提醒、移除。
- **名册**：航线内航班；搜索/状态/目标/航司/直飞中转/排序为主筛，更多含渠道/时段/舱位/价格；行内展开监控口径与采集信息。

### 0.11.2 数据契约
- `flight_daily`：`(from_city,to_city,depart_date,flight_key,cabin,day,platform)` 唯一；存 `n/lo/hi/open/close/fetched_max`。每次扫描按 raw 展开**全部被采到航班**，不依赖关注；重扫同日先删后建（幂等）。
- `flight_key` 单源 `core/flighthist.py`：复合航班号段排序，日期/起降/中转/跨天/经停全纳入；舱位按中文大类归一；raw 未给舱位不并入指定舱。
- `/api/srx/flight/trend`：任意航班历史；raw 采集点 + `flight_daily` 日桶；raw 清理后仍可回放长窗；不补点。
- 关注趋势同核心；目标提醒 `alert_state` 键含用户/航班/日期/目标，同价不重推、续降≥￥10 补推、回到上方重置。
- 试看对象只存在前端内存，不写关注文件、不触发提醒；banner 明示来源。

### 0.11.3 独立编排
- 已配置航线 / 自定义城市双模式；城市输入支持中文/拼音/三字码联想（鼠标+键盘），下拉不被字段规则裁切。
- 选择航线/日期后展示真实候选航班卡；点选带出航班号/起降/中转/跨天/经停/舱位；目标快捷（当前价/低5%/低10%）；渠道、提醒、备注、启停同屏。
- 编辑只改渠道/目标/提醒/备注/启停；身份字段锁定。点击搜索行「航班历史」可试看并带入编排。

### 0.9.3 价格纪元与幂等（切日 / 探针 / 配置）

- 初始 `BASE/BASEW` 来自 v30 归一后的行；`EPOCH_BASE/EPOCH_WAS` 是当前价格纪元
  的基准（初始等于 BASE/BASEW）。
- 日期价格 = `EPOCH_BASE × dayFactor(day)/dayFactor(BASEDAY)`；基准日因子 1 时
  **原样还原**（修复了旧公式把 ¥852 回切成 ¥846 的非幂等）。
- 探针 `probeJitter()` 不再直接改当前价：按轮次+行键的确定性抖动生成新的
  `EPOCH_BASE/EPOCH_WAS`，再通过 `applyDatePrices()` 派生全链路；
  同一轮重复应用同价，不同轮才是新行情。
- `was` 随纪元/日期缩放；`dv` 是历史涨跌 chip，不按 `price-was` 重算
  （修复 CZ3084 +8 / MU582 -14 在往返后被改写的非幂等）。
- `stateStr` 新增 `cal`（低价日历开关）与 `md`（多排默认）两键；配置双拨后
  状态串完全还原；`applyState(stateStr())` 同态应用后状态串/数据指纹仍一致，
  `PROBE_IDEM.config=true/configApply=true`。
- 探针后立即跑幂等复核不会回退探针价：纪元基准保留，日期往返只缩放、
  不回到初始 BASE。

## 0. 结论：有必要做，且前两期零采集增量

用户提案原话：「左侧是解析后的实时列表，右侧是内嵌的无头浏览器多排，可以
联动看原始网页信息——双重校准对齐」；补充「解析详情页 + 跳转原始链接 +
内嵌解析详情页」。

**判定：有必要。** 三条论据，全部有轮史实证：

1. **校准工作流现状是无工作台的**。50+ 轮校准（docs/INTL_CALIBRATION.md）与
   r338/r339 两波五渠道调研的全部立案路径都是「RDP 上机 → 翻 debug/ dump →
   手写 _scratch 脚本 → 人肉拼『原始报文 ↔ 解析行』对照」。检索·探针台把它
   自服务化：原始面、解析面、健康面三看一。
2. **「临时看数据」缺任意航线面**。深链构造链（`_build_view_url`）单源已在产，
   五渠道一次生成只是没人把它摆成台面——零新码逻辑，纯呈现。
3. **双重校准是解析正确性的终极验收形态**。抽样脚本只能证「抽查的行对」，
   行级联动+字段级对齐表才能证「全部行对、全部字段对」。

**采集预算立场（铁律）**：探针台永不自动跑。P1/P2 两期**零采集增量**；P3
唯一采集面，四闸预算（§3.3）。R53e 的教训（监控过多→IP 限流）与每步互锁。
