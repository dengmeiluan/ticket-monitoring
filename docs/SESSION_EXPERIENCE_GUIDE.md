## 1. 本次会话的目标与期望

### 1.1 总目标

对 `D:\idea_project\ticket-monitoring` 的机票监控台做**持续的整站 UI / 交互整改**。判据不是「符合规范」，而是**人的视觉心智与操作心智**：

- 用户看到的第一眼是否干净、扁平、有秩序；
- 用户点下去时，界面的变化是否符合「我点了这个，应该在这里出现那个」的直觉；

用户不接受「局部补丁」，反复强调「解决项目中所有这样的问题」。因此每一轮都要：
**先找到同类问题的全集 → 用可复算的判据普查 → 修复 → 负控 → 门禁 → 记录**。

### 1.3 验收标准（用户可感知 + 工程可验证）

**折叠类**
1. 展开体紧贴触发器；中间不得夹「点击前就已可见」的常驻元素。
2. 触发器两态坐标不变（横移 / 纵移 ≤ 2px）。
3. 收起必须真正减少高度，不能只藏一部分控件；但「保留回到内容的入口」是设计（如分组标题、卡头）。
4. 收起后必须仍有可见入口能再展开（不能「收起了就再也打不开」）。
5. `aria-expanded` 与文案随状态同步；`aria-controls` 只在目标真的存在时写。
6. 一键全收 / 全展可用；收起到 0 个可见正文块；留标题是设计，不算没收干净。

**视觉类**
7. 无卡中卡、无装饰性描边、无通栏白底横带；分隔只用 1px 发丝色，且相邻兄弟不得各画一条形成 2px 双线。
8. 间距落在 4/6/8/12/16/24 阶；圆角取五档令牌；无孤立大空档（>40px 且中间无元素）。
9. 同一层级左缘对齐；数字对齐不能让首字被裁；状态徽标不得截断。
10. 图表 60fps（p95 ≤ 16.8ms）、无 longtask、无遮挡层、断档如实断开而不是白色块遮住。

**数据诚实**
11. 合成 / 演示数据必须标「演示数据 · 合成」，不得标「正常」。
12. `—` 只表示「没有样本」，不表示 0；「0%」必须有有效分母。
13. 「没拿到 / 没解析出 / 门拒」不得记成 `empty`；限流 ≠ 验证墙。
14. 补位行与真实行必须可区分；溯源必须指向真实 URL / 原始行。

**工程**
15. pytest 0 failed、UI 自检 0 failed / 0 JS error、不新增 skip / xfail。
16. 新增 / 修改的每个缺陷都要有一条门禁；门禁必须有正控与负控。
17. 结论必须带证据（几何值、截图、哈希）；未验证的必须写「未验证」。

## 2. 项目与环境速览

### 2.1 架构事实

- **单文件 SPA**：整个前端在 `webui.py` 的 `PAGE = r"""<!DOCTYPE html>…"""` 里（约 4.6 MB、上万个标签行）。改 CSS / DOM 都在这一个 raw string 内，锚点通常是 `</style></head><body><div class="wrap">` 或具名注释 `/* rNNN：… */`。
- **后端**：Python 标准库 HTTP 服务 + SQLite（`data/prices.db`）+ 采集器（`crawlers/`）。10 个渠道：携程、去哪儿、飞猪、同程、途牛（浏览器 / H5 / HTTP）+ 智行 App、去哪儿 App、携程 App、同程 App、飞猪 App（Android 自动化，可选，默认关闭）。
- **两种运行模式**：
  - `python webui.py --demo --port <p>`：演示数据，合成，可安全用于 UI 探针；**不许把演示当生产结论**。
  - `python webui.py --port 8765`：生产 / 真实采集。写操作会落盘、会触发采集，探针必须用临时副本（`r671`）。
- **主视图**：`search`（检索）、`mon`（监控：health / details / watch / trend / specials / overview）、`cfg`（配置）。
- **版本常量**：`main.py` 的 `__version__`（本次编写时 1.5.307），Release 只允许一个常量名。

### 2.2 工具链

| 工具 | 用途 | 关键事实 |
|---|---|---|
| `pytest` | 单元 / 静态 / 浏览器门禁 | 必须 `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`（本机插件会拖慢 / 干扰） |
| `playwright.sync_api` | 真浏览器几何 / 点击 / 截图 | Chromium 已安装；探针自起 demo 服 |
| `docs/uitest.py` | 670 项 UI 自检 | 结果写 `docs/uitest_result.txt`；分片跑 |
| `tools/test_all.py` | 全量编排（pytest xdist + UI 分片） | 退出码 3 = 跑测期间源码被改写，结论作废 |
| `_scratch/*.py` | 一次性普查 / 取证脚本 | 不进门禁；结论要转成 `tests/test_rNNN_*.py` |

### 2.3 Windows / Git Bash 注意

- 控制台是 GBK：打印中文 / emoji 可能崩；脚本要设 `PYTHONIOENCODING=utf-8`，必要时 `sys.stdout.reconfigure(errors="replace")`。
- 路径用 Git Bash 形式（`/d/idea_project/...`），Python 脚本内用绝对 Windows 路径或 `os.path`。
- 文本写文件会整份翻 EOL：仓库要求单一 LF；追加内容后立刻核对 `\r\n` 计数（只允许一个非零）。改文件优先用 Edit / Write（保持原 EOL），不要用 shell 文本模式重写。
- `grep -c $'\r'` 在 Git Bash 是空转（空模式匹配全行），要用字节级计数。

## 5. 工作方法与证据体系

### 5.1 一轮修复的标准流程（照做即可）

1. **复述用户诉求**：把它翻译成一句可验证的界面事实（例如「触发器底到展开体顶之间不得有常驻元素」）。
2. **现场核验**：`md5sum webui.py`；`git status`；确认 demo 服可用。
3. **先写探针，不先改代码**：用 Playwright 在真实视口量当前值；截图留证。
4. **仪器正控**：先证明探针能看见一个已知缺陷（注入 spacer / 旧写法），再相信它的「0」。
5. **定位根因**：优先用 CDP `getMatchedStylesForNode` 看实际命中链，而不是读源码猜。
6. **改最小面**：只改造成该缺陷的那一层；不顺手重构。
7. **复测同一量**：同一视口、同一判据，给出修复前后数值。
8. **负控**：把代码退回「修复前实际生效的组合」，门禁必须红；不是退回「源码里写的那条」。
9. **写成门禁**：`tests/test_rNNN_<topic>.py`，含正控 / 负控 / 覆盖面自证；锚点钉符号（函数名 / 选择器），不钉行号。
10. **记录**：`docs/EXECUTION_SPEC_LATEST.md` 追加同轮条目；项目记忆更新；最后再 pin 一次哈希。

### 5.2 证据层级（从强到弱）

1. **真浏览器几何 + 截图 + 行为往返**（最强）：`getBoundingClientRect` / `Range` / `elementFromPoint` / 像素扫描 / 点击后状态变化。
2. **CDP 计算样式命中链**：解释「为什么源码这样写、实际那样生效」。
3. **渲染后的 DOM 结构 + 计算样式**：能证明「有没有这个元素 / 是否可见」，不能证明「看起来对不对」。
4. **源码静态断言**：只能防「规则被删」，不能证明「规则生效」。
5. **主观描述**（「看起来更干净」）：只能作为线索，不能作为结论。

### 5.3 正控 / 负控模板

**正控（证明仪器能看见）**

```python
# 在干净页面上注入一个已知缺陷，探针必须报出来
pg.evaluate("""() => {
  const d = document.createElement('div');
  d.id = '__inj_block';
  d.style.cssText = 'height:24px;background:#fdd;border:1px solid #f00';
  document.querySelector('#target_parent').insertBefore(d, document.querySelector('#body'));
}""")
assert probe()["blocker"], "注入的可见块没被抓住，判据失效"
```

**负控（复现修复前实际生效的组合）**

```python
# 例：r810 的负控不能把 white-space 也改回 normal!important
#     那等于真的允许换行，lost 归零，判据自然抓不到。
# 正确做法：保持 nowrap，只退回 overflow:visible / clip。
pg.add_style_tag(content=".srx-src-sub{overflow:visible!important;text-overflow:clip!important}")
assert probe()["lost"] > 0
```

### 5.4 浏览器探针的 6 个必备动作

1. **先 `scrollIntoView({block:'center'})` 再量**：`elementFromPoint` 对视口外返回 null。
2. **点击前后各拍一次快照**：只比较**点击前已可见**的元素，才能区分「常驻夹层」与「展开内容」。
3. **按声明关系找展开体**：`aria-controls` → `details` → `data-foldtarget` → 行展开的 `nextElementSibling`；不要用「新出现的最大块」猜。
4. **重渲后按业务键找回节点**：`data-pk` / `data-foldtarget` / 文本；旧节点 rect 会归零。
5. **坐标只跟同一角色节点比**：行对行、按钮对按钮；拿「行」比「行内按钮」会造出 12px / 上千像素的假位移。
6. **所有数值带视口宽度与哈希**：结论必须能复现。

## 6. 判据陷阱大全（本次会话版）

> 每条都是「看起来对、实际错」的判据。写门禁前先扫一遍，能省一轮假红。

### 6.1 裁剪 / 命中 / 溢出

1. **`mask-image` 会把后代的绘制与命中一起裁到边框盒内。** 伪元素撑高在带遮罩的容器里无效；要量 `elementFromPoint` 与像素，不能只看盒高。
2. **`text-overflow:ellipsis` 只对「承载文字的那一层」生效。** 写在容器上、文字却被 span 包住时，是硬切且无省略号。判据要读真正文字节点的 computed 值。
3. **`Range.getBoundingClientRect()` 返回布局矩形，不受 overflow 裁剪。** 它报「超盒」不代表肉眼被裁；要用 `elementFromPoint` 问「盒外像素属于谁」或截图。
4. **`scrollWidth > clientWidth` 含 `padding-right`。** 不等于文字被裁；判据用 `lost > paddingRight + 1` 或截图。
5. **`elementFromPoint` 对视口外返回 null。** 探针必须先 `scrollIntoView`，否则负控永远探不到。
6. **`offsetParent === null` 会排除 `position:fixed` 元素。** 自己注入的浮层用 `position:absolute` 或先修正可见性判据。
7. **「卡底留白」在卡面无可见边界时不是视觉缺陷。** 先证有底色 / 描边 / 阴影；否则 `card.bottom - lastChild.bottom` 只是 DOM 几何。
8. **`display:contents` 父级没有盒子，`parentRect` 恒 0。** 判「子元素溢出父盒」必须排除它。
9. **横滚容器里的 `scrollWidth > clientWidth` 是设计，不是溢出。** 排除 `overflow-x:auto` 的父级。
10. **负 margin 在 `overflow:hidden` 里会裁字。** 对齐类改动必须截图看首字，不能只看数字对齐。

### 6.2 折叠 / 坐标 / 布局

11. **「展开体」不能用「点击后新出现的最大块」猜。** 有 `aria-controls` 只认它；行展开认 `nextElementSibling`；否则会把结果网格 / 一万像素外的元素当成展开体。
12. **重渲会换掉节点；旧节点 `getBoundingClientRect()` 归零。** 会读出「行上移 525px」这类假位移。按 `data-pk` / 文本 / 选择器重新找回。
13. **坐标只跟同一角色节点比。** 行 vs 行内按钮 = 12px 纵向、上千像素横向的假位移。
14. **只有「点击前已可见」的元素才算常驻夹层。** 展开后才出现的摘要 / 说明 / 详情属于展开内容。
15. **收起后整卡 `display:none` 时，卡内触发器不可见，必须找到外部入口再测。** 点隐藏按钮会造出「展开体在触发器上方」的假红。
16. **单行 / 横向布局没有「展开体在下方」的几何。** 判据要先分类：纵向展开看底→顶，横向展开看右→左的阅读序。
17. **同值 `min-width:N` 与 `max-width:N` 在精确 N 处同时命中，后写者静默胜出。** 断点必须互斥（如 `max-width:900` + `min-width:901`）；扫描档位要包含断点本身。
18. **`!important` 会让某个断点想改行为的规则变成死规则。** 用 CDP 看实际命中链，别只看源码顺序。
19. **`flex-basis` 决定换行，差一点就折行要改 basis 到地板值，别加断点。**
20. **固定 `max-height` 治不了浮层越界**：没超上限就不会滚；要按「触发器到视口底」算。
21. **折叠触发器候选要按行为筛**（`[data-sec]` / `[data-foldtarget]` / `.srx-foldbtn` / `.srx-mbtn` / `[aria-expanded][role=button]`），不能把 `role=status` 的 live 徽标也算进去（r802 的 `#cfgDirty` 假缺陷）。
22. **「同线」不等于「没有空档」。** 沉底只是把空白搬家；两条判据要同时满足（r804 教训）。
23. **收起后留标题是设计，不是没收干净。** 判「收齐」要数可见正文块，不能只用面板高度 0。
24. **量间距必须限定同一 `parentElement` / `offsetParent` 的兄弟**；跨层级会把 98/669px 量成「空隙」。

### 6.3 普查 / 门禁 / 测试

25. **空容器上的普查恒真。** 普查必须自证「本次扫了 N 个样本，N 不得为 0」；明细表要先等 `行数 > 5`。
26. **`silent` 切页 / 过早扫描会留下骨架。** 明细表 8s 才出 240 行；必须等真实行。
27. **门禁锚点钉符号（函数名 / 选择器 / `^def test_`），不钉行号。** 行号一天漂三次。
28. **负控要复现「修复前实际生效的组合」**，不是源码里写的那条（r810）。
29. **负控要打中守卫真正读的对象**；只撤一条不生效的声明会白跑。
30. **门禁要证明「被测那一层」真的生效**：改动落盘 ≠ 在渲染层生效；跨行代码别用单行锚点。
31. **替身缺字段会让产品恒走错误分支**（r794b）。

### 6.4 并行 / 环境 / 工具
