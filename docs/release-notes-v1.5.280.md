# v1.5.280 — 携程国际航班明细打通（去哪儿 H5 路径同源收口）

## 这轮解决什么

此前携程国际只稳定拿到「日历最低价」：有价格，但没有航班号、时刻、舱位、余票、
行李和共享承运信息，无法进入同班比价、航班监控与 30 天走势；用户点开携程国际
深链也只能看到日历壳。表面像「携程没数据」，实际是国际航班维度没有落地。

本轮把携程 PC 国际列表接成国际主通道：

- **真实航班列表**：`flights.ctrip.com/online/list/oneway-{from}-{to}?depdate=…`
  在受信会话下发出 `international/search/api/search/batchSearch` 与 `pull`
  两个报文。首包可能只带 `finished:false` 空壳，真实行程由 pull 补量；采集端
  等到「有行且流结束」再解析，避免把空壳当空结果。
- **实测证据（2026-10-22，SHA→TYO 2026-11-16）**：174 条行程（直飞 48 / 中转
  126），最低含税 ￥972，与携程页面头条 `11-16 ¥972低` 一致；单次采集 11–14s。
  携程国内同为真实列表（SHA→CAN 2026-10-23：184 条，最低 ￥320），国内路径不变。
- **解析口径**：含税总价 = `adultPrice + adultTax`；显式 `ticketCount<=0` 才剔除，
  缺省余票照收（实测 363/489 条政策缺省，页面照常展示，不等同 H5 的
  `quantity=null` 无票）；价格取目标日起飞、价带内最低可售政策；舱位按
  `priceUnitList.cabinClass` 判定（`S`=超级经济舱，`Y-@S` 混合舱不误标）；
  余票、行李文本、共享承运航班号随最低价政策配对；时区戳交给既有
  `flightnorm` 修正国际真时长。
- **日历降级为兜底**：仅当 PC 列表某日无行时，才使用原有 15380 日历通道补日，
  并继续按「日历价」语义标注；不再让日历价顶替真实航班进入同班价梯。
- **登录态语义**：`needUserLogin`/页面登录提示会置 `login_suspect`，health 与
  配置登录入口可直达修复；PC 列表成功后清除该标记，不把「登录过期」误报成
  「渠道无数据」。
- **原页深链同源**：携程国际「查看详情/原页」改为 PC 列表页，和采集路径同一
  入口；去哪儿用户深链补齐 H5 主路径注释与城市名参数，避免链接指向停服 PC 页。

## 数据与边界

- 携程国际目前按「经济/超经」查询口径采集；更高舱位若渠道未在列表返回，不伪造。
- 列表价与日历价可能短暂不同（余票/政策变化）；页面以本轮真实列表为准，
  日历行仍标「日历」，不参与达标与同班比价。
- 未登录时若 PC 列表返回空壳，会回退日历并标记需登录；两者都无价时如实显示未供。
