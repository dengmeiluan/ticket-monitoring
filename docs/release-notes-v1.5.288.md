# ticket-monitoring v1.5.288 · 2026-10-23

本轮把「检索页看到的结果」与「探针真实采集链路」对齐：探针可展开观察逐渠道阶段、增量结果与阻塞原因；检索页首次进入保持中性筛选，任务快照、结果筛选和待提交草稿互不改写；渠道产物与会话状态分栏陈述，日历价不再冒充明细。

## 探针可观察性

- 任务面板显示子任务进度、阶段计数（排队/请求解析/成功/无结果/仅日历/失败/取消）、更新时间与原始响应组数；保留逐渠道入口账本（PC/H5/API/日历）及耗时。
- 事件流支持按渠道、阶段筛选，支持跟随最新/暂停跟随；收起探针后任务继续执行，重开可继续观察。
- 结果按渠道增量进入任务行；取消时已解析行保留；终态任务提供失败项重试与重连入口，失败项重试不受 60s 新查询冷却拦截。
- 同渠道跨腿并发统一限流（全局 2、同平台串行），避免同一持久化会话被并行打开后互相踢下线。

## 检索页状态与计数

- 首次进入为中性筛选：保留航线范围行，不因历史日期/渠道/额外筛选被清空；恢复条件明确提示，生效条件始终可见。
- 探针待提交草稿、已提交任务快照、结果筛选三者分离：改草稿不改列表；清除结果筛选不改任务日期与请求渠道；单腿探针日期按快照锁定，不能被结果筛选删除。
- 数量口径分栏：跨日期总量、所选日期、渠道筛选后、额外筛选隐藏、实际展示分别计数；未采、无票、失败、筛选为空分别说明，不自动换到有数据日期。
- 有行但全部为日历/补位时，明确显示「仅有日历/补位参考，无真实明细」，不再落成空白提示；提供发起探针补明细入口。
- 日期带在 14 天均未采时默认收起为单行提示，可点「展开日期带」查看；平板端固定 56px 日格，保留可发现的横滑暗示。
